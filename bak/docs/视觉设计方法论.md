# 视觉设计方法论

> 状态：草案 · 2026-10-22
> 范围：只讲视觉，包括气质、层级、颜色、字体、空间、形状、分层、图标、状态视觉、构图和验证。流程、交互规则和文案不在这里。
> 来源：前端设计准则（artifact-design skill）和本项目已定稿的视觉规范「Dining POS」（`pos-ds/project/README.md`、`tokens.json`）。每条方法后面附一句「POS：」，写的是它在收银平板上的落地。

## 一、视觉设计要解决的五件事

做任何一个视觉决定前，先问它在解决下面哪一件。哪一件都不解决的，就是装饰，删掉。

| # | 问题 | 用户感受到的 | 主要手段 |
|---|---|---|---|
| 1 | **层级**：先看什么、后看什么 | 一眼找到重点 | 尺寸、字重、明度、位置 |
| 2 | **分组**：哪些东西是一起的 | 不用读就知道结构 | 间距、面色、对齐 |
| 3 | **焦点**：现在该点哪里 | 不犹豫 | 唯一的实心强调色 |
| 4 | **状态**：这个东西现在怎样 | 扫一眼就知道异常 | 语义色 + 形状 + 文字 |
| 5 | **气质**：这是什么样的产品 | 可信、专业、合身 | 字体、色相、圆角、密度 |

前四件是功能，第五件是性格。性格要服务功能：B 端工具的气质应该来自做好前四件事时的克制和精确，不来自装饰。

## 二、方法流程：从气质到像素

### 步骤 1　定气质：三个关键词，三个反关键词

用词约束方向，比用参考图更稳。反关键词同样重要，它排除掉最容易滑向的默认。

- **POS：** 关键词是**利落、可信、耐看**（收银员一天看 8 小时）。反关键词是**花哨、廉价、冷冰冰**。

### 步骤 2　从主题的世界里取材

区别感从主题本身来，不从流行风格来。列出这个行业的材料、器具和惯例，至少有一处细节只有这个主题才有，而且它是内容，不是贴上去的装饰。

- **POS：** 桌号、单号、小票的等宽数字、`¥203.50` 的两位小数、「并入 A08」这样的状态写法、厨房单的分隔虚线。应收上方那条虚线就来自小票。

### 步骤 3　拆参照：只拆结构，不抄皮

找 3–5 个同类优秀产品，每个按同一张表拆：分层方式、主操作样式、选中样式、圆角、字体、字重、密度。拆完再决定吸收哪几格，不整体照搬。

- **POS：** Square、Clover、Toast 和 ai-shop B 端拆成同一张对比表，最后得到四套方案（色块 / 黑白灰 / Tailwind 细线 / 主流 POS 色块），定稿为方案 1。

### 步骤 4　选一种分层原理

界面分层只有三种做法：**线**（描边、分隔线）、**面**（底色差）、**影**（阴影、模糊）。选一种做主，最多一种做辅。混着用，层级就乱了。

| 做法 | 气质 | 适合 | 风险 |
|---|---|---|---|
| 面 | 柔和、现代、触控友好 | 平板、移动、高频操作 | 面色差太小会糊成一片 |
| 线 | 精确、理性、信息密 | 桌面后台、表格 | 线多显得碎 |
| 影 | 有物体感、层叠清楚 | 浮层、拖拽 | 影一多就脏、显老 |

- **POS：** 只用面。`sh-bg` 画布 → `sh-surface` 面板 → `sh-faint` 中性块 → `sh-primary-tint` 强调块。线只出现在应收上方的虚线和键盘按下态，阴影不用。

### 步骤 5　建基础系统（token）

先定原子，再做组件。所有值进 token，每个 token 写**用途**，颜色 token 还要写**在哪个底上的对比度**。下面第三节逐项讲方法。

### 步骤 6　写组件的视觉配方

每个组件用同一个模板描述：**面 / 字 / 圆角 / 尺寸 / 各状态的变化**。组件只引用 token，不出现字面值。

- **POS 示例（主按钮）：** 面 `sh-primary`，字 `sh-on-primary` 600，圆角 `radius-full`，高 `pos-ctl` 44（关键操作 52），按下下沉 1px。

### 步骤 7　页面构图

用组件拼页面时，过一遍第四节的构图规则：对齐、留白、唯一焦点、重复一致。

### 步骤 8　验证

用第五节的测试方法检查，再回到对应的 token 或配方去改，不在页面上单点修补。

## 三、基础要素的方法

### 1. 层级

- **层级控制在 3–4 级**：主（标题、金额）、正文、次要、弱化。级数再多，用户就分不出来了。
- **一次只用一到两个手段拉开层级。** 字号大了就别再同时加粗加色。最省力的顺序是先用明度（墨 / 次墨），再用字重，最后才用字号。
- **最重要的东西不一定最大**，但一定最「实」，也就是对比最强、唯一的实心。
- **POS：** 墨 `sh-ink` 和次墨 `sh-sub` 两级明度；700 只给金额，所以金额天然最重；结账是全屏唯一的实心按钮。

### 2. 颜色

**按角色分配，不按色相分配。** 先列出颜色要承担的角色，再给每个角色取值：

| 角色 | 作用 | 用量 | POS token |
|---|---|---|---|
| 画布 | 最底层 | 大 | `sh-bg` |
| 面 | 内容容器 | 大 | `sh-surface`、`sh-elev` |
| 中性块 | 次级控件、分组底 | 中 | `sh-faint` |
| 墨 / 次墨 | 文字 | 中 | `sh-ink`、`sh-sub` |
| 强调 | 可点、选中 | **小（一屏 < 10%）** | `sh-primary` 及 tint / text / on |
| 语义 | 成功、警告、危险、信息 | 小，只在有状态时出现 | `sh-success` 等 |

方法要点：

- **中性灰带一点色相。** 纯中灰显得没考虑过。让灰朝主色或暖 / 冷方向偏一点，整屏会更统一。
- **强调色只给「可点」和「状态」**，不做装饰、不做大面积背景。
- **一个主色拆四个值**：实心、tint 底、tint 上的文字、实心上的文字。换皮肤只换这四个。POS 就是 `sh-primary` / `-tint` / `-text` / `on-primary`。
- **tint 用主色加透明度生成**（POS 浅色 12%，深色 20%），这样叠在任何面上都自然。
- **语义色拆「点 / 底 / 字」三件**：原色做点，透明 tint 做底，加深色做字。原色（尤其黄、橙、绿）作文字对比度几乎都不够。
- **语义色与主色拉开色相**：主色不能是红色系，否则和危险色撞。POS 因此不用红色皮肤做默认。
- **对比度是硬指标**：正文和标签文字 ≥ 4.5:1，大字和粗体按钮 ≥ 3:1。写进 token 说明，并注明在哪个底上测的。次墨落到下限就不能再降。
- **状态永远不只靠颜色**：再配一个形状（圆点）和一个词。

**深色模式单独设计，不是反相：**

- 深色下越「高」的层越亮（`sh-elev` 比 `sh-surface` 亮一档），浅色下靠面色差。
- 主色在深色下提亮、降饱和（POS 松绿 #216857 → #5cc0a0），实心上的文字反过来用深色。
- tint 透明度在深色下加大，否则看不出来。
- 画布可以是纯黑，但面板要比它亮，层级才在。
- token 结构固定：裸 `:root` 定义全部浅色值，`prefers-color-scheme: dark` 配合 `:not([data-theme="light"])` 和 `[data-theme="dark"]` 两处重定义深色值，`body` 必须有明确背景。

### 3. 字体

- **选字看用途，不看流行**：界面字体首要是小字号清楚、数字好认、中西文混排协调。中文和西文的 x 高度、字重要匹配。
- **POS：** Inter + Noto Sans SC，回退苹方、鸿蒙黑体。Inter 的等宽数字适合金额。
- **字号用固定档位**，档间比约 1.1–1.25，小字号档密、大字号档疏。
  - **POS 八档：** 12 / 13 / 14 / 15 / 17 / 20 / 24 / 30，最小 12。
- **字重最多三种，每种绑定一个用途**，不临时加粗。
  - **POS：** 700 只给价格和金额，600 给标题、菜名和按钮，其余 400，标签不加粗。
- **行高随字号反向变化**：正文约 1.5，标题约 1.2–1.3，单行控件里的字由控件高度决定。
- **数字是一等公民**：会上下对齐或会跳动的数字（金额、数量、计时）一律等宽数字（`tabular-nums` / `sh-num`）。
- 段落行宽约 65 字符；标题用 `text-wrap: balance`；英文大写标签加一点字距。

### 4. 空间

- **基础单位定一个，档位不超过 5–6 档**。档位要能明显区分，相邻两档差太小等于没分。
  - **POS：** 4 / 8 / 14 / 20 / 32。
- **内近外远（接近原则）**：组内间距明显小于组间间距，比例约 1 : 2 起。分组首先靠间距，其次才靠面色，最后才靠线。
- **兄弟元素用 `gap`**，不用逐个 margin，避免重叠或翻倍。
- **栅格跟着内容走**：宫格用 `auto-fill` + 最小宽度，列数让内容填满，不留孤零零的一个。
  - **POS：** `minmax(136px, 1fr)`，三栏统一间距 8。
- **密度做成档位**：紧凑 / 标准两档整体切换间距、控件高和卡片高，不局部压缩。紧凑档也不能低于触控下限 44。
- **POS：** 紧凑（控件 44、卡 88、间距 8）是默认，标准（48、108、12）可选。

### 5. 形状

- **圆角表达角色，按尺寸分档**：越大的容器圆角越大，越可点的东西越圆。
  - **POS：** 8 小件；12 选项、桌台卡、按键；16 面板、菜品卡、弹层；胶囊给按钮、标签、筛选、步进器。
- **嵌套圆角**：外层圆角 ≈ 内层圆角 + 两者间距，否则内外弧线不平行，看着别扭。
- **胶囊形 = 可点**。形状要有一致的含义，用户靠形状就能判断能不能点。
- **不要所有块一个圆角一个阴影**。边框、底色、圆角、阴影都在宣告「这是独立对象」，只给真正独立的元素。

### 6. 图标

- **一套图标库，一种风格**：线性或面性二选一，不混用。
- **线宽和字重匹配，尺寸和字号匹配**：图标比旁边文字的字号大 2–4px，视觉上才等重。
  - **POS：** Lucide，线宽 1.75，18px；行内 15px。
- **颜色跟随文字**，不单独上色；只有状态图标用语义色。
- **光学对齐**：播放、箭头这类不对称图标要微调位置，不要只做几何居中。
- 不用 emoji 当图标或分节标记。

### 7. 状态的视觉公式

每种状态只改一两个属性，并且全系统统一：

| 状态 | 改什么 | POS 做法 |
|---|---|---|
| 默认 | — | 按组件配方 |
| 按下 | 位置或明度 | 下沉 1px |
| 选中 | 面 + 字色 | `sh-primary-tint` 底 + `sh-primary-text` 字 |
| 焦点 | 外环 | `sh-ink` 焦点环，键盘焦点必须可见 |
| 不可用 | 优先隐藏；不能隐藏就降对比并写原因 | 「离线不可用」 |
| 危险 | 入口描边 + 墨字，最后一步实心红 | `sh-btn--danger` → `--danger-solid` |
| 异常提示 | 语义点 + 文字 | 打印入口变警告色 |

### 8. 动效（作为视觉的一部分）

- 动效表达「从哪来、到哪去」，不做装饰。时长按移动距离定：小反馈约 100ms，弹窗约 180ms，侧滑约 220ms。
- 一个精心设计的时刻，胜过处处都有动效。
- 尊重 `prefers-reduced-motion`。

## 四、构图

- **一屏一个焦点**：只有一个实心主操作，其他降为 soft / muted。
- **对齐到少数几条线**：同类元素共享左边线和基线；重复的卡片内边距、元素位置完全一致。
- **视觉重量平衡**：重的元素（实心按钮、金额、大面积色块）不要堆在一侧；高频重操作放在拇指区。
  - **POS：** 结账放在右下。
- **留白是分组工具**，不是剩下的空。宁可删元素，不要压缩留白。
- **结构手段必须表达真实信息**：编号只给真有先后顺序的内容；分隔线只在分组真的需要时出现。
- **内容决定高度**：容器不被拉伸来填空，文字不被截断（截断是 bug，要么换行，要么在自己的容器里滚动）。

## 五、验证方法

视觉稿完成后逐项测，发现问题回到 token 或组件配方去改。

| 测试 | 做法 | 检查什么 |
|---|---|---|
| 眯眼 / 模糊 | 模糊到看不清字 | 层级和焦点还在不在；最突出的是不是主操作 |
| 灰度 | 去掉颜色 | 只靠明度能不能分出层级和状态 |
| 5 秒 | 给人看 5 秒后问 | 记住的是不是该记住的 |
| 对比度 | 逐个文字 token 在各个底上测 | 正文 ≥ 4.5:1，粗大字 ≥ 3:1 |
| 双主题 | 浅色、深色、跟随系统各看一遍 | 有没有某个颜色只在一个主题下成立 |
| 换皮肤 | 切换全部主色 | 只换四个值能不能全部成立，有没有和语义色撞色 |
| 密度 | 切换紧凑 / 标准，改应用宽度 | 断点处有没有挤压、溢出、孤行 |
| 极端数据 | 超长菜名、六位数金额、0 条、200 条 | 截断、换行、空状态是否得体 |
| 构建检查 | 看实际渲染 | 元素重叠、样式互相抵消、字体静默回退 |

## 六、避开模板感

没有明确视觉方向时，下面这些是最容易滑进去的默认，主动绕开：

- 米色底 + 衬线大标题 + 赤陶色强调；近黑底 + 一个荧光绿或朱红点缀；白底 + 紫蓝渐变大 hero。
- 什么都居中；所有块同一个大圆角加阴影；卡片左边加一条强调色竖条。
- 没想过就用 Inter 或 Space Grotesk；用 emoji 做分节标记；内容没有先后顺序也加 `01 / 02 / 03`。

POS 用了 Inter，但这是因为它的等宽数字适合金额，而且与 ai-shop 对齐。理由要写下来，这才算选择，不算默认。

**做多重按场景定**：工具、后台、文档走实用路线，把层级、间距、配色做扎实，不加夸张的 hero；品牌页、营销页才走编辑化路线，把大胆集中在一处，其余保持安静。拿不准时，排得扎实的页面永远可以接受，过度设计则不一定。

## 七、视觉规范的交付物

一份可落地的视觉规范至少包含下面这些。POS 已具备的打勾：

- [x] 气质与设计语言（几条可执行的原则，例如「一屏一个实心主操作」）
- [x] 颜色 token：每个都有浅 / 深两个值、用途和对比度
- [x] 皮肤规则：换哪几个值、不换哪些
- [x] 字体、字号档、字重用途、数字规则
- [x] 间距档、圆角档、控件尺寸档、密度档
- [x] 图标库、线宽、尺寸
- [x] 组件视觉配方与状态（`components/`）
- [x] 布局与断点图
- [x] 可切换方案的视觉原型（`prototypes/pos-workbench.html`）
- [ ] 第五节验证结果的记录（灰度、双主题、换皮肤、极端数据的截图）
- [ ] 每个关键视觉选择的理由（为什么用面不用线、为什么选松绿）
