# Dining POS 原型评审与优化意见

> 日期：2026-10-22
> 评审对象：`prototypes/dining-pos.html`（index 标为「最新」，黑白灰 + 主题色，A 圆润 / B 犀利），同时对照 `prototypes/pos-workbench.html`（6 布局 × 4 方案）。`dining-pos-v3.html` 与 `dining-pos.html` 逐字节相同，按同一份处理。
> 依据：`pos-ds/project/README.md`、`tokens.json`、《POS 点餐页 · 功能区与方案》、《视觉设计方法论》、《POS 颜色规范》。
> 方法：读 CSS 和渲染逻辑；在 1440×900 和 1024×768 下渲染，看浅色、深色、结账面板和桌台面板；对原型里实际写的色值逐一计算 WCAG 对比度。

## 结论

1. **新原型的方向是对的，但它已经偏离了定稿规范，规范却还没跟上。** 它用了带色调的中性灰，墨色表示位置，主题色表示订单和钱，红色只表示失败，还去掉了线条。这些规则比 README 更清楚、更克制。但它同时取消了警告和信息色，换了皮肤集合、圆角和危险按钮样式，这些都和 `tokens.json` 冲突。需要先拍板哪边为准，再回写规范（第一节）。
2. **一屏出现了两个实心主操作。** 「送厨」墨色实心和「结账」主题色实心并排，两者对比度只有 2.5:1，墨色还更重，收银员的视线会先落在送厨上。这是最该先改的视觉问题。
3. **两版原型都有同一批硬伤**：沽清和编号文字只有 2.1:1，危险标签 4.2:1，徽标字号 11.5px，多处触控区只有 30–40px，中性层级之间的对比只有 1.10:1，暖光下会看不出来（第二节）。
4. **两版原型都没有用 `tokens.json` 的取值。** 原型、规范、代码三处已经开始各说各话，建议改成由 tokens.json 生成原型的 CSS 变量。

## 一、需要拍板的方向分歧

每条都给出现状、规范写法和建议。建议采纳的，同步改 README 和 tokens.json；建议回退的，改原型。

### 1. 状态色：新原型把成功、警告、信息都改成了灰色

- **现状**：`.bd.ok / .warn / .info` 都是 `s2` 底加 `fg2` 字。「已下单」是灰色，「催菜中」是墨色实心标签，打印、网络异常统一用红点。
- **规范**：成功、警告、危险、信息四色，状态一律「圆点 + 文字」。
- **问题**：
  - 催菜、缺纸、离线、待结账、限量都是高峰期要一眼看到的异常，变灰之后只能逐字读。
  - 墨色同时表示「当前位置 / 选择」和「需要注意」，同一个颜色承担了两种含义。
  - 缺纸这类警告显示成红点，和真正的失败（打印失败、支付失败）混在一起。
- **建议（折中）**：
  - 成功态降为灰色可以采纳，常态不需要颜色。
  - 信息色并入主题色（就餐中 = 主题色 tint，这一点新原型已经这么做了），外带、外卖标签用灰色。
  - **警告必须保留橙色**：点用 `sh-warning`，字用 `pos-warning-text`，底用 `sh-warning-tint`。打印缺纸、离线的入口点改橙色，红色只留给失败。
  - 最后剩三种语义：危险、警告和主题。tokens.json 删掉 info、success 的标签用法。

### 2. 墨色实心用得太多，「送厨」和「结账」抢焦点

- **现状**：选中的分类、选中的筛选、送厨按钮、催菜标签、待结账桌、选择条、会员卡、B 版系统栏，全部是墨色实心块。一屏墨色实心块 6 处以上。
- **规范**：一屏一个实心主操作；送厨是 soft，挂单是 muted。
- **建议**：
  - **送厨改回 `soft`（主题色 tint）或 `mut`**。结账保持唯一的实心主题色。
  - 选中的分类、筛选、规格可以继续用墨色，这是「位置」的含义，面积小。
  - 催菜标签改为第 1 条的警告样式。
  - 待结账桌改为警告 tint 加「待结账」文字，不用墨色整块。
  - B 版系统栏如果保留整块墨色，选中的分类就改用 `s3` 底加墨色字，避免画面上下两条黑色大块夹住内容。

### 3. 换皮肤时连中性灰一起换

- **现状**：每套配色手调约 16 个值，包括 bg、surface、s2、s3、fg 和 fgd。
- **规范**：tokens.json 写的是「换皮肤只换四个值，不换中性面」。
- **建议**：**采纳**。中性灰朝主题色偏一点是方法论推荐的做法，效果也确实更统一。但要改成规则生成，不手调：中性面 = 基础中性灰与主题色按固定比例混合（例如 bg 4%、s2 3%、s3 6%、文字 8%）。这样新增皮肤只需要给出四个主色值，再改 tokens.json 的皮肤说明。

### 4. 皮肤集合三处不一致

| 来源 | 皮肤 |
|---|---|
| tokens.json | 松绿、靛蓝、暖橙、绛红、石墨、茶青、黛蓝 |
| pos-workbench.html | 上面 7 套 + 辣椒橙 |
| dining-pos.html | 松绿、墨黑、靛蓝、陶土、酒红、青碧 |

问题：

- **墨黑**的主题色等于墨色，「墨 = 位置、主题色 = 订单和钱」这条规则会失效，送厨和结账都变成黑色。如果保留，墨黑皮肤下结账要换一个能区分的样式，或者干脆不提供墨黑。
- **陶土** #AD4F27 色相 18°，危险色 #D92D20 是 4°，只差 14°，比焦糖（差 23°）更容易和危险色混淆。
- **青碧** #0E6B77（187°）和黛蓝 #1F5F7A（198°）几乎重复，保留一个即可。
- 新原型把危险色从 #F04438 换成了 #D92D20，tokens.json 没有同步。

建议的最终集合是 7 套：松绿（默认）、靛蓝、焦糖、绛红、石墨、茶青、黛蓝或青碧二选一。陶土、辣椒橙只作品牌色，不进收银皮肤。墨黑如果要保留，作为第 8 套「无彩色」，并写明它的结账样式例外。

### 5. 去掉数字：大部分合理，有三处要放回来

- **合理**：系统栏的桌数和单数、分类计数改成小圆点、分组计数，去掉后画面明显更静。
- **建议放回**：
  - **菜品编号**：P0 功能里有「按编号搜索」，编号不可见，收银员就不知道能用编号搜。现在编号用 `fgd`，只有 2.1:1，等于看不见。建议在列表视图里显示编号，用 `fg3`（5.1:1）；卡片视图可以不显示。
  - **单号**：打印面板里仍然写「#1024 厨房单」，结单区却没有单号，收银员没法把厨房单、外卖单和当前订单对上。建议放回桌台订单条的副标题。
  - **送厨按钮上的数量**：「送厨 · 2」能防止误送，按一次就把几道菜送进厨房，数量是确认信息，不是装饰。

### 6. 危险按钮从描边改成 tint 填充

- 和「去掉线条」一致，可以采纳，但要改 README 的写法（「危险操作描边加墨字」）。
- 现在 `#D92D20` 在 `#FDECEB` 上只有 4.2:1，不达标。文字改用 `pos-danger-text` #B42318（5.75:1）。

### 7. 已预订桌用描边

- 全原型只剩这一处描边，和「全部用色块分层」的规则矛盾。
- 建议改为 `surface` 白底（与空闲桌的 `s2` 区分），加「已预订 19:00」标签。

### 8. 圆角

- A 版用 22 / 18 / 14 / 12，B 版用 8 / 6，都不在规范的 8 / 12 / 16 五档里（规范还写明 22 在首版不用）。
- 建议先定 A 还是 B，再把选定的值写回 `radius-*`。如果选 A，建议收敛到面板 16、菜品卡 12、控件 12、按钮胶囊，与现有组件对齐，迁入 b-app 的成本最低。

## 三、做得好、应该保留的

- **一个主题色的规则**写得很清楚：主题色只表示订单里的东西和钱。这比 README 的「可点与状态」更容易执行，建议写进规范。
- **红色只留给失败和危险操作**，金额没有标红，支付品牌色没有进入界面色板。
- **去掉线条后层级反而更清楚**：订单行改用圆角色块悬停，金额区是一整块 `s2`。
- **分类计数改成小圆点**，左栏安静了很多。
- **Noto Sans SC 补加载了 600**。在 pos-workbench 里中文 600 没有加载，会被渲染成 700，菜名和价格一样粗，层级被压平了。新原型修好了，workbench 也应该补上。
- **状态都带文字**：已下单、催菜中、已沽清都有字，颜色不承担唯一信息。

## 四、建议的修改顺序

| 优先级 | 内容 |
|---|---|
| P0 | 送厨改为 soft（第一节第 2 条）；警告色恢复（第一节第 1 条）；沽清和编号文字对比度、危险文字色、11.5px 字号（第二节第 1、2、4 条） |
| P1 | 触控热区；中性层级对比；空单隐藏操作区、确认收款写差额；已点卡价格改回墨色；放回单号和送厨数量 |
| P1 | 拍板皮肤集合、圆角方案、换皮肤是否连中性灰一起换，然后回写 tokens.json 和 README |
| P2 | 字号、字重收敛到档位；原型改由 tokens.json 生成变量；断点调整；清理重复的 `dining-pos-v3.html` |

## 五、需要同步更新的文档

- **README**：设计语言里加入「墨色 = 位置，主题色 = 订单和钱」；危险按钮写法；桌台状态；去掉数字的原则。
- **tokens.json**：
  - 改皮肤集合。
  - 皮肤规则改为「四个主色值 + 中性灰按规则偏色」。
  - 危险色取值要定一个：#F04438 还是 #D92D20。
  - 删除 info 的标签用法。
  - 圆角改为最终选定的方案。
- **《POS 颜色规范》**：第二节的桌台状态映射、第三节按钮配色、第四节皮肤表按拍板结果更新。
