## 1. 当前范围与入口

本轮选择 B 方案：在已有 HTML 2.0 风格查看页上优化桌台、点餐，采用原有业务组件及动作分发机制。C 方案独立概念稿、React 工程不属于本次提交。

从仓库根目录启动：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory prototypes
```

若端口已占用，先确认现有服务能提供项目文件，或换端口并同步替换以下地址。

- 桌台：http://127.0.0.1:8765/style-compare/pos-ui-v2.0.html?wb=tables#glass
- 点餐：http://127.0.0.1:8765/style-compare/pos-ui-v2.0.html?wb=order#apple
- v1.5 点餐：http://127.0.0.1:8765/style-compare/pos-ui-v2.0.html?v=1.5&wb=order#m3
- 组件库：http://127.0.0.1:8765/style-compare/pos-components-v2.0.html

`wb=order` 初始化点餐，其他值默认桌台；`v=1.5` 加载 v1.5 基线；`#apple`、`#m3`、`#uber`、`#glass`、`#base` 选择外观。使用 HTTP 打开，iframe 注入依赖同源访问。

## 5. 已知限制与下一步

1. **草稿只存于当前 iframe 会话内存**，刷新或切换基线会重置；原页 localStorage 只沿用显示配置存档，不代表订单持久化。
2. **尚无服务端订单模型**。除初始桌外，其他桌主要为状态示例；选桌会建立空草稿，不能据此判断已用餐桌的历史账单为零。当前选中后金额可能从示例金额切换为草稿金额，后续应区分“未加载账单”和“空订单”。
3. `orderFields` 只隔离部分订单状态。后续扩展支付、平台券、拆单或挂单时，需要核对是否还有全局订单字段跨桌串用。
4. 规格及部分动作继续使用原实现；本轮没有把所有原示例浮层改为完整业务流程。结账、拆单、换桌、拼桌尤其需要单独回归。
5. 开台人数目前取座位数，应补充人数输入；区域来自桌号首字母，区域数量仍按 12 / 6 示例值，后续改用显式数据。
6. `dock` 通过替换原输出 HTML 的类名和固定文案调整按钮与桌台信息。底层模板变更后可能失效，优先重构为显式共用订单头、操作底栏组件。
7. 工作台高度目前使用父窗口高度减固定 240px，外层说明区换行或展开调试区时会额外滚动。后续按实际可用高度计算，并补真实设备旋转测试。
8. 部分 CSS 以 `.pad-v2` 为作用域，会影响 iframe 内其他工作台的共用控件；三栏覆盖已限制桌台、点餐，但其他工作台仍需验证。
9. 新增标题与提示主要为中文，未补齐双语字典；菜品照片依赖 Wikimedia 网络访问，白色玻璃态大量背景模糊的真机性能未测。

下一步优先：账单加载状态及金额一致性 → 明确共用订单组件 → 人数选择 → 完整送厨 / 结账闭环 → 草稿持久化 → 平板触控与布局回归。
