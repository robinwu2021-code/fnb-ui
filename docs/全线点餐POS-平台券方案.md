# 全线点餐 POS · 平台券（团购券）对接方案

> 状态：已做进原型 · 已确认（按文档默认，2026-10-23）
> 原型：`pos-ui.html` 结账页「③ 费用与优惠 › 平台券」、结单区费用行、快捷操作「验券」（可在设置里加到结单区头）、页首「模拟扫码 › 团购券码」；设置「外卖与渠道 › 团购验券」；报表「优惠 › 平台券抵扣」。
> 代码：数据与算价在 `ui/core.js`（`PLATS`、`PVOUCHERS`、`totals()` 的 `pv`）；验券浮层和动作在 `ui/modules/checkout.js`（`OVL.pvoucher`、`pvscan / pvn / pvadd / pvdel`）。

## 一、要解决的事

顾客在美团·点评、抖音、快手、小红书等平台买了团购券（代金券、套餐券），到店消费时出示券码。收银员要在 POS 上**验券、抵扣、核销**，钱由平台结算给门店。

和「本店券」的区别：

| | 本店券 | 平台券 |
|---|---|---|
| 谁出钱 | 门店让利 | 顾客已在平台付款，平台结算给门店 |
| 记账 | 优惠 | **平台券抵扣**（收入的一种来源，不计入优惠合计） |
| 校验 | 本店规则 | 向平台验券：券是否有效、是否已用、是否本店可用 |
| 核销 | 本地记录 | 调平台核销接口；可在时限内撤销 |

## 二、支持的平台

| 平台 | 标识 | 原型里的状态 | 说明 |
|---|---|---|---|
| 美团·点评 | 黄底「美」 | 已授权 | 美团与大众点评共用一套团购券 |
| 抖音（抖音来客） | 黑底「抖」 | 已授权 | |
| 快手 | 橙底「快」 | 未授权 | 验券时提示去设置授权 |
| 小红书 | 红底「红」 | 未开通 | |

平台标识沿用支付方式图标的做法：品牌色小方块 + 一个字（`dn-plat`）。品牌色不随黑白灰色系变，靠它认平台。新增平台只在 `PLATS` 里加一行。

## 三、流程

```
结账页 ③ 费用与优惠 › 平台券（或结单区「验券」、扫码枪直接扫）
  → 侧滑「平台券 · 验券」：平台授权状态一排 · 扫码 / 输券码（自动识别平台）
  → 平台返回券信息：平台 · 券名 · 类型 · 面额 · 售价 · 有效期 · 券码 · 剩余次数
  → 选本次使用张数（同一券码可多次的，如 2 张代金券）→「加入本单」
  → 结账页显示「平台券 · N 张 −¥X」，其余优惠按规则置灰并写原因
  → 收款完成时向平台核销；取消结账不核销
```

券抵扣完全部金额时，收款区显示「平台券已抵扣全部金额」，直接「完成」。

## 四、规则（默认值，可在设置里改）

| 规则 | 默认 | 原型表现 |
|---|---|---|
| 与店内活动同享 | 否 | 活动行置灰：「已用平台券，不与店内优惠同享」 |
| 与本店券同享 | 否 | 优惠券行置灰，同上 |
| 人工折扣、抹零 | 不可 | 整单折扣置灰；抹零写「用平台券后不抹零」 |
| 每单最多 | 3 张 | 超过时提示「一单最多 3 张平台券」，步进器到上限不再加 |
| 代金券找零 | 不找零、不退回 | 面额超过应付时，验券面板出警告条，建议移除一张或加菜；抵扣金额按应付封顶 |
| 套餐券 | 按券里的菜抵扣 | 本单缺券里的菜时置灰：「本单没有券里的菜：…」 |
| 核销时机 | 收款完成后 | 验券只是预占；取消结账不核销 |
| 撤销核销 | 24 小时内 | 在订单详情撤销（原型未画，见第六节） |

## 五、验券结果的几种情况

| 情况 | 表现 |
|---|---|
| 有效 | 券卡片 + 本次使用张数 +「加入本单 · −¥X」 |
| 已加入本单 | 券卡片上标「已加入 N 张」 |
| 券已使用 | 警告条：「券已使用 · 这张券 10-21 19:02 已在本店核销，不能重复使用」 |
| 平台未授权 | 警告条：「平台未授权 · 到设置 › 外卖与渠道 › 团购验券授权后再验」 |
| 套餐券缺菜 | 券卡片置灰，写缺哪道菜 |
| 面额超过应付 | 警告条，写超出金额 |

## 六、决定（2026-10-23，按文档默认）

| # | 问题 | 决定 | 原型 |
|---|---|---|---|
| 1 | 记账口径 | **抵扣项**：放在「③ 费用与优惠」第一行；报表单列「平台券抵扣（平台结算，不计优惠）」 | 已是 |
| 2 | 与店内优惠同享 | **不同享**：活动、本店券、会员价、人工折扣、抹零都不叠加；设置里保留开关 | 已是 |
| 3 | 撤销核销 | **订单详情**里撤销，核销后 24 小时内；授权规则见下 | 已做（见第七节） |
| 4 | 离线 | **不允许离线验券**（券要先向平台确认没被用过）；对接方式（开放平台直连或聚合服务商）由技术方案定 | 离线时「平台券」行置灰写「离线不能验券，联网后再验」，验券面板出警告条 |
| 5 | 外卖单 | **不走本流程**：外卖单的平台优惠由平台算好，平台券只用于到店团购券 | 已是 |

## 七、撤销核销（订单详情）

| 情况 | 能否在 POS 撤销 | 做法 |
|---|---|---|
| 本人核销，24 小时内 | 能 | 「撤销核销」→ 选原因（必选）→ 确认 |
| 别人核销，24 小时内 | 能，需主管授权 | 「撤销核销 · 需授权」→ 选原因 → 主管输授权码 → 确认 |
| 超过 24 小时 | 不能 | 显示「超过 24 小时 · 请到平台商家后台退款」（平台不再受理撤销） |

原建议是「超过 24 小时需授权」；由于平台的撤销窗口就是 24 小时，超过后 POS 调不通，改为不能撤、引导去平台后台。

- 订单详情「支付记录」逐张列出平台券：平台标识 · 券名 · 核销时间 · 操作人 · 张数 · 金额 · 状态（已核销 / 已退回）。
- 原因四选一：验错券、顾客改用其他方式付款、重复核销、其他。记录原因、操作人、授权人。
- 撤销后券退回顾客的平台账户；订单变为**部分支付**，支付记录出「待补收 ¥X」，到结账补收。撤销结果以平台返回为准。
- 结账用了平台券的单，完成后核销记录自动出现在该单的支付记录里。
