## 5. 关键限制与不得误判的状态

1. **两类版本分开：** SQLite数据库当前v2；Vault业务快照schema v3，兼容旧v2。显示偏好仍在DataStore；业务不再主要保存在DataStore。
2. **仍有快照：** SQLite中保留门店级JSON，未完成全量实体化。当前事件不完整，不能从事件重建整个门店。
3. **过渡协议：** `local-page`不是可信设备身份，`page-order-stream`不是订单级聚合，聚合状态仍有占位值；当前页面每次操作生成新ID，尚无完整客户端超时查回执流程。
4. **存储能力缺口：** SnapshotStore默认saveCommand仍仅存快照，应用SQLite有覆盖实现；N2必须明确不支持命令时拒绝，测试内存适配器另行声明。
5. **构造器兼容边界：** 保留嵌套null/默认值，只省略顶层不存在的payment/audit；支付/审计仍选目标桌最后匹配记录，更严格新增证据校验尚未实现。
6. **模拟服务：** SyncEngine补发即模拟成功，PrintEngine只改状态；不能以系统网络能力证明云或厨房可达。新command_events不会由模拟引擎自动确认。
7. **结账限制：** 当前new/queued仍阻止结账。已确认实施顺序不等于已批准云待同步时放行现金、厨房人工交付或离线全局资产核销。
8. **演示权限和资产：** 本机注册/公开体验主管、门店共用演示余额、券活动不等于生产身份或真实资产。生产前必须替换和隔离。
9. **恢复保护：** 坏快照/未知版本停止恢复，尚缺完善的恢复界面；真实断电及磁盘故障不能仅以SQLite回滚测试当作已验收。

在工程目录执行，先配置JDK 17及Android SDK（通过环境变量或本地local.properties，不提交本机路径）：

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
```

SQLite设备测试需可用Android模拟器/设备。先用`adb devices`确认目标；前次使用emulator-5556，编号不是固定环境配置。可在已确认的测试设备安装app-debug和androidTest APK后运行：

```sh
adb -s <测试设备ID> shell am instrument -w \
  -e class ai.neargo.fnb.pos.core.data.PageCommandTest,ai.neargo.fnb.pos.core.data.CommandJournalTest,ai.neargo.fnb.pos.core.data.SqliteSnapshotStoreTest \
  ai.neargo.fnb.pos.test/androidx.test.runner.AndroidJUnitRunner
```

本地调试不要清除现有应用数据作为迁移测试替代；设备测试使用独立测试库。规则保持纯Kotlin、页面沿用共享组件和中英文Text；不得把认证、打印等外部副作用塞入事务reducer。
