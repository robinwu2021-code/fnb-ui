## 2. 代码约定（新开发必须遵守）

- **分层：** 规则写在 `core/model`（纯 Kotlin，可单测）；数据入口是 `core/data/Repositories.kt` 的接口；页面在 `feature/*`，模式为 `Screen(UiState, onAction)`。
- **依赖注入：** 手工注入，入口 `AppContainer`。阶段三把各仓库接口的实现从 `LocalWorkspace` 换成远端实现，页面层不改。
- **组件：** 只用 `core/designsystem/component` 里的组件，扁平风格（零阴影、无灰描边）。新组件同时加进「系统管理 → 设备与系统 → 组件验收」页。
- **文字与翻译：** 一律使用本工程的 `Text`（自动翻译）。新增中文文案必须同步在 `app/src/main/assets/i18n/en.json` 加英文词条，带变量的用 `{0}` 占位。
- **正则：** Android ICU 正则比 JVM 严格，`}` 必须转义，否则单测通过但真机崩溃。
- **金额：** 以分计算，显示用 `yuan()`；当前实现仍多用Int，统一Long与金额上限列为P0任务。

## 4. 阶段三：接入真实服务（需后端）

后端服务与接口规格目前都不存在，需先由后端确定。建议顺序：

| 顺序 | 内容 | 替换点 |
| --- | --- | --- |
| 3.1 | 账号认证、门店授权、会话失效回到登录、员工权限 | `SessionRepository` |
| 3.2 | 目录与桌台下发、版本号与冲突处理 | `StoreConfigRepository`、`FloorRepository` |
| 3.3 | 订单与送厨服务，幂等键沿用本地 `batchId` | `SyncRepository` / `SyncEngine` |
| 3.4 | 报价、优惠核验、支付单、结果查询（状态未知先查单，不重复扣款） | 结账流程 |
| 3.5 | 图片上传、库存服务、真实打印机与钱箱指令 | `LocalMedia`、`PrintRepository` / `PrintEngine` |

注意事项：

- 离线语义保持不变：断网时送厨批次和收款落盘排队，联网后按创建顺序补发。
- 订单有新加或待同步菜品时不能结账。若门店要求断网结账，需产品先定规则。
- 演示菜品图来自 Wikimedia，上线前换门店自有图床，并去掉 `PosApplication` 里的演示 User-Agent。
