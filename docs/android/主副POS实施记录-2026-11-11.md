# N5 主副 POS 实施记录（基础版）

日期：2026-11-11。分支 `android-ui-v3`。对应[实施方案 §6](../architecture/下一阶段实施方案-2026-11-10.md)和[协同方案](../architecture/多POS离线局域网与云端协同方案.md)。

## 结论

一台主 POS 带多台副 POS 的基础链路已经打通，单元测试和模拟器都验证过。

| 主机 | 副机 |
| --- | --- |
| 门店唯一的协调方 | 业务操作以「意图」形式交给主机执行 |
| 负责打印和所有管理类操作 | 本机只保存主机数据的只读副本 |

副机失联时只读，不会绕过主机写本地或云端。

## 角色

`LanState.role` 有三种取值：

| 角色 | 说明 |
| --- | --- |
| 单机 | 不参与局域网 |
| 主 POS | 门店唯一协调方 |
| 副 POS | 业务操作交主机执行 |

角色保存在本机数据里。主 POS 的服务随应用自动启动，默认端口 47600。

| 操作 | 副 POS |
| --- | --- |
| 开台、加菜、改量、备注、送厨、催菜、上菜、会员、优惠、挂单、取单、结账、清台、换桌、并台、拆单、预订、桌位、主管授权 | 转为意图交主机执行（`Routed*`） |
| 门店配置、商品、库存、餐牌、交班、预结单、补打、人工确认送达 | 拒绝，提示「仅主 POS 可执行」 |
| 本地直接写营业数据 | 工作区内拒绝（兜底） |
| 模拟打印、同步引擎 | 不运行 |

## 配对与加密通道（`core/lan/LanChannel.kt`）

**连接方式：** 手动填写主机地址（IP:端口）。主机页面会列出本机的局域网地址。

**配对码**
- 主机生成 8 位数字配对码，5 分钟内有效。
- 每次配对握手计一次尝试，用原子计数，最多 3 次。配对成功后配对码立即作废。
- 副机配对时校验主机签名和配对码证明，然后**固定主机公钥**，以后只认这把公钥。
- 主机登记副机的设备 ID、名称、公钥和指纹。

**握手**
- 双方各生成临时 ECDH P-256 密钥，并用各自的设备私钥签名整段握手记录。
- 主机设备密钥在 Keystore 里，副机也是。
- 已配对设备连接时，主机核对设备公钥指纹，副机核对主机公钥，任何一方不符都拒绝。

**会话**
- 会话密钥由 HKDF-SHA256 从 ECDH 共享密钥和双方随机数派生，两个方向各用一把 AES-256-GCM 密钥。
- 报文 nonce 由方向和递增序号组成，接收方要求序号严格递增，防止重放和乱序注入。
- 会话期限最长 8 小时，且不超过主机自身的离线授权到期时间。

## 主机仲裁与幂等（`RemoteIntent.kt`）

- **意图内容：** 意图只描述要做什么，例如商品 ID 加 SKU 再加数量。价格、库存、权限由主机按当前状态重新校验，不接受副机提交的订单快照。
- **串行执行：** `HostExecutor` 用互斥锁串行处理所有副机意图，主机是单写协调方。
- **去重：** 先按「副机设备 + 命令 ID」查命令日志，已提交就返回「重复请求」，不再执行。
- **同事务：** 执行时通过 `RemoteOrigin` 把副机的设备、命令 ID 和操作人带进主机事务。日志里来源是副机，协调方是主机，所以去重记录和业务修改在同一个事务里提交。

**副机发送（`LanLink`）**
- 意图先保存为待确认，再发送。
- 连接阶段就失败的，说明一定没发出去，撤回待确认记录，按只读处理。
- 已发出但没收到回执的，保留下来，后台以同一命令 ID 重发。
- 待确认列表在副机的「主副 POS」页和提示条里显示。

## 同步

- 副机每 2 秒拉取一次主机门店快照，用令牌（快照的 SHA-256）判断是否变化，没变化时不传正文。
- 快照作为本机只读副本保存，同时保留副机自己当前选中的桌台。

## 设备管理与撤销

- **主机页：** 服务状态、本机地址、配对码、已配对副机列表（在线或离线、指纹、配对和最近活动时间），可以撤销副机或停止主 POS。
- **副机页：** 主机名称和地址、加密连接状态、原因、最近同步、会话有效期、待确认列表，可以立即同步或解除配对。
- **撤销：** 立即断开连接，之后再握手和后续请求都会被拒绝。

## 验证

**单元测试（真实本机套接字）：** `LanClusterTest` 共 5 项，连续跑 3 次都稳定通过。全部 122 项通过。
- **配对码：** 错误 3 次后作废，成功一次后作废。
- **一主两副并发：** 两台副机各发 10 次加菜，主机正好 20 份，两台副机的副本与主机一致。命令来源记为副机，协调方为主机。送厨在主机产生打印任务。
- **幂等：** 同一命令 ID 重发只执行一次，门店不一致时拒绝。
- **失联：** 主机下线后副机只读、不排队，副机本地写入和管理操作被拒绝。主机恢复后按固定公钥重连。
- **身份：** 撤销后被拒绝；数据复制到另一把密钥的设备后，提示「设备密钥与配对记录不符」；伪造主机时，提示「主机身份与配对记录不符」。

**模拟器：** pos_tablet 作主 POS，pos_tab 作副 POS，经宿主机端口转发通信。
- 配对成功，加密连接，会话 8 小时。
- 两台模拟器重启后，副机自动重连。
- 副机为 A06 加菜并送厨，主机事件的来源是副机设备，协调方是主机，操作人是副机账号。副机本地事件数为 0。
- 停掉主机应用后，副机出现红色只读提示条，加菜不生效。主机恢复后，副机自动重连并能继续加菜。
- 主机撤销副机后，副机显示「设备已被主机撤销」并保持只读。
- 两台都没有崩溃。en.json 新增 67 条。

## 仍未覆盖

- **自动发现：** 目前只能手动填地址。
- **配对强度：** 配对码证明不是 PAKE。截获握手的人可以离线暴力尝试 8 位码，所以要靠 5 分钟时效、3 次尝试和一次性使用来降低风险。生产环境建议换成 SPAKE2 或扫码交换公钥。
- **同步粒度：** 按门店整份快照同步，没有按实体增量。大店需要增量同步加游标。
- **失联时的副机：** 默认只读，没有做草稿或缓存模式。
- **主机故障：** 不会自动切换主机，受控切换属于 N9。
- **委托授权：** 主机没有签发带父授权链的局域网委托凭证；主机的离线授权也没有设备数量上限字段。
- **发件箱：** 副机的待确认列表存在本机数据中，没有复用 N2 的 SQLite 命令发件箱（语义相同）。
- **主管授权：** 主管凭据会在加密通道内传给主机验证，不保存也不进事件，但更好的做法是在副机上做挑战签名。
