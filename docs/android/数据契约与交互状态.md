# Android 页面数据契约与交互状态

基线：当前 v3.6 原型。下面区分原型字段与正式模型建议；服务方法名为能力契约示意，不是已经存在的接口或后端协议。

## 1 状态作用域

| 作用域 | 数据 | 生命周期与约束 |
| --- | --- | --- |
| 会话 | 员工、权限、可用门店、当前门店 | 正式由认证服务管理；原型不存储/发送密码，无真实令牌 |
| 终端显示 | 皮肤、组件风格、字体、密度、布局、语言 | 当前 `pos-v3-settings`；Android持久化非敏感偏好并做版本迁移 |
| 门店 | 区域、桌台、目录、库存、餐牌、配置 | 原型以快照在两店间切换；正式数据必须带storeId |
| 订单 | 人数、行项目、送厨状态、优惠选择、收款记录 | 原型按桌号保存会话对象；正式以orderId标识，不能以桌号永久代替 |
| 页面 | 搜索、分类、筛选、选中桌台、列表位置 | 页面切换可恢复，不写入业务实体 |
| 编辑草稿 | 商品表单、SKU输入、图片读取中状态 | 保存成功才更新正式数据；失败/重建应保留可恢复草稿 |
| 临时效果 | Toast、导航、图片选择器、确认弹层 | 一次性消费，避免重复执行 |

原型桌台坐标键为 `pos-v3-table-positions`，不是按门店分键；正式位置数据应按storeId+areaId+tableId隔离，不能直接沿用全局键。订单与上传图当前刷新丢失，Android需定义进程重启后的恢复策略。

## 2 核心实体

| 实体 | 原型主要字段 | 正式模型要求 |
| --- | --- | --- |
| Store | id、name、en、address、code | 员工授权关联、营业状态、版本 |
| Area | 数组中的id、中文名、英文名 | 独立areaId，禁止按显示文案关联 |
| DiningTable | id(桌号)、area、seats、status、minutes、reservation、paid、x/y | 独立tableId、displayNumber、storeId、areaId；时间与订单关联分离 |
| Category | 中文名、英文名，商品category按中文名关联 | 稳定categoryId；改名不影响商品关系 |
| Product | id、name/en、category、price/basePrice、stock、spec、specId/specIds、skus、image、tags/hot/timed | categoryId、mediaId、版本、可售状态；兼容旧spec需显式迁移 |
| OptionGroup | id、name/en、values字符串、required | Option(id、name、translations、surchargeMinor)数组；不把字符串解析当生产协议 |
| SKU | key、choices、price、stock、manualPrice/manualStock | 稳定skuId、optionIds、价格分、库存版本；manual字段属于编辑默认值策略 |
| Menu | id、name/en、items、published | 菜单明细、发布时间/版本、可售时段；发布需校验非空 |
| Order | table、guests、lines、member/coupon/activity、paidRecords、note、held | orderId、storeId、tableId、版本、业务状态、报价/优惠结果 |
| OrderLine | id、dishId、name/en、unit、qty、spec、note、skuKey、status | productId/skuId、名称/规格/单价快照、批次id；服务端状态版本 |
| PaymentRecord | id、label/en、amount、method、time | paymentId、orderId、状态、金额、渠道、服务端时间、幂等键 |
| DisplayPreferences | model.mjs中的设置字段 | 校验枚举、默认值、schemaVersion；移除选项兼容旧数据 |

原型金额为整数分；Android建议金额使用Long最小货币单位，数量使用整数，禁止用Float/Double进行财务累计。界面统一两位小数。正式价格与优惠由报价服务确认，原型公式仅用于一致性测试。

时间正式保存时间戳并统一服务端/门店时区策略，界面再格式化；原型 `minutes` 和 `12:10` 是演示显示值。账号、令牌、支付资料与普通界面偏好分开管理。

## 3 UiState、Action 与 Effect

每页状态包含内容、加载/提交状态、字段错误和可用操作。单一 `isLoading` 不应阻塞所有不相关区域，例如图片读取只影响图片/保存，不能清空SKU输入。

| 页面 | UiState关键项 | Action示例 | 一次性Effect |
| --- | --- | --- | --- |
| 桌台 | 区域/状态/搜索、列表、选中详情、grid/floor、错误 | SelectArea、SelectTable、SeatGuests、ChangeView | 打开人数弹层、进入订单 |
| 点餐 | orderId、目录、查询/筛选、购物车分组、送厨状态 | AddProduct、SelectSku、ChangeQuantity、SendKitchen | 规格选择、库存不足提示 |
| 结账 | 订单分组、报价、优惠资产、支付方式、支付状态 | ApplyBenefit、RequestQuote、StartPayment、RetryQuery | 支付确认、完成后返回 |
| 商品编辑 | 基础资料、规格组、SKU草稿、图片状态、餐牌勾选 | ChangeBasePrice、SelectGroups、EditSku、PickImage、Save | 图片选择器、保存成功返回 |
| 显示 | 偏好、当前分组、形状微调展开 | ChangePreference、Reset | 无业务订单副作用 |

这些命名为Android建议，不要求复刻HTML的字符串data-action。事件携带id和值；不要依赖列表下标作为长期关联。相同操作不重复生成订单、送厨批次或支付单。

## 4 订单行与送厨状态

| 当前 | 事件/条件 | 结果 | 原型行为与正式要求 |
| --- | --- | --- | --- |
| new | 加减且库存允许 | new或数量归零移除 | 仅草稿可直接改数量；同SKU/同规格/同备注/同单价可合并 |
| new | 送厨且在线 | sent | 原型直接模拟成功；正式需等待任务/服务回执 |
| new | 送厨且离线 | queued | 原型会话队列；正式必须持久化幂等批次 |
| queued | 在线重试 | sent | 正式重复重试不得重复出单，失败保留队列 |
| sent | 催菜 | rush | 禁止回退到new |
| sent或rush | 上菜 | served | served不得因重复/乱序事件回退 |
| served | 催菜 | 不变 | 原型忽略不可回退操作，正式给出一致状态 |

清空草稿只移除new，保留queued/sent/rush/served。送厨后调整数量必须通过退菜/加菜等正式命令及权限，不能复用草稿步进器。原型挂单只是held标记，不等于后台订单持久化。

当前设置面板已移除网络演示开关，但model仍覆盖offline/queued测试；正式离线状态应由连接与同步层提供，而非显示偏好。

## 5 桌台状态

空闲idle → 开台 → 用餐中dining；预订reserved → 到店开台 → dining；完成真实结账后 → paid → 进入清台cleaning → 清台完成idle。

- 原型 `tableState()` 在订单含行时优先显示dining；这是演示派生逻辑，不是生产桌台状态机。
- 原型可演示paid→cleaning→idle，但收款核对没有真实支付完成并更新桌台的闭环。
- 正式结账成功必须由订单/支付权威结果驱动桌台变化，禁止仅点击按钮就置paid。
- 预订、桌台占用和账单状态分开建模，避免已有预订覆盖当前用餐状态。
- 开台人数为1至该桌座位数；桌号在门店范围内唯一；状态变更需检查版本，避免两终端同时开台。

平面画布当前900×460，各区域独立；坐标校验x=0–744、y=0–332（历史边界，仍在使用）。卡片当前140×112，不能据其尺寸自行扩大历史坐标范围。Android将位置与画布单位分开，缩放统一换算；目前只有坐标输入，未实现拖拽、旋转或墙体编辑。

## 6 SKU、库存与图片

### SKU组合规则

选择多个规格组生成笛卡尔组合，最多100个SKU。原型按组id排序，以组id+选项名称生成key；正式用稳定组/选项id生成组合并分配skuId。新组合默认售价=基础售价+各选项加价；库存取启用规格前的默认份数。

修改基础价/规格时保留仍存在组合的手动值；未手动调价的组合随基础价重算。删去组合后再次添加，其草稿手动值不保证恢复。SKU价格0–99999元、最多两位小数，库存非负整数；有SKU时商品库存为合计只读，展示售价取SKU最低值。

点餐必须选择可售SKU，所选SKU单价快照进入订单；0余量禁选。当前校验仅统计当前单桌订单，没有跨桌库存预占、售后回补或并发扣减。正式库存服务应返回可售量、版本及拒绝原因；冲突后刷新并保留其他编辑内容。

### 图片状态

empty → reading → ready；读取或解码失败 → error，可重新选择；remove恢复empty。读取中阻止保存，替换/移除/关闭使旧异步回调失效。格式JPG/PNG/WebP，≤5MB；支持地址输入作为替代，两种输入互斥。

原型Data URL只存会话。Android应区分本地选中Uri、上传中、mediaId/remoteUrl、失败重试；系统图片选择后处理所需Uri访问生命周期。正式保存前完成授权上传，成功后关联mediaId；取消或上传失败不覆盖原图。裁剪/压缩当前未实现，不作为已交付功能。

### 餐牌关联

商品可关联零/多餐牌；关联已发布餐牌后在点餐可见，草稿餐牌不自动发布。保存替换该商品关系，不改变其他商品且不得重复。解除全部发布关联后隐藏商品，已有订单行快照继续保留。空餐牌自动停用且不可发布。

## 7 结账与优惠边界

原型账单分新加/待送厨、已送厨未结账、历史已结账记录；优惠分会员、券、活动、储值卡等入口。当前会员95折、满200减10券、满100减5活动及5%服务费为本地示例，可叠加；门店设置里的费用配置不应被误认为已驱动全部金额模型。储值仅预览，不扣真实余额。

`payment-review`要求订单非空且没有new/queued行，随后仅展示模拟核对。现金、扫码、银行卡、储值是选择与预览状态，没有真正执行收款、券核销、退款或储值扣款；历史记录为示例。

正式支付建议状态：idle → quoting → ready → submitting → processing → succeeded / failed / unknown。unknown用于网络中断后无法确认结果，必须查询权威结果再允许再次付款；不能将超时直接视为未支付。成功回执需写入订单、收款记录、桌台及打印任务，失败保留账单和可重试入口。

## 8 Repository能力与接口准备

| 能力 | 输入重点 | 输出/失败处理 |
| --- | --- | --- |
| Authenticate / LoadStores | 非日志化凭据、终端上下文 | 会话/授权门店；无权限/失效 |
| LoadCatalog / LoadTables | storeId、版本、筛选 | 目录/桌台快照；增量或全量策略另定 |
| SeatTable | storeId、tableId、guests、版本、requestId | orderId；已占用/版本冲突 |
| SaveProduct | 草稿、SKU集合、mediaId、餐牌关系、版本 | 商品快照；逐字段错误、组合冲突 |
| AdjustInventory | SKU盘点数量、原因、版本、requestId | 库存新版本；冲突需重新核对 |
| SendKitchenBatch | orderId、行快照、batchId/幂等键 | 批次状态；离线/超时可查询 |
| QuoteOrder | orderId、版本、券/活动/资产选择 | 明细、应收、不可用原因、报价有效期 |
| Create/QueryPayment | orderId、quoteId、渠道、幂等键 | paymentId及权威状态；未知结果查询 |
| UploadMedia | 本地文件、类型、大小、storeId | mediaId、缩略图；校验失败/重试 |
| PrintJob | orderId、票据类型、requestId | 排队/已发设备/已确认/失败；人工补打标识 |

正式后端需补齐鉴权、请求/响应schema、版本冲突、幂等范围、错误码及审计要求后再接入。页面开发先用演示实现，不能把本文示意方法名当现成HTTP接口。

## 9 验证依据

原型测试入口：`node --test prototypes/v3/*.test.mjs`。现有18项模型测试覆盖数量/库存、送厨离线队列、金额、设置迁移、布局映射、厨房状态、桌台筛选/坐标、管理校验/餐牌关系、SKU生成与独立库存等。

这些不是Android UI测试，也不验证真实支付/打印/并发。Android另做ViewModel状态测试、组件截图/交互测试及真机流程验收，案例见[页面实施清单](页面实施与验收清单.md)。
