# Android POS · 零售业态接入方案与任务（2026-11-11）

> 分支：`android-retail`（从 `android-ui-v3` `80130b4` 切出）。餐饮功能仍在 `android-ui-v3` 上继续开发，本分支定期合入它。
> 规格来源：React 原型 `prototypes/pos-react`（已冻结，分支 `pos-react-retail`）的零售部分，以及《[零售 POS 设计方案](../全线点餐POS-零售POS设计方案.md)》《[原型 → App 交接清单](../全线点餐POS-原型交接App清单.md)》（两份文档在 `pos-react-retail` 分支）。新画面需要原型时只做静态 UI 原型。

## 一、原则

1. **同一个 App。** 不另做零售 App。登录后选的门店带「业态」（餐饮 / 零售），决定进哪套工作台；同一账号可以有不同业态的门店，切店即切业态。
2. **共用的照用，不复制。** 登录与选店、账号与权限、系统管理（分类、商品与 SKU、库存盘点、收款方式、设备、员工）、交班、报表、打印、客显、同步与主副 POS、设计系统组件全部共用；只有业态独有的流程新做。
3. **按现有工程的约定写。** Screen 只收 `UiState` + `onAction`；业务规则写进 `core/model` 的纯 Kotlin 规则对象并配单元测试；数据按门店隔离存在 `LocalWorkspace`；金额一律 `Long` 分。
4. **规则从原型移植，按「分」改写。** 原型 `src/domain/*.ts` 用元做浮点；App 里改成分的整数运算，移植时用原型的随机输入导出对照数据（fixtures）核对结果。

## 二、业态差异一览

| 方面 | 餐饮（现有） | 零售（新增） |
|---|---|---|
| 工作台页签 | 桌台 · 点餐 · 系统管理 | 收银 · 订单 · 商品 · 系统管理 |
| 开单 | 选桌开台 → 点菜 → 送厨 → 结账 | 扫码加购 → 收款（一单几十秒，无桌台、无送厨） |
| 商品录入 | 分类宫格点选、规格 / 套餐弹窗 | 扫码为主（标准码、称重码、店内码、PLU），宫格放无码商品；称重弹窗、尺码 × 颜色 SKU 矩阵 |
| 计价 | 服务费、活动与券互斥、用券不抹零、抹零到元 | 无服务费；行级促销（第二件半价）、会员价（低于售价才生效）、券在促销后、抹零到角 |
| 售后 | 退菜、反结账 | 退货（有单 / 无单授权）、换货（抵扣带回收银，多退少补） |
| 库存 | 今日份数、沽清、盘点 | 进销存：入库、盘点（审批过账）、报损、预警、流水；卖出自动扣、退货回库或报损 |
| 打印 | 小票、厨房单（分档口） | 小票、退货小票、价签（EAN-13） |
| 外设 | 打印机、厨房屏、客显 | 扫码枪（HID）、电子秤、标签打印机、客显 |

## 三、数据模型改动（`core/model/Models.kt`，全部带默认值，旧数据可直接读）

| 改动 | 说明 |
|---|---|
| `BizType { Dining, Retail }`；`StoreData.biz`、`StoreSummary.biz` | 默认 `Dining`，现有门店不受影响；演示数据加一家零售门店 |
| `Product` 加 `barcodes`、`unit`（件 / kg）、`weighable`、`costPrice`、`memberPrice`、`promo`（第二件半价等）、`expiry`、`safetyStock` | 餐饮不用的字段为空 |
| `Sku` 加 `barcode` | 服饰尺码 × 颜色每格一个码 |
| 新增 `RetailSale`（单号、行、会员、整单优惠、收款、退货记录、状态）与 `RetailLine`（商品 / SKU、件数或重量、单价、促销、会员价、赠送、临时商品） | 不复用 `TableOrder`：零售没有桌台、送厨、上菜状态 |
| 新增 `StockDoc`（入库 / 盘点 / 报损：草稿 → 已过账；盘点提交时冻结账面快照）| 过账写现有 `stockMovements`，流水原样复用 |
| `PaymentRecord` 复用 | 零售收款、退款、换货补差 / 退差都记在这里，交班汇总自然包含 |

## 四、规则移植（`core/model/Retail*.kt`）

| 新文件 | 内容（原型出处） |
|---|---|
| `RetailCartRules` | 扫码加购合并（同商品同规格合并并移到最上，称重行不合并）、加减、撤销、赠送、件数、第二件半价（`domain/cart.ts`） |
| `RetailPricing` | 小计 → 行级促销 → 会员价 → 券 → 抹零到角 → 应收；换货抵扣后的补收 / 退差（`domain/pricing.ts` 的 RETAIL_RULES、`aftersale.exchangeSettle`） |
| `BarcodeRules` | 码分类（标准码 / 店内码 / PLU / 18 位称重码 / 会员码 / 付款码）、称重码解析、按码找商品、EAN-13 校验与条码模块（`domain/catalog.ts`） |
| `ReturnRules` | 可退数量（称重整行）、整单优惠按行分摊（尾差落金额最大行）、退款金额、默认回库、原单状态、平台单不能门店退、无单退货限制（`domain/aftersale.ts`） |
| `StockDocRules` | 入库、盘点差异与过账、报损、临期、低库存、按变化量改库存（`domain/stock.ts`） |

收款键盘、快捷金额、找零、收款方式可用性、班次盘差这些两业态共用的规则，先看现有 `OrderRules` / `WorkbenchRules` 有没有，有就共用，没有再补进共用文件，不放进零售文件。

## 五、画面（`feature/retail/*`）

对照原型的画面预设逐个做；组件全部用现有 `core/designsystem/component`，缺的补进设计系统（例如 SKU 矩阵、价签预览），不在 feature 里自绘。

| 画面 | 原型 | 要点 |
|---|---|---|
| 收银（W2：购物车 + 扫码区 / 收款区） | `retail/RetailPos.tsx` | 常驻扫码框、快捷商品、刚扫一件（撤销 / 再来一件）、数量 × N、查价、临时商品、开钱箱；称重弹窗；SKU 矩阵；取单 / 挂单；清空确认；收款（现金 / 扫码 / 刷卡，复用结账的收款组件）；收款完成「下一位」 |
| 订单 · 退货 · 换货 | `RetailOrdersWB.tsx` `ReturnDialog.tsx` | 列表与状态筛选、详情、退货四步、无单退货授权、换货三步 → 收银带抵扣 |
| 商品 | `GoodsWB.tsx` `PriceLabel.tsx` | 商品资料（改价 → 待打价签）、库存（筛选、流水、去入库 / 盘点）、价签（队列、模板、预览、打印） |
| 库存作业（系统管理里） | `StockWB.tsx` | 入库、盘点（提交 → 审批过账）、报损、预警；调拨标「未实现」 |

## 七、待定

1. 一个账号下的门店是否允许混合业态（例如餐厅里的零售角）——方案先按「一店一个业态」，混合放后面。
2. 零售订单号规则（原型用 `#R` 前缀）是否和餐饮共用序列。
3. 标签打印机型号与指令集（TSPL / ZPL / ESC/POS 标签模式）。
4. 电子秤型号与通讯协议。
