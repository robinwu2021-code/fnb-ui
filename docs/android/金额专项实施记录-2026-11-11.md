# 金额专项实施记录（N2）

日期：2026-11-11。分支 `android-ui-v3`。对应 [实施方案 §4.2](../architecture/下一阶段实施方案-2026-11-10.md) 的金额专项，必须在新协议字段冻结和接入真实支付之前完成。

## 规则（`core/model/Money.kt`）

| 项目 | 规则 |
| --- | --- |
| 单位 | 全部金额为 Long 整数分，不使用浮点参与计算 |
| 币种 | `CNY`；门店设置 `StoreSettings.currency`，收款 `PaymentRecord.currency`；不支持的币种拒绝收款 |
| 单价/加价上限 | ¥99,999.00（`MAX_UNIT`），与商品管理原有上限一致 |
| 单行份数上限 | 999 份（`MAX_QTY`），点菜弹窗步进器同步 |
| 单据/收款/备用金上限 | ¥99,999,999.99（`MAX_BILL`） |
| 比例计算 | 服务费、会员价、手工折扣按万分比整数运算，四舍五入：0.5 分进位 |
| 溢出 | 乘法和累加用 `multiplyExact` / `addExact`，溢出时抛异常，不会回绕成负数；业务入口先按上限拒绝 |
| 输入 | 元文本最多两位小数；现金实收最多 8 位整数 |

## 改动范围

**模型：** 以下金额字段全部由 Int 改为 Long。
- 商品和规格：`Sku.price`、`Product.price`、`SpecOption.delta`、`MealChoice.delta`、`MealSelection.delta`。
- 订单和收款：`OrderLine.unit`、`Totals`、`PaymentRecord` 的 amount/received/change、`DiningTable.paid`。
- 余额和调整：`walletBalance`、`AdjustmentAudit.amount`。
- 交班：`ShiftState.float`、`ShiftRecord` 的全部金额和各渠道金额。

**规则：**
- `OrderRules.totals` 改为整数运算。
- `OrderRules.add` 新增三项上限：单价、单行份数、单据金额。超限时拒绝并给出原因。
- `ManageRules.price` 和 `ManageRules.options`、`MealRules.price`、`CashRules`、`ShiftRules.summary` 都已改为 Long。

**仓库接口：** `settle` 的金额和实收、`closeShift` 的实盘都改为 Long。收款时校验上限和币种。交班实盘改用单据上限，原来误用单价上限，只能填 ¥99,999。

**页面：** 结账、现金键盘、点菜弹窗、交班页已适配。点菜弹窗原来把金额截断为 Int 显示，现在改为溢出时显示「—」。

**词条：** en.json 新增 7 条。

## 兼容与迁移

- **旧数据：** 旧快照和事件中的金额都是 JSON 整数，可以直接按 Long 解码，不需要迁移脚本。
- **币种：** 旧数据缺少币种字段时，默认为 CNY。
- **载荷版本：** 事件载荷的字段结构没有变化，只是新增了可选的币种字段，所以载荷版本仍为 1。

## 验证

- **单元测试：** 新增 `MoneyTest`，共 7 项。全部 101 项通过。覆盖内容：
  - 四舍五入边界：0.45 分舍、0.5 分入、1.5 分入。
  - 溢出抛异常。
  - 元文本解析与上限。
  - 订单上限拒绝，且单据可以超过旧 Int 能表示的范围。
  - 现金大额输入。
  - 旧 Int JSON 解码。
  - 原型账单在会员、九折、券、活动叠加时金额不变。
- **设备测试：** 19 项通过。
- **模拟器：**
  - 用旧 Int 金额数据覆盖安装，加载正常，桌台金额显示正确。
  - 对 A02 现金结账，应收 ¥32.00：服务费 ¥1.60，会员优惠 −¥1.60。
  - 设备库里的 PaymentRecorded 事件记录了 amount=3200、currency=CNY 和订单号，没有崩溃。

## 仍未覆盖

- **多币种：** 只支持人民币。多币种需要汇率和舍入规则，暂未涉及。
- **舍入策略：** 服务费、会员价、券、活动都是本机演示规则。真实报价和优惠核验属于 N10，届时需要按服务端的舍入策略重新核对。
