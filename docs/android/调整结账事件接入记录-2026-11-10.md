# 改量、授权调整及结账事件接入

日期：2026-11-10。延续[开台加菜接入](开台加菜命令接入记录-2026-11-10.md)，本轮保持现有页面和Repository接口。

| 操作 | 事件 | 事件额外信息 |
| --- | --- | --- |
| 改量 | DishQuantityChanged | 桌台及订单结果快照 |
| 退菜 | DishVoided | 对应主管授权审计 |
| 赠送 | DishGifted | 对应主管授权审计 |
| 整单折扣 | OrderDiscounted | 对应主管授权审计 |
| 结账记账 | PaymentRecorded | 对应支付记录，含实收、找零及支付方式 |

上述事件、Inbox回执、命令流版本和业务快照在同一SQLite事务中保存。退菜打印任务、结账打印任务及现有离线队列包含在同一业务快照事务内。写入失败不发布内存状态；校验或授权被拒绝不生成新事件。

PaymentRecorded表示当前本地收款逻辑已记账，不代表第三方支付渠道已实际成功；模拟支付限制仍保留。结账后订单虽被清空，事件中的支付快照仍可追溯。

## 验证

70项单元测试通过，Debug和测试APK编译通过。11项SQLite设备测试通过，新增两项页面用例覆盖改量、退菜、折扣、赠送、审计/支付JSON内容、授权失败、重复赠送、重复结账以及结账失败后的内存和磁盘回滚。测试在emulator-5556执行。

独立审阅无重要问题；按审阅建议补充内存回滚及结构化JSON字段断言。

## 后续

当前仍为每门店本地页面命令流；送厨、并台/拆单、桌台生命周期、挂单、优惠和配置等操作尚未全部事件化，不能通过事件重建完整门店。真实主副POS通信、授权校验、支付查询和厨房回执仍待接入。网络超时重试须复用原命令ID，不能通过重新点击付款替代查询结果。
