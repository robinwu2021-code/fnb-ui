# N1-03 管理与账本事件补齐记录

日期：2026-11-11。分支 `android-ui-v3`。完成后，N1 的写入覆盖全部落地：营业写入口都有事件，设备和同步入口进入本机任务日志。

## 事件机制调整

`LocalWorkspace` 的事件参数从「类型 + 桌号」改为 `EventSpec`。事务在锁内拿到提交前后的门店数据，再决定事件类型和载荷。
- 页面订单和桌台事件通过 `page(type, tableId)` 沿用 `BusinessEventFactory`，载荷不变。
- 管理和账本事件使用新的 `ManagementEventFactory` 专属载荷，不伪造 tableId。

所有事件仍然共用过渡聚合 `page-order-stream`，保证本地修订号连续。按实体拆分聚合属于 N2-02。

## 新增事件

| 入口 | 事件 | 载荷 |
| --- | --- | --- |
| `addArea` | AreaCreated | `ConfigEventPayload` |
| `saveTable` | TableConfigCreated / TableConfigUpdated | 同上；桌台只比较区域、座位、坐标，不含营业状态 |
| `addCategory` | CategoryCreated | 同上 |
| `addSpecGroup` | SpecGroupCreated | 同上 |
| `saveProduct` | ProductCreated / ProductUpdated | 同上；餐牌关联的变化一并列出 |
| `saveMenu` | MenuCreated / MenuUpdated | 同上 |
| `setPublished` | MenuPublished / MenuUnpublished | 同上 |
| `saveSettings` | StoreSettingsUpdated | 同上 |
| `adjustStock` | StockAdjusted | `StockAdjustedPayload`：库存流水和调整后的商品 |
| `closeShift` | ShiftClosed | `ShiftClosedPayload`：固化的交班记录和账本范围 |

**配置载荷 `ConfigEventPayload`**
- 字段为 `entity`、`entityId`、`changes`。每条变化都带实体类型、ID 以及前后完整内容，新建时 before 为 null。
- 主实体本身可以不变，例如商品只改了餐牌关联，但本次必须有配置变化，否则不写事件。
- 现在页面没有删除入口。以后加删除时用墓碑表示，即 after 为 null。
- 载荷不含账号、密码哈希或显示偏好，测试中有断言。

**库存流水**
- `StoreData.stockMovements` 是新增字段，旧快照默认为空。
- 每条记录商品和 SKU、名称、调整前后数量、差量、原因、操作人和时间。
- 调整前不限量时，前值和差量都为 null。
- 新增校验：SKU 必须存在，原因不超过 60 字。

**交班载荷**
- 包含交班记录、本班时间范围内的收款 ID 和授权调整 ID、交班单打印任务 ID。
- 同时记录交班时仍待同步的队列项，以及未同步收款的 ID，作为交班时的未决项。

## 设备任务日志

预结单、补打、打印执行和同步补发不写营业事件，而是写入 `StoreData.taskLog`。日志只保留最近 500 条。

| 入口 | 日志类型 | 来源 |
| --- | --- | --- |
| `preBill` | PrintRequested | local |
| `reprint` | PrintReprinted，detail 记原任务 ID | local |
| `process` | PrintAttempt，只在状态变化时记录 | simulation |
| `syncNow` | SyncAttempt | simulation |

来源为 simulation 的记录是模拟引擎的结果，不能当作真实出纸或云端回执。

## 写入权限

管理和账本写入目前只在本机执行。按已确认方案，以后接入一主多副时，这些写入只允许主 POS 执行，副机需要经主机仲裁。N5 之前不开放多机写入。

## 验证

- **单元测试：** 新增 `ManagementEventsTest`，共 6 项。覆盖配置事件、餐牌关联、库存流水、交班范围、任务日志，以及写入失败后状态不变。全部 85 项通过。
- **设备测试：** 新增 1 项。库存事件写入失败时整体回滚，重启后库存流水仍在，交班事件固化记录。全部 14 项通过。
- **模拟器：**
  - 带着已有数据覆盖安装，升级后正常加载。
  - 在库存盘点里把水煮鱼「标准 · 微辣」从 8 改为 12，交班时实盘填 500 元。
  - 设备库中依次出现 StockAdjusted 和 ShiftClosed，载荷内容正确，没有崩溃。
