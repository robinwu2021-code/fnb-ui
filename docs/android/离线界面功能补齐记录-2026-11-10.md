# Android POS 离线界面功能补齐记录

更新：2026-11-10。工程：`bak/pos-android`，分支：`android-ui-v3`。本轮以本地快照、演示账号与现有共享组件补齐交互；无需后端即可查看和操作以下页面。

## 功能与入口

| 功能 | 入口 | 本轮实现 |
| --- | --- | --- |
| 主管授权 | 点餐账单更多操作 / 结账优惠区 → 主管授权·退赠折扣 | 退菜、整行赠送、整单折扣；输入主管账号、密码和原因；授权失败不改账单 |
| 退菜 | 授权弹层 | 已送厨行选择份数；待同步行先同步；生成本地厨房退菜单；最后一行退完转待清台，可清台恢复空闲 |
| 赠送 | 授权弹层 | 原单价与数量快照保留，赠送行不收费；重复赠送拒绝，草稿赠送后不再直接加减 |
| 折扣 | 授权弹层 | 1–100价格百分比，80代表八折，100恢复原价；在会员优惠后计算，不减服务费 |
| 操作记录 | 授权弹层下方 / 交班 | 记录操作人、授权人、原因、时间、数量、金额；随门店快照保存，交班增加退赠统计与打印明细 |
| 现金找零 | 结账 → 现金 | 数字键盘、刚好、快捷面额、清空、实收与找零；不足或精度错误不能确认；小票记录实收和找零 |
| 本地优惠 | 点餐优惠券 / 结账优惠与资产 | 满200减10券、满100减5本机活动；门槛不足提示，不重复叠加同一优惠 |
| 储值演示 | 结账 → 储值卡 | 绑定本机会员后扣减门店演示余额，初始500元；余额不足拒绝，扣减与收款记录一起保存 |
| 批量状态 | 点餐已下单分组 → 批量 | 多选/全选菜品，批量催菜或已上菜；不把已上菜回退为催菜 |
| 预订管理 | 桌台搜索左侧 → 预订管理 | 新建、取消、到店开台、历史状态；校验联系人、电话、人数、时间和桌台占用 |
| 旧预留兼容 | 自动迁移 | 旧版Reserved桌台迁入预订列表，联系人标记待补充，可取消或到店开台 |
| 拼音搜索 | 点餐搜索 / 商品资料 → 搜索别名 | 匹配中文、英文、编号、拼音及首字母；演示数据内置别名，自建商品可录入 |
| 套餐换菜 | 商品编辑 → 套餐换菜 / 点餐套餐选择 | 配置组、选项与非负加价；每组必选一项，展示差价；选择及单价写入订单快照和厨房单 |
| 字体 | 显示设置 → 字体 / 组件验收 | 随包Manrope、Inter、Roboto、Noto Sans、IBM Plex Sans、Outfit；另可选系统字体；Outfit标题配Inter正文 |
| 组件展示 | 系统管理 → 组件验收 | 补充现金键盘、找零和所有字体对照 |

### 本机授权方式

直接体验会话使用公开演示主管：`manager@demo.local` / `demo12345`。本机注册的商户账号可用自己的密码授权（账号作为本地商户主管，保存加盐哈希）。演示主管不在普通注册账号会话生效。授权不切换当前登录身份；审计中不保存输入密码。

这仍是本机角色模型；真实员工权限、主管分配和云端认证在服务接入阶段实现。

## 本地持久化与兼容

- Vault升级为schema v3，显式保存版本与新增默认字段，兼容旧v2及旧快照省略version的情况。
- 迁移保留原订单、账号、库存、餐牌和收款；对未改名的演示商品补齐缺失的搜索别名与套餐示例配置。
- 预订与授权记录、演示储值余额都在StoreData中按门店保存。预订当前采取“立即留台”，同一桌在取消或到店前不接收第二个预订，尚不支持时段轮转。
- 不同优惠规则的非空订单禁止直接合并/拆入，先核对一致；空目标订单继承来源优惠，避免操作后悄悄丢掉主管折扣。
- 金额校验与结账核对再次在仓库执行，账单变化或重复结账不会按旧金额再次收款。

## 离线边界

保留现有规则：新加和待同步菜品不能结账，避免清空订单后丢失尚未处理的送厨批次；离线产生的批次仍落盘排队。现金、银行卡和本机储值演示可对已完成送厨/同步的订单记账；扫码离线不可用。

打印任务只在本机模拟处理，不连接真实硬件。本机券、活动和储值是演示数据，不核销真实资产。拼音采用商品别名，不依赖联网转换；套餐选项是本地配置，不自动扣减被换入菜品的原料库存。多终端库存、真实支付及真实同步仍待服务契约。
