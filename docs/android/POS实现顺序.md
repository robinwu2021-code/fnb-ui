# 餐饮 POS Android 实现顺序

> 2026-11-10排期更新：本轮离线界面项已补齐，下一步先处理本机可靠性与离线管理闭环；具体顺序和验收见[剩余任务清单](剩余任务清单-2026-11-10.md)。下文阶段一、二保留历史验证记录。

更新：2026-11-05。依据 [功能清单](POS功能清单（按页面）.md)、[数据契约](数据契约与交互状态.md)、v3.2–v3.4 规范。原则：**先完整离线，再接服务**。每一阶段结束时应用在断网下可独立完成该阶段的全部业务，数据重启不丢。

## 阶段一：完整离线模式（已完成 2026-11-05）

目标：不依赖任何后端，一台终端即可完成「登录 → 选店 → 配置门店 → 开台点餐 → 送厨 → 结账 → 清台」。

| 顺序 | 内容 | 完成标准 |
| --- | --- | --- |
| 1.1 | 门店级本地数据：区域、桌台、分类、规格组、商品与 SKU、餐牌、订单、收款、同步队列 | 全部按门店隔离、带稳定 ID，重启后恢复 |
| 1.2 | 联网状态：系统网络检测 + 演示「强制离线」 | 页头云图标反映真实状态与待同步数量 |
| 1.3 | 离线送厨：新加 → 待同步（queued）→ 联网自动补发 → 已下单 | 批次幂等，重复补发不重复出单；状态不回退 |
| 1.4 | 离线收款：现金 / 银行卡本地记账，扫码 / 储值离线禁用 | 收款记录进入同步队列；有新加或待同步行不能结账核对 |
| 1.5 | 同步队列页 | 列出待同步 / 已同步批次，可手动立即同步 |
| 1.6 | 本地账号：登录、注册、直接体验；选择门店 | 邮箱格式、密码 ≥ 8 位、两次一致；密码只存加盐哈希；切店数据隔离 |
| 1.7 | 系统管理：桌台、区域、门店与营业 | 桌号唯一、座位 1–30、区域名唯一；门店简称同步页头 |
| 1.8 | 系统管理：分类、规格组、商品资料（六分区 + SKU + 图片）、库存盘点、餐牌 | 按 v3.3 / v3.4 校验；只有已发布餐牌中的商品进入点餐；SKU 独立价格与库存 |
| 1.9 | 系统管理：终端与打印、收款与费用、员工与权限、界面显示、切换门店、退出登录 | 信息页与入口可用，不冒充真实设备 |

阶段一验证：24 项单元测试通过；模拟器（pos_tablet）跑通注册 → 选店 → 强制离线送厨 → 结账被拦 → 同步队列 → 恢复在线自动补发；新建桌台、新建带 SKU 的商品并关联餐牌、发布草稿餐牌后点餐可见、SKU 规格加菜、切店隔离、退出与重新登录、重启后会话与数据保留。验证中修复：标签点击不聚焦输入框、注册错误显示位置、开关行只能点小开关、账单新分组出现在可视区外、商品编辑返回键直接丢草稿、表格列间无间距、新商品默认库存为 0。

## 阶段二：工作台补全（离线，已完成 2026-11-05）

| 顺序 | 内容 |
| --- | --- |
| 2.1 | 桌台平面位置视图与坐标调整 |
| 2.2 | 换桌、并台、拆单 |
| 2.3 | 菜品备注、整单备注、挂单与取单 |
| 2.4 | 交班：按本地收款记录汇总，钱箱核对 |
| 2.5 | 小票预览与本地打印队列（缺纸重试、补打标识） |
| 2.6 | 组件验收页 |

阶段二验证：38 项单元测试通过（含换桌 / 并台 / 拆单、备注、挂单取单、打印失败与重试、离线批次换桌后补发、交班汇总、坐标校验、翻译词条）。模拟器跑通：平面位置与调整坐标、菜品备注、挂单取单、换桌候选（按座位过滤）、缺纸厨房单失败 → 换纸自动重打、小票预览、结账单与交班单入队、清点交班与差额、组件验收页、页头一键切换英文（桌台、点餐、管理页无残留中文）。验证中修复：Android 正则对 `}` 更严格导致启动崩溃（翻译加载改为失败不影响启动）、经页头离开结账后回到点餐出现旧结账页、旧数据无开班时间显示 1970 年、英文分类栏截断。

实现说明：
- 英文界面：设计系统提供统一 `Text`，渲染前查 `assets/i18n/en.json`（728 条，含 `{0}` 模板与切段回退）；新增文案需补词条。
- 字体：随包 Manrope 可变字体（OFL，许可见 `assets/licenses`）用于拉丁文字与数字，中文按字形回退系统 Noto Sans CJK；可在显示设置切换为系统字体。其余四种字体方案未随包。
- 打印：本机模拟打印（只改变任务状态），厨房单受「模拟打印机缺纸」影响，前台单不受影响。

| 顺序 | 内容 |

## 本轮约定

- 「离线」= 云端不可达。送厨批次与收款在本地落盘并排队，联网后按创建顺序补发。
- 按数据契约：订单仍有新加或待同步菜品时不能结账核对。若门店需要断网结账，需另定产品规则（例如允许本地厨打后视同已送厨）。
- 同步引擎目前对接的是本地模拟服务：补发即视为成功。阶段三替换为真实接口，接口与幂等语义不变。
