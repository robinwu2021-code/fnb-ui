# 现有 Android 工程评审与 v3 UI 对齐记录

日期：2026-11-05。对象：[bak/pos-android](../../bak/pos-android/README.md)（分支 `android-ui-v3`）。基线：v3 原型（组件规范 v3.5、落地 v3.6）及本目录架构文档。

结论：技术栈可沿用；代码分层过薄、状态集中在一个全局 ViewModel，是进入真实业务前必须先处理的问题。本轮已把点餐、桌台、结账、显示设置的界面对齐到 v3 原型，并在平板与手机模拟器上构建、运行、截图核对。

## 1 技术架构评审

| 项目 | 现状 | 评价 |
| --- | --- | --- |
| 语言与 UI | Kotlin 2.4 + Jetpack Compose（BOM 2026.09）+ Material 3 | 合适，继续沿用 |
| 构建 | AGP 9.4、Gradle 9.8、compileSdk 37 / minSdk 26 / targetSdk 36、Java 17 | 版本新；首次构建需联网拉依赖，离线构建会失败 |

| 测试 | 无单元测试、无 UI 测试 | 金额、SKU、送厨状态机需先补单测 |

## 2 代码架构评审

### 2.1 主要问题

- **订单串桌**：原 `PosStore` 只有一张当前订单。切换桌台只改桌号不换明细，开台直接清空明细，违反必测场景 1。本轮已改为按桌台保存订单明细。
- **全局可变状态**：界面直接写 `store.member = …` 等字段，Screen 拿整个 Store。与《原型架构与 Android 页面映射》§4 的 `Screen(UiState, onAction)` 约定不符，后续拆分成本随页面增多上升。
- **界面依赖演示数据**：多个页面直接 import `MockData`。接服务时界面层必然要改，与旧 README「换 repository 即可」的说法不符。
- **无持久化与恢复**：草稿、送厨队列、显示偏好都只在内存里。重启恢复和离线送厨队列无法验收。
- **一次性效果混在状态里**：提示条是 Store 字段加协程计时，可接受，但导航与弹窗仍由页面局部状态驱动，没有统一的 Effect 通道。
- **旧视觉体系**：v2 色板 7 套皮肤、深色模式、全胶囊按钮、灰色块、旧 L1–L6 语义，与 v3 规范冲突。本轮已替换。
- **触控热区**：步进器、筛选、页头按钮视觉 36dp 且无命中扩展。本轮基础组件统一补到 48dp 命中。

### 2.2 建议的拆分顺序

1. 抽出 `core/model`（实体、金额、状态枚举）与 `core/data`（Repository 接口 + 演示实现），界面不再 import `MockData`。
2. 按作用域拆状态：会话 / 门店、订单（按 orderId）、显示偏好（DataStore 持久化）、设备状态。
3. 每个 feature 改为 `ViewModel → UiState + onAction`，一次性效果（导航、提示、选择图片）走单独通道。
4. 导航加登录守卫、门店作用域和带参路由（结账携带 orderId）。
5. 补金额计算、同规格合并、库存上限、送厨状态不回退的单元测试。

## 4 第二轮：按评审改造架构与组件（2026-11-05）

§2.2 的五项已全部实施，工程结构与约定见 [bak/pos-android/README.md](../../bak/pos-android/README.md)。

| 评审问题 | 改造结果 |
| --- | --- |
| 界面直接依赖演示数据 | 新增 `core/model`（纯 Kotlin 实体与 OrderRules）和 `core/data`（Repository 接口 + DemoWorkspace 演示实现）；界面不再 import 演示数据 |
| 全局可变 PosStore | 删除。会话 / 桌台 / 订单 / 显示偏好 / 设备 / 提示分别为独立接口，由 AppContainer 手动注入 |
| Screen 直接改状态 | 点餐、桌台、结账、显示设置均为 `ViewModel → UiState + onAction`；导航结果走 Effect 通道，提示走 MessageBus |
| 无持久化 | 显示偏好与工作台快照写入 DataStore；强杀进程后草稿、送厨状态、桌台状态、当前桌台、皮肤与布局均恢复 |
| 路由无参数 | 类型安全路由，结账携带 tableId |
| 无测试 | 14 个单元测试：加菜合并、库存上限、沽清、草稿改量、状态不回退、A03 金额与原型一致、按桌隔离、开台人数校验、先送厨再结账、清台流转、快照重启恢复 |

组件改为基于 Material 3（Button、FilledIconButton、FilterChip、可选中 Surface、Card、Badge、Dialog、ModalBottomSheet、Switch、HorizontalDivider），统一扁平化：零阴影、零色调提升、去掉渐变分隔，改用 1dp 极淡分隔与色块。桌台卡去掉阴影后，网格改铺轻底，白色空闲卡靠色块区分，不加灰框。

模拟器验证（pos_tablet，2560×1600）：加菜 → 送厨 → 开台 A01 → A01 加菜 → 换回 A03（明细不串）→ 结账 ¥283.50 → A03 转已结账 → 强杀重启后桌台与订单状态保留；换皮肤与布局 L4 重启后保留；手机尺寸布局正常；全程无崩溃。
