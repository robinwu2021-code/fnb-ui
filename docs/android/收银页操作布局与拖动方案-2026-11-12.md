# 收银页操作布局与拖动方案（2026-11-12，已实现第 1–5 步）

> 范围：餐饮点餐页、零售收银页。目标：**分散**和**混合**两种操作模式同时支持、可切换；页面支持**拖动调整**。原型见 `prototypes/static-ui`（分散 / 混合两种已画）。

## 一、核心：一张操作注册表，两种模式都从它摆

现在各页面的按钮是写死在各自位置的。两种模式要并存，先把「有哪些操作」和「放在哪」拆开：

| 字段 | 说明 |
|---|---|
| `id` | 稳定 ID（如 `line.note`、`order.hold`），存偏好用 |
| `scope` | 作用对象：**行**（选中行）/ **整单** / **桌台** / **下一次加购**（×2、查价）/ **收尾**（送厨、收款）/ **设备** |
| `biz` | 餐饮 / 零售 / 共用 |
| `perm` | 所需权限（沿用 `Perm`），无权限显示置灰 |
| `enabled(state)` | 按选中行状态置灰（未送厨不能退菜、无规格「规格」灰） |
| `tier` | 高频 / 低频（低频默认进「更多」） |

两种模式的摆放规则（按 scope 自动摆，不逐个写死）：

| scope | 分散模式（现状） | 混合模式（参考实机） |
|---|---|---|
| 行 | 行上（− / +、点行展开） | 中间竖条（数量步进在最上） |
| 整单 | 账单头按钮行 | 账单头小图标 |
| 桌台 / 低频 | 「更多」 | 竖条底「更多 ›」 |
| 下一次加购 | 扫码框 / 商品区旁 | **不动**（同左） |
| 收尾 | 账单底 | 账单底（不动） |
| 设备 | 页头 | 页头（不动） |

好处：新增一个操作只登记一次，两种模式都有；权限、置灰规则只写一份；单测可以直接测「某 scope 在某模式落在哪」。

## 二、「页面拖动」分三层，都只在「编辑布局」状态下生效

平时收银不响应拖动，避免高峰误拖。进入方式：显示设置 →「编辑布局」，或工作台空白处长按 1 秒（需要「门店设置」权限）。编辑状态顶部一条：**完成 / 恢复默认 / 取消**。

| 层 | 拖什么 | 结果 | 约束 |
|---|---|---|---|
| 1. 分栏宽度 | 菜单 \| 竖条 \| 账单之间的分隔把手 | 改账单宽、竖条宽；菜品格子列数随宽度自动算 | 账单 320–480dp，竖条 64–96dp；双击把手恢复默认 |
| 2. 区块位置 | 账单头、分类栏上的把手 | 账单拖到左 / 右；分类栏拖到上 / 左 / 右 / 下，落点高亮 | 落点只有现有 L1–L6 六种组合，松手即选定其一（不做任意自由摆放） |
| 3. 竖条按钮 | 竖条里的按钮、「更多」里的按钮 | 长按拖动排序；在竖条和「更多」之间拖进拖出 | 只有 scope=行 的操作能进竖条；竖条最多 12 个；数量步进固定在顶，不能拖走 |

分散模式下第 3 层改为：账单头按钮行可排序、可拖进 / 拖出「更多」。

## 三、偏好怎么存

沿用 `DisplayPrefs`（本机 DataStore），新增：

| 字段 | 说明 |
|---|---|
| `actionMode` | `Scatter` / `Hybrid`，**按业态分开**（餐饮一个、零售一个） |
| `layout` | 已有 `OrderLayout` L1–L6，拖动区块后写这里 |
| `billWidth`、`railWidth` | dp，拖动分隔把手后写这里；0 = 默认 |
| `railActions`、`moreActions` | 操作 ID 列表（按业态分开）；未知 ID 忽略，新版本新增的操作按默认位置补上 |

按**设备**保存（收银机和点餐平板常常分工不同）；第二期可加「按员工覆盖」。主副 POS 各自保存，不同步。

## 四、屏幕尺寸

| 宽度 | 处理 |
|---|---|
| ≥ 1200dp（10–13 寸横屏） | 完整支持两种模式和三层拖动 |
| 900–1200dp | 混合模式竖条收窄成图标 + 短字；区块位置只允许账单左 / 右 |
| < 900dp（手机、小屏） | 不出竖条，行操作改为点行弹出操作面板；不支持编辑布局 |

## 五、实施步骤

| 步 | 内容 | 验证 |
|---|---|---|
| 1 | 操作注册表 + 两种模式按 scope 摆放；显示设置加「操作布局：分散 / 混合」 | 单测：每个 scope 在两种模式的落点；模拟器两模式各收一单 |
| 2 | 混合模式：选中行（新加 / 最后扫的默认选中）、数量步进、置灰规则 | 单测：选中行与置灰；模拟器餐饮 / 零售 |
| 3 | 编辑布局状态 + 分栏宽度拖动 | 模拟器拖动、重启后保持 |
| 4 | 区块位置拖动（映射 L1–L6） | 六种落点各试一次 |
| 5 | 竖条 / 「更多」按钮拖动排序与进出 | 单测：只行操作可进竖条、上限、未知 ID；模拟器 |
| 6 | 补参考图有、App 没有的操作：单品打包、全单打包、餐饮临时菜 | 单测 + 模拟器 |

## 六、实现情况（分支 android-action-layout）

| 步 | 状态 | 代码 |
|---|---|---|
| 1 操作登记表 + 分散 / 混合切换 | ✅ | `core/model/ActionLayout.kt`；显示设置 · 布局「点餐页 / 收银页操作布局」（按当前门店业态，各存一份） |
| 2 混合模式竖条、选中行、数量步进、置灰 | ✅ | `feature/common/ActionRail.kt`；餐饮 `DiningRail`（未送厨可改量 / 删 / 备注，已送厨可赠 / 退 / 催 / 上菜）；零售 `RetailRail`（默认选中最后扫的行） |
| 3 拖分栏宽度 | ✅ | `core/designsystem/component/EditHandles.kt` `WidthHandle`；账单 320–480dp，竖条 64–96dp |
| 4 拖区块位置 | ✅ | 账单「✥ 拖到左 / 右」、分类栏「✥ 拖动分类栏」→ L1–L6；同侧冲突时分类自动换到另一侧 |
| 5 竖条 / 「更多」排序与进出 | ✅ | `RailEditor`：长按拖动，拖过分隔线进出「更多」；整单 / 桌台 / 设备操作拖进竖条会弹回并提示 |
| 6 单品打包、全单打包、餐饮临时菜 | 未做 | 需要新增业务数据（打包标记、临时菜），另行排期 |

编辑入口：显示设置 → 布局 →「编辑收银页布局（拖动）」（需「门店设置」权限、宽屏）。编辑时顶部一条「恢复默认 / 取消 / 完成」，改动先进草稿，「完成」才保存到本机。

验证：单测 252 个通过（新增 `ActionLayoutTest` 6 个）；模拟器上餐饮、零售两种模式各走一遍，三层拖动各试，重启后布局保持。

## 七、已按默认处理的问题（可再调）

1. 「页面拖动」= 上面三层（已确认）。
2. 编辑布局要「门店设置」权限。
3. 布局按设备保存。
4. 账单左右沿用现有布局设置（默认在右），混合模式不单独改；可拖动换到左。
