# N4 身份与离线授权实施记录

日期：2026-11-11。分支 `android-ui-v3`。对应[实施方案 §6](../architecture/下一阶段实施方案-2026-11-10.md)和[协同方案 §5](../architecture/多POS离线局域网与云端协同方案.md)。

## 范围说明

本机侧已经全部实现：设备密钥、授权验签、期限与会话、撤销、版本防回退、时钟异常、只读降级、授权中心。

还没有生产身份服务。现在用**开发测试签发器**代替云端或激活服务签发授权，它只在调试版受信任。发行版目前没有任何受信签发方，只能处于「本地待认领」。

## 设备身份

- **密钥：** `KeystoreDeviceKeys` 在 Android Keystore 生成 EC P-256 签名密钥，别名 `neargo-device-v1`，私钥不可导出。设备测试验证了导出为 null。
- **指纹：** 设备指纹是公钥 SHA-256 的 base64url。数据首次在本机落盘时绑定这个指纹，存在 `Vault.deviceKeyThumbprint`。
- **复制数据：** 把数据库复制到另一台设备，或者重装后用备份恢复，本机密钥都不同，判为「设备身份不符」，暂停营业写入。不在本机的授权也不能导入。
- **N4 之前的旧数据：** 由第一台加载它的设备绑定。

## 离线授权（`core/identity`）

**格式**
- 授权凭证是 compact JWS。头部固定为 `alg=ES256`、`typ=offline-grant+jws`，带 `kid`。
- 载荷包含：`iss/sub/aud/jti/iat/nbf/exp`、tenantId、storeIds、deviceKeyThumbprint、roles、kind（短期或长期）、policyVersion、authEpoch。

**验签**
- 固定算法和类型。`none` 和其他 typ 一律拒绝。
- 签发方必须是受信根，并且签发方名称和 kid 都要匹配。
- `aud` 必须为 `neargo-pos`。
- 只要内容被篡改，签名就校验失败。

**期限**
- `GrantPolicy` 默认短期 7 天、长期 90 天，可以配置。
- 续期必须由签发方签名，本机不能自行续期。

**状态评估（`OfflineAuthority.evaluate`）**

按以下顺序检查：时钟回拨（相对本机记录过的最大时间，容差 5 分钟）→ 会话过期 → 数据绑定设备 → 验签 → 授权绑定设备 → 撤销清单 → 版本低于已知版本 → 当前时间早于签发时间 → 尚未生效 → 已过期 → 门店不在授权内。

各状态是否允许营业写入：

| 状态 | 营业写入 |
| --- | --- |
| Active、Demo | 允许 |
| PendingClaim（本地待认领） | 由策略开关决定，当前允许 |
| 其余状态 | 暂停 |

**会话：** 本机登录会话最长 12 小时，并且不超过有效授权的到期时间。会话过期时提示条提供「重新登录」。会话过期只是登录过期，与授权过期是两回事。

## 只读降级

- **拦截：** 带事件的营业写入在事务内先评估授权。不可写时直接拒绝，不落盘，提示「…已暂停新营业写入，账本保留可查询与导出…」。
- **保留：** 订单、收款、待同步队列、打印任务都原样保留。
- **仍可进行：** 登录、选店、授权中心操作、模拟打印和补发、备份恢复。
- **审计：** 命令信封带 `authorizationRef`（授权编号）和 `policyVersion`，随事件保存作为审计证据。它们不参与幂等摘要。

## 授权中心与提示条

**入口：** 页头下方的提示条，或系统管理 → 设备与系统 → 授权中心。

**页面内容：**
- 当前状态、原因、营业写入是否允许、本次登录有效期。
- 授权的类型、签发方（开发签发标注「非生产」）、有效期、剩余时间、角色、门店、版本。
- 设备 ID 与指纹、策略说明。

**操作：**
- **导入激活包：** 校验签名、设备、撤销、版本、期限。
- **开发签发：** 短期 7 天或长期 90 天，仅调试版提供。
- **撤销本机授权：** 模拟收到云端撤销清单。
- **主管确认校时：** 只在时钟异常时出现，需要主管账号和密码。

**提示条：** 不可写时显示红色并说明原因。本地待认领时显示一行灰色说明。

**授权日志：** 导入、签发、撤销、校时都记入 `Vault.authLog`，不保存凭证内容。

## 信任根

`TrustAnchors` 中生产根目前为空。调试版额外信任本机开发签发器，env 标为 dev。开发签发器的私钥存在应用私有目录，是明确的测试材料，不冒充生产信任根。

## 待确认与限制

- **待认领营业：** 方案默认只提供演示和配置能力，正式营业需要明确批准。为了不改变现有本机注册的体验，暂时允许营业写入并标注「待认领」，需要门店或产品确认。开关是 `GrantPolicy.PENDING_CLAIM_ALLOWS_BUSINESS`。
- **撤销时效：** 断网时无法即时收到撤销，最长离线期限就是最长暴露窗口。目前只有本机撤销清单，联网下发要到 N8。
- **时钟检测：**
  - 只能发现明显的回拨，对比的是本机记录过的最大时间和授权签发时间。
  - 没有可信时间源时，无法绝对防止回拨；单调时钟锚点也还没实现。
  - 主管校时之后，如果授权签发时间仍然晚于当前时间，状态继续判为异常，需要导入按正确时间签发的新授权。
- **员工口令：** 仍是加盐 SHA-256，不是生产口令方案。体验主管账号是公开的。这两项都不能作为生产身份系统。
- **角色：** 授权里的 roles 目前只展示，还没有按角色限制具体操作，例如收银员不能做主管授权。
- **局域网委托：** 主机给副机签发子凭证的委托链属于 N5。

## 验证

- **单元测试：** 117 项通过，新增以下 11 项。
  - `OfflineAuthTest`，共 5 项：篡改、none 算法、其他 typ、陌生签发方、发行版无信任根；7 天和 90 天的边界；撤销、版本、门店、设备绑定；时钟回拨和尚未生效；会话上限和待认领。
  - `AuthWorkspaceTest`，共 6 项：
    - 待认领到开发签发，信封带授权引用。
    - 到期后只读、账本不变、仍可登录，续期后恢复。
    - 会话不超过 12 小时，会话过期与授权过期分开。
    - 数据复制到另一台设备后不可写，也不能导入他机授权。
    - 撤销、版本防回退、时钟异常校时后导入新授权恢复。
    - 发行版没有开发签发。
- **设备测试：** 20 项通过。新增 `KeystoreIdentityTest`：Keystore 密钥稳定，验签通过，私钥不可导出，授权绑定指纹。
- **模拟器：**
  - 现有账号启动后显示待认领提示条。
  - 开发签发短期授权后状态为有效，签发方标注「非生产」，会话到 12 小时后。
  - 撤销后出现红色提示条，点菜被拒绝，原账单不变。
  - 签发长期 90 天授权后恢复加菜。
  - 设备库里的事件信封带有授权编号和策略版本。
  - 英文界面已检查。全程没有崩溃。
