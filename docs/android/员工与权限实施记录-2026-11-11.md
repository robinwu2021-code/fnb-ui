# 员工与权限实施记录

日期：2026-11-11。分支 `android-ui-v3`。补齐[日常运营功能清单](日常运营功能清单-2026-11-11.md)里本轮暂缓的「员工账号与角色权限」。

## 模型

**员工** 包括姓名（门店内唯一，1–12 字）、角色、PIN 和启用状态。
- PIN 为 4–6 位数字，加盐哈希后存在门店数据里。
- PIN 不进入事件载荷。

**角色与权限**

| 权限 | 店长 | 主管 | 收银 | 服务员 |
| --- | --- | --- | --- | --- |
| 开台、点餐、送厨、出菜 | ✓ | ✓ | ✓ | ✓ |
| 结账收款 | ✓ | ✓ | ✓ | — |
| 退菜、赠送、折扣授权 | ✓ | ✓ | — | — |
| 会员建档、会员充值 | ✓ | ✓ | ✓ | — |
| 交班 | ✓ | ✓ | ✓ | — |
| 日结、查看报表 | ✓ | ✓ | — | — |
| 门店、菜品、活动、打印设置 | ✓ | ✓ | — | — |
| 员工与权限、设备与系统 | ✓ | — | — | — |

## 规则

- **兼容：** 门店还没有任何员工时，门店账号按店长处理，原有流程不变。
- **启用员工模式：** 第一位员工必须是店长，创建后当前设备自动以这位店长上岗。之后必须始终保留至少一名启用的店长。
- **上岗：**
  - 员工模式下，每台设备都要用员工 PIN 上岗。
  - 页头的锁屏图标用来换人。
  - 换门店、退出登录时，当班员工会被清空。
  - PIN 连续错 5 次，锁定 1 分钟。
- **数据层校验：**
  - **按事件类型校验：** 每次带事件的写入都按事件类型（`StaffRules.permFor`）校验当班员工的权限，无权限时拒绝，不落盘。
  - **其他写入：** 打印机配置、打印核对这类不带事件的写入，也单独做了校验。
  - **副机：** 副 POS 发来的命令，按副机传来的当班员工 ID 在主机上校验。
- **主管授权：** 退菜、赠送、折扣可以用主管或店长的姓名加 PIN 授权，原有的主管账号授权仍然有效。审计记录里同时保存操作人和授权人。
- **审计：** 事件信封的 actorId 记为当班员工 ID。会员流水、退菜赠送审计、打印核对的操作人，记为员工姓名。
- **界面：**
  - **入口隐藏：** 没有相应权限时，页头的报表和交班图标会隐藏，服务员也进不了系统管理。
  - **自动跳转：** 换人后，如果当前页面超出新员工的权限，会退回桌台页。
  - **员工管理页：** 员工列表、新建和编辑（角色、重置 PIN、启用或停用），并附角色权限对照表。

## 验证

- **单元测试：** 新增 `StaffPermissionTest` 共 6 项，覆盖：
  - 没有员工时保持全部权限。
  - 首位员工必须是店长并自动上岗；事件里不含 PIN；不能停用唯一的店长。
  - 各角色的放行和拒绝：服务员、收银、主管。
  - PIN 锁定、停用、重置。
  - 主管 PIN 授权与审计字段。
  - 换门店时清空当班员工。

  全部 143 项通过。
- **模拟器（主 POS）：**
  - 新建店长 Boss（自动上岗）、收银 Li、服务员 Wang。
  - 锁屏后服务员输错 PIN 被拒，输对后上岗；页头的报表和交班入口隐藏，进不了系统管理。
  - 服务员结账时提示「Wang（服务员）没有「结账收款」权限」。
  - 换收银员 Li 上岗后结账成功，事件的 actorId 为 Li 的员工 ID。
  - 员工事件里没有 PIN 的盐和哈希。
  - 全程没有崩溃。

## 限制

- **PIN 存储：** PIN 是本机的加盐 SHA-256，不是生产级的口令方案。员工数据会随门店快照同步到副 POS，副机才能在本机校验 PIN。
- **设置类入口：** 「设备与系统」中的主副 POS、授权、备份，目前只在界面上不允许服务员进入，数据层没有逐项校验。
- **组织与云端：** 没有跨门店员工和云端账号体系，也没有考勤或排班。
