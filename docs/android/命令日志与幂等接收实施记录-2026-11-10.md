# 命令日志与幂等接收内核

日期：2026-11-10。基于[同步契约](../architecture/同步节点与事件契约.md)。这是本地协议基础，尚未替换页面订单仓库，也没有开放网络接口。

## 实现

业务数据库从v1升级为v2，仅新增三张表，保留原快照及队列表：

| 表 | 职责 |
| --- | --- |
| command_aggregates | 门店/聚合ID、版本及处理器生成的状态 |
| command_inbox | 门店+设备+命令编号唯一，保存请求摘要和原回执 |
| command_events | 唯一事件编号、聚合版本、事件内容、递增读取序号和远端确认标记 |

`CommandJournal.execute(command, reducer)`在同一SQLite事务内检查Inbox、校验期望版本、执行纯计算处理器、提交聚合、事件和回执。重复同内容命令返回原回执，不再执行处理器；同编号不同内容拒绝。版本冲突时不产生任何新状态或事件。

`pending(storeId, limit)`按序读取未确认事件，单批1–500条。`ack(storeId, eventId)`仅在调用方已取得远端持久确认后标记，重复确认无副作用；跨门店确认无效。确认后保留事件及Inbox供重放查询，不自动触发打印或收款。

请求摘要包含当前命令契约所有字段，使用明确UTF-8编码及SHA-256；这是去重校验，不是身份签名。JSON payload字符串按精确内容比较，客户端重试必须保存并复用原命令。

## 接入边界与后续任务

当前内核只在设备测试中调用，页面仍使用LocalWorkspace。不得把两套聚合状态当作已自动同步；正式接入时须将具体领域操作完整迁移到同一命令事务，避免先改页面快照、再补写事件的双写。

下一步实现开台/加菜等具体命令处理器及页面适配，补齐tenant、员工、epoch、授权引用、关联事件和协议版本；随后接入经过认证的主副POS通道。身份、主机权限与epoch必须在可信服务层校验，不能直接把此内核暴露到LAN。

reducer只允许纯计算，禁止在事务内做网络、出纸或收款副作用；远端ACK验证、退避重试、日志保留和清理策略仍待同步服务实现。现有模拟同步引擎不会自动确认这张新事件表。
