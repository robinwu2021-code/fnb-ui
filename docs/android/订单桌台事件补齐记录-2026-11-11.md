# N1-02 订单与桌台事件补齐记录

日期：2026-11-11。分支 `android-ui-v3`。范围以 [Repository写入覆盖表](Repository写入覆盖表-2026-11-10.md) 中标为「N1-02订单桌台」的 12 个入口为准。

## 新增事件

| 入口 | 事件类型 | 载荷附加 |
| --- | --- | --- |
| `startCleaning` / `finishCleaning` | TableCleaningStarted / TableCleaningFinished | — |
| `setPosition` | TablePositionChanged | — |
| `clearNew` | OrderDraftCleared | — |
| `setLineNote` | DishNoteChanged | `changedLines` |
| `setOrderNote` | OrderNoteChanged | — |
| `advance` | DishRushed / DishServed | `changedLines` |
| `setMember` | OrderMemberChanged | — |
| `setBenefits` | OrderBenefitsChanged | — |
| `createReservation` / `cancelReservation` | ReservationCreated / ReservationCancelled | `reservation` |
| `checkInReservation` | ReservationCheckedIn | `reservation`（状态 Arrived） |

载荷沿用 `BusinessEventPayload` 兼容 v1：新增两个可选顶层字段 `reservation` 和 `changedLines`。为空时和 `payment`、`audit` 一样省略，旧事件的解析不受影响。

## 行为变化

- **预订到店：** 不再调用 `openTable`，改为单事务开台并只把该条预订标为到店，产生独立事件。直接开台仍用 TableOpened，并把该桌所有待到店预订标为到店，与原逻辑一致。
- **取消与到店的桌号：** 事务外先查预订所在桌，事务内再次校验预订仍待到店且桌号没变。
- **无变化不写事件：** 改备注为相同内容、已上菜再上菜、无新菜时清空新菜，都不写快照也不写事件。订单规则返回的订单与原订单相同时，不再递增序号。
- **无返回值入口：** `clearNew`、`advance`、`setMember` 新增「未在用餐」校验。业务拒绝时抛出 `WorkspaceRejectedException`，由页面的 `launchStorage` 显示原因，不会让应用崩溃，也不会显示成功提示。保存失败仍抛出 `WorkspaceWriteException`。

## 验证

- **单元测试：** 新增 `OrderTableEventsTest`，共 5 项。覆盖成功事件顺序、拒绝无事件、无变化无事件、载荷字段，以及写入失败后内存状态不变。全部 79 项通过。
- **设备测试：** `PageCommandTest` 新增预订到店回滚测试，用 SQLite 触发器让事件写入失败，确认快照和内存都回滚，重试后成功。13 项设备测试通过。
- **模拟器：** 在 `pos_tablet` 上点了催菜、上菜、会员、进入清台、清台完成、预订到店。导出设备库后，`command_events` 里依次出现对应的 6 个事件，没有崩溃。

## 仍未覆盖

- 事件仍使用过渡协议：`local-page` 设备号、`page-order-stream` 聚合。信封和聚合改造在 N2。
- 会员和优惠事件只记录本机演示状态，不代表资产已经核验。
- 催菜和上菜是本地操作，不是 KDS 回执。
