# 餐饮 POS 多规格 SKU 与商品图片规范 v3.4

本次在 v3.3 商品编辑器基础上扩展，沿用紧凑分区、共享字体/皮肤/间距及平面按钮。入口：系统管理 → 商品管理 → 商品资料 → 新建/编辑。

## 编辑器结构

保留基本资料、图片、基础售价、规格组、库存、餐牌关联，增加通栏 SKU 表格。规格组选项使用紧凑复选，价格和库存按列对齐；组合表内部滚动，弹层底部固定取消/保存，窄屏允许表格内部横向滚动。

## 多规格与 SKU

- 在“规格组”维护 `选项:加价`，例如 `标准:0,大份:20`；同组名称不可重复，加价非负且最多两位小数。
- 商品可关联多组规格，自动生成笛卡尔组合，最多 100 个 SKU；超限提示并禁止保存。
- 新组合售价 = 基础售价 + 各选项加价。新组合库存默认取启用规格前的可售份数，逐个 SKU 独立填写。
- 调整基础售价或规格选择时，仍存在的组合保留手动价格和库存；未手动调整的价格随基础售价重新计算。取消某组合后其草稿值不再保留。
- 有 SKU 时商品库存只读，显示各 SKU 库存合计；无 SKU 时直接填写商品库存。库存必须为非负整数，0 表示该 SKU 沽清。SKU 售价范围为 0–99999 元、最多两位小数。
- SKU 标识由排序后的规格组 ID 和选项名称生成。生产系统应改用稳定选项 ID，避免改名影响关联。
- 保存后商品显示最低 SKU 售价；点餐必须选择一个有库存的组合，按所选 SKU 独立单价加入购物车，订单行保留组合及价格快照。
- 同菜品不同 SKU 分行；同 SKU 同备注的未送出菜品可合并。加菜/增量校验 SKU 库存，不能用其他 SKU 的余量绕过限制。库存盘点按 SKU 分别调整并回算总量。

## 图片上传与预览

支持本地 JPG、PNG、WebP，单张 ≤5 MB；读取并解码成功后即时预览，错误在图片分区显示。保留 HTTP/HTTPS 图片地址作为替代输入，两种方式互斥。移除后恢复占位，保存商品后应用；取消不修改原商品。

异步读取中阻止保存；替换、移除或关闭编辑器会使旧读取结果失效。当前上传仅将图片读取为页面会话内 Data URL，不发送至服务器；刷新恢复演示数据。正式开发须接入鉴权上传、对象存储、服务端类型/大小校验、缩略图和资源生命周期；裁剪/压缩尚未实现。

## 共享实现

| 文件 | 职责 |
| --- | --- |
| `sku.mjs` | 解析规格、生成稳定组合、价格与库存校验 |
| `components/sku-editor.mjs` | SKU 表格与表单读取 |
| `components/product-media.mjs` | 上传、解码预览、替换、移除与读取竞态控制 |
| `components/management.mjs` | 共享商品分区表单 |
| `workbenches/admin.mjs` | 草稿变更、保存、餐牌关联、SKU 盘点 |
| `model.mjs` / `workbenches/order.mjs` | SKU 选择、订单快照与库存限制 |

[组件展示页](http://127.0.0.1:8765/v3/components.html) 的“管理表单”直接复用同一编辑器，展示份量 × 温度四种组合，支持切换规格、修改 SKU 和图片预览；展示保存仅提示演示。

## 验证与原型边界

执行 `node --test prototypes/v3/*.test.mjs`，18 项通过，覆盖组合生成、稳定匹配、手动值保留、组合上限/无效金额、SKU 库存隔离和加菜限制。浏览器验证四组合独立价格/库存、总量回算、基础价变更、图片读取预览/移除、商品保存与餐牌关联。

库存校验限当前单桌订单演示，未实现跨桌全局预占、并发扣减、支付/退菜回补或持久化。规格组和选项目前不支持改名编辑。生产开发应采用商品 ID、规格组 ID、选项 ID、SKU ID 分层模型，以服务端库存及金额为准。中英文界面标签已提供，规格选项名称按配置原文展示。
