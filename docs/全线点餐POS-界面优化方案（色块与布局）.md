# 全线点餐 POS · 界面优化方案：色块代替线框，订单、点餐、结账重排

> 状态：已实施（2026-10-23，按第六节三条推荐选项），结果见文末「七、实施结果」
> 对象：`prototypes/bapp/pos-ui.html`、`pos-components.html`、`proto.css`，以及 [UI 组件方案](全线点餐POS-UI组件方案.md) v8。
> 来源：本轮六条意见——① 减少灰色边框；② 结单区价格区和上方的边界要清楚，用色块不用线；③ 订单页支持列表 / 块两种排列，能按各种状态筛选；④ 点餐「左右」排布每块太宽，要排三列以上；⑤ 优化结账页的交互和排列，减少灰色线框；⑥ 键盘按键用色块。
> 方法：在原型里实测默认设置（白卡细线 · 紧凑 · 标准形状 · 1280×800）下每个工作台的描边、分隔线和关键尺寸。

## 一、结论

六条意见其实是两个问题：

1. **分层靠线，不靠面。** 默认面感「白卡细线」为了减少大块灰色，把卡内块都改成「白底 + 1px 灰描边」，金额区也改成「透明底 + 一条顶线」。结果是白面板里套白卡片，层次全靠细线，一屏十几到二十几个灰框（①②⑤⑥）。
2. **布局没有跟着任务走。** 点餐左右排布、订单页、结账页沿用了最早的网格：卡片太宽、只有列表、收款的输入区和确认按钮离得远（③④⑤）。

方案：
- **改用「浅色块」分层：** 新增一档很浅的块色，白面板里的卡片、按键、分组一律用块色，不加描边。分隔线只留在列表行之间这一种用法。
- **结单区底部做成整块色块：** 合计、优惠、应收收进一块有底色的区域，和上面的菜品列表靠底色分开。
- **订单页：** 加「列表 / 卡片」切换和状态筛选条。
- **点餐左右排布：** 卡片收窄到三到四列。
- **结账页：** 改成「左支付方式 · 中收款 · 右明细」三栏，键盘和确认收款放在一起。

## 二、问题梳理（实测）

### 1. 灰色边框和分隔线（①⑤⑥）

默认「白卡细线」面感下，各工作台一屏里的描边（1px 内描边）和分隔线：

| 工作台 | 描边 / 线 | 来自 |
|---|---|---|
| 结账 | 26 | 支付方式 5 块、键盘 14 键、订单行分隔 5 条、金额区顶线、应收顶线 |
| 桌台 | 19 | 桌台卡 8 块、统计块、分组列表外框和 3 条行线、订单行 5 条、危险按钮 1 |
| 点餐 | 10 | 菜品卡、待下单组外框、订单行 4 条、金额区顶线、会员行底线、应收顶线 |
| 班次 | 7 | 统计块外框、分组列表外框和 4 条行线、金额区顶线 |

| 问题 | 说明 |
|---|---|
| 白套白，只能靠线 | 面板是白的，卡内块也是白的，只能给每块加 1px `--pc-edge` 描边才分得出来 |
| 线有四种用法 | 卡片外框、列表行线、区块分隔（金额区顶线、应收顶线）、行内分隔（会员行底线），粗细颜色都一样，看不出层级 |
| 键盘是白键 + 描边 | 14 个白色按键，每个一圈灰线（101 × 52）。按键和功能键（退格、清空）、数字键长得一样 |
| 「灰块」面感又太灰 | 另一档「灰块」把卡内块铺成 `faint`（#EDEFF2），面板里大面积中灰，正是上一轮要去掉的 |

### 2. 结单区价格区（②）

| 现状 | 问题 |
|---|---|
| 「白卡细线」下，金额区 `dn-total` 是透明底，只有一条 1px 顶线 | 菜品列表滚动时，列表最后一行和金额区之间只隔一条细线，分不清哪里是列表、哪里是合计 |
| 金额区里又有会员行底线、应收顶线 | 一个区域里三条线，层级更乱 |
| 合计区 336 × 166，加上操作按钮约占结单区高度的 1/3 | 高度没问题，问题在边界 |

### 3. 订单页（③）

| 现状 | 问题 |
|---|---|
| 只有列表一种排列（6 行、行高 44） | 高峰期要扫一眼看到哪些桌待结账、哪些单挂起，列表信息密但不直观 |
| 筛选在左侧导航里：「进行中 / 挂起 / 已结账」和「堂食 / 外带 / 外卖」 | 状态只有 3 种，而业务状态字典里订单有 9 种、外卖有 9 种；状态和渠道不能组合；没有「全部」 |
| 状态标签在行尾 | 列表里状态是最重要的信息，却在最右边 |

### 4. 点餐「左右」排布（④）

| 现状 | 问题 |
|---|---|
| 内容区宽 760，左右卡最小宽 250 → 只排两列，每张 376 × 104 | 方图只有 88，右边 270 宽放菜名、价格、库存，大半是空白；一屏只能看到 8 道菜（上下排布一屏 8 道、无图 12 道） |

### 5. 结账页（⑤）

| 现状 | 问题 |
|---|---|
| 上方 3 × 2 支付方式（每块 285 × 80，带描边），占 168 高 | 最常用的只有 2–3 种，却占了整整一排大卡；收款主要操作被挤到下半屏 |
| 中间左「实收 + 找零 + 快捷金额」，右 4 列键盘 | 「应收」只在右侧明细最底下和确认按钮里出现，收银员要左右来回看 |
| 「确认收款」是 872 宽的通栏按钮，在最底部 | 离键盘远；输完金额手要从键盘挪到屏幕最下面 |
| 扫码收款时中间只有一个转圈 | 没有「已收 / 待收」、没有扫码枪状态、没有「取消」 |
| 组合支付没有分账视图 | 「组合支付」点了以后和现金一样 |

### 6. 键盘（⑥）

见第 1 节：白键 + 描边，功能键和数字键同色，确认键不在键盘上。

## 三、方案

### 3.1 分层原则：「面分层，线分行」

| 层 | 用什么区分 | 令牌 |
|---|---|---|
| 画布 → 面板 | 画布浅灰、面板白 | `--c-canvas`（gray-50 #F4F6F9）/ `--c-surface`（白） |
| 面板 → 卡内块（菜品卡、桌台卡、支付方式、按键、分组、统计块） | **块色**，不加描边 | 新增 `--c-tile`：介于白和 faint 之间（≈ #F5F6F8，取 gray-50 或在 50 和 100 之间新增一档 75） |
| 块 → 选中 | 主色 tint + 主色字（不变） | `--c-primary-tint` |
| 块 → 悬停 / 按下 | 深一档 | `--c-tile-hover`（gray-100）/ `--c-tile-pressed`（gray-150） |
| 列表里的行与行 | **唯一保留的线**：1px `--c-line`，只在行间，不画外框 | `--c-line` |
| 区块与区块 | 间距 16，或换底色（如结单区合计块） | — |

由此的规则：
- **不再给块加描边。** 删除「白卡细线」里所有卡内块的 `inset 0 0 0 1px` 描边（菜品卡、桌台卡、支付方式、按键、待下单组、统计块、分组列表外框）。
- **一个区域里最多一种线。** 金额区的顶线、会员行底线、应收顶线都去掉，改为间距或底色。
- **描边只留给两种语义：** 当前选中桌的 2px 墨色内圈；危险按钮的描边（组件方案规定，不变）。
- **面感从两档改为两档新的：**「色块」（新默认，块色 `--c-tile`，很浅，整屏灰面积小）和「灰块」（保留，块色 `faint`，对比更强、适合强光环境）。「白卡细线」退役。

预计效果：默认面感下，结账页的描边和线从 26 降到 5（只剩订单行分隔），桌台页从 19 降到 9，点餐页从 10 降到 4。

### 3.2 结单区：合计做成整块色块（②）

```
┌ 结单区（白面板）──────────────┐
│ A03  进行中               ⋯  │  头
│ 4 人 · 48 分钟 · 堂食 · #1024 │
│ [备注条：少辣 · 赶时间]        │
│ 待下单 · 5 份           清空  │  可滚动主体
│ ┌ 待下单组（块色）──────────┐ │
│ └──────────────────────────┘ │
│ 已下单 · 4 道 · 上菜 1/4 批量 │
│ 行 / 行 / 行（行间细线）       │
├──────────────────────────────┤  ← 由底色切开，不用线
│▓ 会员 · 金卡  138****6621  券 ▓│  合计块：整块底色，贴满面板宽，
│▓ 小计 / 服务费 / 优惠          ▓│  上方左右两角圆，
│▓ 应收            ¥248.00      ▓│  内部只用间距分组
│▓ [挂单] [送厨·5] [   结账   ]  ▓│  操作按钮也在块里
└──────────────────────────────┘
```

| 项 | 做法 |
|---|---|
| 底色 | 合计块用 `--c-canvas`（比面板深一档、比块色再深一点点），贴满面板宽（去掉面板 `.ft` 的左右内边距，块自带 12 内边距），上沿两角跟随卡内圆角 `--rt`，下沿跟随面板圆角 |
| 内部分组 | 会员行、明细、应收三组之间用 8 / 12 间距，不画线；应收一行字号 32，左右两端对齐 |
| 按钮 | 挂单、送厨、结账放在合计块内的最后一行，按钮本身是色块，在浅底上清楚 |
| 和列表的边界 | 主体滚到底时，最后一行和合计块之间就是底色变化；主体可滚时，合计块顶部加 8px 的同色渐隐，提示上面还有内容（不加阴影） |
| 批量模式 | 合计块保留，最后一行换成催菜 · 转菜 · 退菜（已实现的逻辑不变） |
| 其他用到 `dn-total` 的地方 | 桌台详情、结账明细、班次钱箱同样改成整块底色，同一组件 |

### 3.3 订单页：列表 / 卡片两种排列 + 状态筛选（③）

**筛选**：左侧导航改为「时段」（今天、本班、昨天、近 7 天），状态和渠道移到面板头部的工具栏，三排：

| 排 | 内容 | 组件 |
|---|---|---|
| 1 | 搜索（单号 / 桌号 / 手机尾号）· 右侧「列表 / 卡片」分段 | `sh-toolbar` · `sh-search` · `sh-seg` |
| 2 | 状态筛选：全部 · 进行中 · 待结账 · 部分支付 · 挂起 · 已结账 · 已反结账 · 已取消，每项带计数和状态图标；单选 | `sh-filter` + `st-ic` + 计数 `em` |
| 3 | 渠道：全部 · 堂食 · 外带 · 外卖（外卖选中后，状态排换成外卖状态：待接单 · 已接单 · 待取餐 · 配送中 · 已送达 · 已拒单 · 退款中 · 接单超时）；单选 | `sh-seg` |

- 状态取 `pos-states.js` 的 `order` / `delivery` 实体，名字、图标、颜色和全站一致。
- 筛选后列表头写「共 N 单 · ¥合计」；没有结果时用空状态（「没有挂起的订单」）。
- 需要「待处理」数量提醒的状态（待结账、部分支付、待接单、接单超时）计数用主色或危险色，其余用次要色。

**列表排列**（现有 `dn-orow`，调整）：
- 列顺序改为：状态（`st-tag`，第一列）· 单号 · 桌号 / 渠道 · 件数与时间 · 金额（右对齐）。
- 行间细线保留（这是唯一保留的线），当前行 tint。

**卡片排列**（新增 `dn-ocard`）：

```
┌ 块色卡片 ─────────────────┐
│ #1024            [进行中] │  单号 18 号 · 状态 st-tag
│ A03 · 堂食 · 4 人          │
│ 6 件 · 11:42 · 上菜 3/6    │
│ ¥268.00                   │  金额 22 号，压底
└───────────────────────────┘
```

- 宽 ≥ 200，内容区 760 排 3 列（导航在上时 4 列）；块色无描边，当前单 tint。
- 待结账、部分支付、接单超时这类要处理的单，卡片左上角加 4px 状态色竖条（色块，不是描边）。
- 外卖卡片把桌号换成平台 + 平台单号，并显示预计送达时间。

### 3.4 点餐「左右」排布：三列以上（④）

| 项 | 现状 | 改为 |
|---|---|---|
| 最小列宽 | 250 | 200 → 内容区 760 排 3 列（每张 ≈ 245），导航在上时（≈ 900）排 4 列 |
| 方图 | 88 | 72（卡高 ≈ 88），菜名 15 号两行、第二语言名一行、价格和库存压底 |
| 无图的菜 | 方块写前两个字 | 不变（72 方块写前两个字，22 号） |
| 一屏菜品数 | 8 道 | 18–21 道 |

同时，「上下」排布最小列宽从 150 提到 160，避免英文名截断太多；无图模式不变。

### 3.5 结账页：左支付方式 · 中收款 · 右明细（⑤⑥）

```
┌ 支付方式 ┐┌ 收款 ─────────────────────────┐┌ 明细 ────────┐
│ 微信   ✓ ││ 应收 ¥248.00   已收 ¥0 待收 ¥248│ A03 · 4 人   │
│ 支付宝   ││ ─ 实收 ─────────────── ¥300.00 │ 订单行……     │
│ 现金   ● ││ 找零 ¥52.00                    │（可折叠）    │
│ 银行卡   ││ [¥248] [¥250] [¥300] [¥500]    │              │
│ 会员储值 ││ ┌7┐┌8┐┌9┐┌⌫┐                  │ 合计块（色块）│
│ 组合支付 ││ ┌4┐┌5┐┌6┐┌清空┐               │ 小计 / 优惠   │
│          ││ ┌1┐┌2┐┌3┐┌      ┐            │ 应收 ¥248.00 │
│ 离线时扫码││ ┌00┐┌0┐┌.┐│确认收款│           │              │
│ 两项置灰 ││              └ ¥248 ┘          │              │
└──────────┘└────────────────────────────────┘└──────────────┘
```

| 区 | 做法 |
|---|---|
| 支付方式（左，宽 ≈ 160） | 竖排 6 项，每项 56 高：品牌色小方块 + 名称 + 一行说明（余额、离线不可用）。块色无描边，选中 tint + 主色字 + 右侧勾。用 `dn-pay--row` 变体，不再是 3 × 2 大卡 |
| 收款头（中上） | 一行三个数：**应收**（32 号）· 已收 · 待收；组合支付时下面出分账条（已付的方式和金额，每条可撤销） |
| 现金 | 实收大字（输入框改为块色、无描边）、找零紧跟其下（不够时换成「还差」危险字）；快捷金额一排胶囊（应收、整十、整百、500）；键盘见下 |
| 扫码（微信、支付宝） | 中间显示「请顾客出示付款码」+ 扫码枪状态（已连接 / 未连接）+ 等待转圈；底部「取消收款」（muted）。失败走已做好的「支付失败」结果弹窗 |
| 银行卡、会员储值 | 银行卡：「请在刷卡机上操作」+ 刷卡机状态；会员储值：会员卡信息 + 余额 + 需验证时的手机号输入 |
| 确认收款 | 并入键盘：键盘第 4 列下面两格合并成「确认收款 ¥248.00」实心主色键（高 2 × 52 + 间距）。现金不够时这个键变 `--off` 并写「还差 ¥23.50」。这是这一屏唯一的实心按钮 |
| 明细（右，360） | 订单行默认折叠成「6 道菜 · 展开」，展开后可滚动；底部用和结单区一样的合计块（色块），写小计、会员价、服务费、抹零、应收 |

**键盘（⑥）**

| 键 | 现状 | 改为 |
|---|---|---|
| 数字键 0–9、00、. | 白底 + 灰描边 | 块色 `--c-tile`，22 号 500，无描边；按下深一档 |
| 功能键（退格、清空、取消） | 同数字键，只是字小、次要色 | 深一档的块色 `--c-faint`（gray-100），图标或字用墨色，一眼和数字键分开 |
| 确认键 | 不在键盘里 | 主色实心，合并两格（见上） |
| 授权键盘（3 列） | 同上 | 同样的块色规则；没有确认键（输满 4 位自动校验） |
| 尺寸 | 101 × 52 | 不变（大号控件高，紧凑 52 / 标准 56），间距 8 |

### 3.6 其他同类问题（顺带）

| 位置 | 改法 |
|---|---|
| 桌台卡 | 空闲桌块色，用餐中主色 tint、待结账警告 tint（不变）；去掉描边；当前桌保留 2px 墨色内圈 |
| 统计块 `sh-stat` | 块色，无描边，数字之间不加竖线 |
| 分组列表 `sh-cells` | 放在白面板里时用块色（即现在的 `--sunk`），去外框，行间细线保留 |
| 待下单组 `dn-group` | 块色，无描边 |
| 侧滑面板里的分组列表 | 同上 |
| 设置页表格 `sh-table` | 行间细线保留，表头下不加粗线 |

## 四、改动清单

| 类别 | 改动 |
|---|---|
| 令牌（`tools/gen-colors.py` → `pos-colors.css`） | 新增 `--c-tile` / `--c-tile-hover` / `--c-tile-pressed`（gray-50 与 100 之间，生成器里加一档 75，并补对比检查：块色上次要字 ≥ 4.5:1）；兼容层加 `--sh-tile` |

## 六、需要确认的三点

1. **「白卡细线」面感退役，默认改为「色块」**（推荐）。另一个选择是保留三档，把「色块」加成第三档、设为默认；代价是每个组件多维护一套面感规则。
2. **结账页确认键并入键盘**（推荐）。另一个选择是保留底部通栏「确认收款」，但移到键盘正下方、宽度与键盘一致。
