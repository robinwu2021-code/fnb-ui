## 2. 3.0的结构

四层结构：**基础令牌 → 通用组件 → 餐饮组件 → 页面模板**。设置通过同一解析器生成令牌；组件库与原型使用相同组件、状态和令牌，不各画一套样张。

命名沿用`sh-*`通用、`dn-*`餐饮，设计名称保留`Dining*`；已有名称能复用就不另造同义件。例如已点清单由OrderDock组合OrderHeader、OrderLine、AmountSummary、ActionBar，而不是在三个页面复制整块HTML。

统一设置优先级：**触控/可读性与窗口约束 → 用户显式覆盖 → 风格默认 → 产品默认**。皮肤提供颜色、风格提供组件配方、布局提供空间位置，三者相互独立。

## 3. 设置体系

| 设置组 | 选项 | 生效边界 |
| --- | --- | --- |
| 皮肤 | 松绿+原7套：墨黑、虹选红、经典蓝、微信绿、青碧、琥珀、紫 | 主操作/选择/数量等角色色；不能改业务状态含义 |

| 密度 | 紧凑/标准/舒展 | 间距与行高下限；不缩字号和触控区 |
| 应用导航 | 顶部/底部 | 工作台入口；系统身份信息仍在顶部 |

| 菜品呈现 | 有图/无图、网格/列表、图片四种方向、3:2/1:1 | 无图时记住图片方向，但暂不显示方向控件 |

### 风格配方

| 风格 | 容器与操作表现 | 与全局规则的关系 |
| --- | --- | --- |
| Quiet默认 | 小圆角白面板，浅主题选中，留白分区 | 本轮确认的视觉基线 |
| 原版适配 | 较紧凑、中性层次、传统资源栏 | 复用旧结构，不恢复44px点击区和灰线 |
| Apple-inspired | 柔和分组、白色分段滑块、圆润动作 | 使用所选Google字体与皮肤，不固定系统蓝 |
| Material-inspired | tonal层次、清晰选择标记、较圆操作 | 使用填色/勾选，不恢复灰色Outlined边界 |
| Uber-inspired | 平直结构、较强字重、明确高对比动作 | 用户选松绿时仍使用松绿，不强制全黑 |
| 白玻璃 | 半透明白面、轻柔影，清晰内容层 | 无灰色描边；需实底回退，不能牺牲文字对比 |

历史Apple/M3/Uber精确外观留在2.0对照页；3.0是统一POS约束下的适配风格。若风格变化只改一个主按钮，不能视为完成。

## 4. 基础：颜色、字体、间距

默认颜色：画布`#F3F5F4`、面板`#FFFFFF`、局部块`#F6F8F7`、操作底栏`#F0F5F2`、正文`#181A1C`、辅助`#5C5E61`、主色`#306F5F`。其他皮肤的选中、文字、按下、焦点由语义角色解析；操作底栏采用中性底或该皮肤的极浅底，不永久绑定绿底。

不画常驻灰色线框。必要浮层采用中性模糊阴影；普通面板靠底色差和间隙区分。焦点保留有色环，选择保留勾/形状，错误保留文字与标记。装饰阴影不能代替输入标签和操作语义。

状态保留9组：待处理、进行中、等待中、完成、预约、暂存、变更、关闭、异常。每组至少有图标+文字；克制配色可降低常态色彩，仍必须保留完整含义。“当前对象”“已点数量”“业务状态”分别表达，不能共用一个实心色块。

字体：Manrope、Inter、Roboto、Noto Sans、IBM Plex Sans、Outfit；中文Noto Sans SC。Outfit预设用于标题/数字，正文配Inter。加载400/500/600/700所需字重，按选择加载；支持离线字体与系统回退。不能沿用旧文档未经复测的字体宽度结论作为3.0验收证据。

| 角色 | 标准 字号/行高 | 大字（默认） | 特大 |
| --- | --- | --- | --- |
| 辅助、状态 | 14/20 | 16/24 | 18/26 |
| 正文、按钮、菜名 | 16/24 | 18/28 | 20/30 |
| 面板标题 | 20/28 | 24/32 | 28/36 |
| 页面标题 | 28/36 | 32/40 | 36/44 |
| 应收/待收金额 | 32/40 | 40/48 | 44/52 |

以上为HTML逻辑px；Android对应sp并考虑系统缩放。紧凑账单金额可使用独立32/38角色，避免直接套40px展示金额占据过多高度。12px仅给非关键编号，不给价格、状态和操作。数字使用等宽特性，金额不可截断。

| 空间 | 紧凑 | 标准 | 舒展 |
| --- | --- | --- | --- |
| 工作区外边距/栏间 | 12 | 20 | 24 |
| 面板内边距 | 16 | 20 | 24 |
| 卡片间距 | 12 | 16 | 20 |
| 区块间距 | 16 | 24 | 32 |

文字/图标小间距4或8，字段间12或16。尺寸均为最小值，内容和字体放大时增高；菜单及账单列数相应减少。按钮点击区至少48×48，主要按钮默认56高，紧凑账单可48高。

## 5. 形状与容器

| 框架档 | 面板/卡片/浮层圆角 |
| --- | --- |
| 直角 | 0/0/8 |
| 利落 | 4/2/8 |
| 轻圆（Quiet默认） | 8/4/12 |
| 柔和 | 16/12/20 |

按钮独立0/4/8/12/胶囊，默认12；输入、键盘、多行选项在胶囊档仍最多12。贴窗口边的浮层只圆露出的角。普通面板elevation=0，菜单/浮层可用轻柔影，白玻璃允许材质层次但需实底回退。

不继续使用“容器必须比按钮更圆”的旧硬规则。本版认可平直区域+柔和按钮；重点是相同角色一致、内外嵌套不出现无意的形状冲突。

## 6. 布局模板与空间分配

W1导航/内容/详情用于桌台、点餐、订单、菜品、会员；W2核对/收款用于结账；W3汇总/实盘用于班次；W4菜单/内容用于设置和报表。导航位置与页面模板分开定义。

L1左分类右详情；L2上分类右详情；L3上分类左详情；L4右分类左详情；L5分类→详情→内容；L6内容→详情→分类。顶部分类只跨内容，不横跨详情。

分类宽96、桌区/订单128、设置160；详情320/380/最大400。断点按应用可用宽：<600单任务，600–959主内容+可展开详情，960–1279条件允许多栏，≥1280完整宽布局。内容不足时改横向分类或详情面板，保留用户偏好，宽度恢复后还原。

菜品支持图上文下、图左文右、图右文左、文上图下及文字卡；布局组件统一处理图片尺寸、双语、标记、价格和库存，不能每个方向复制一份功能较少的卡片。

账单以菜品清单为主体：头64–88、操作区96–112为建议预算；≥480高时清单目标至少55%。当前B方案测量88/118只能作为现状，不视为已达到3.0目标。低高度时折叠次要信息或切全屏，超预算长文保持可读，不能隐藏关键错误。列表独立滚动，底栏固定；顶部固定操作模式也只有一处主操作。

## 8. 关键组件契约

| 组件 | 内容与变体 | 关键约束 |
| --- | --- | --- |
| Button | 主、次、文字、危险；图标、计数、加载 | 一个活动任务一个主操作；危险实心仅最终确认；禁用原因可读 |
| SearchInput | 查询、清空、扫描可选 | 输入法组合输入不丢焦点；编号/中英文搜索能力明确标注 |
| OptionPicker | 单选、多选、必选、加价、不可用 | 多行块状，选择标记+文字；汇总规格和价格 |
| DiningMenuItem | 四向图文/无图/列表；库存、沽清、限时、已点 | 价格和名称来自同一数据；未加载图片有占位；已点≠当前聚焦 |
| DiningTableTile | 空闲、预订、待点餐、用餐、超时、待结账、部分付、待清台、并入、拼桌、停用 | 完整11态；选中独立；金额未加载不伪装0 |
| DiningOrderLine | 待下单/制作/上菜/催菜/退/赠/改价、批量、规格、备注 | 份数、菜名、行额优先；金额右对齐；长文换行，步进器可下移 |
| OrderDock | 简头、菜品分组、费用、金额、动作 | 可折叠快捷菜单；清单占空间优先；切布局不丢单 |
| FeePromotionList | 服务费、活动、会员、券、平台券、人工、抹零 | 保留互斥原因；平台抵扣与门店优惠分开显示 |
| PaymentWorkspace | 账单、方式、现金、组合支付、找零 | 支付中/未知/失败/成功明确；布局不改变交易金额与身份 |
| Dialog/Sheet | 规格、备注、授权、桌台、会员、设备 | 只开一个主模态；长内容可滚，主操作可达；返回保留有效输入 |
| SettingsPanel | 即时预览、偏好保存、恢复 | 各设置可见且真正生效；无效组合有解释，不静默覆盖 |

每个组件登记：ID/名称、职责、数据输入、事件、变体、状态、尺寸、布局适配、语言、可访问性、实现等级与使用页。复杂组件增加最小样例和失败样例。实现等级为“可交互演示”“静态样张”“入口示意”“尚未实现”，不能以按钮存在代替功能完成。

## 10. 组件库3.0与原型3.0的交付设计

## 11. 实施顺序与验收

1. 冻结3.0方案，逐项核对旧组件、设置、页面要素及实现等级。
2. 建立统一设置/令牌解析器，迁移旧存档；先修复皮肤、风格、字体、布局覆盖冲突。
3. 实现通用组件及全状态样张，再实现餐饮组合；组件库先可独立查看。
4. 装配点餐、桌台、结账，补齐中英文和异常状态，保持账单清单优先。
5. 覆盖其余六个模块；完成版本对照、截图及限制清单。

验收采用：所有组件状态覆盖+设置成对组合+关键极端场景；不穷举无意义的全组合。专项覆盖最大字体/长英文/双语/最窄窗、左右图文/上下图文、L1–L6、上下导航/操作区、不同皮肤与风格、刷新恢复设置、切桌不串单。
