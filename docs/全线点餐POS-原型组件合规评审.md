# 全线点餐 POS · UI 原型是否严格使用组件方案（评审）

> 日期：2026-10-23
> 对象：`prototypes/bapp/pos-ui.html`，对照 [UI 组件方案](全线点餐POS-UI组件方案.md)、`pos-components.html`、`proto.css` 的组件段、[色彩体系](全线点餐POS-色彩体系.md)。
> 处理：P0、P1、P2-1、P2-2 已改完（2026-10-23），结果见文末「四、处理结果」；P2-3 维持原样（原型可以接受）。
> 方法：在浏览器里把原型渲染出 93 个画面（5 个工作台 × 6 种浮层、5 个侧滑页签、上下 / 左右与纯文字菜品卡、设置工作台全部 51 项），逐个元素采集：用到的类名、行内样式、计算后的字号 / 字重 / 圆角、实心主按钮个数、危险实心按钮位置、只有图标的按钮是否有无障碍标签、可点元素的高度。另外静态比对 `proto.css` 的段落归属和组件页的覆盖情况。

## 结论

**没有严格使用。** 颜色、圆角、字重都走了令牌，按钮形态和危险操作的规则也守住了；但有四类硬规则没守住，另有一批组件「原型先做了、方案没跟上」，形成平行实现。

| 结论 | 说明 |
|---|---|
| 守住的 | 用到的类名全部有定义；圆角全部来自形状令牌（8 / 10 / 14 / 胶囊，以及由它们派生的 3、6）；字重只有 400 / 500 / 600 / 700；危险实心按钮只出现在确认弹窗里；实心主按钮在不带浮层的画面里都只有一个（浮层打开时是弹窗里的一个加被遮住的一个，可以接受）；色值只出现在皮肤色板和支付品牌图标里（方案允许的例外） |
| 没守住的硬规则 | 11px 字（P0-1）、触控尺寸不足（P0-2）、只有图标的按钮缺无障碍标签（P0-3）、用字符当图标（P0-4） |
| 方案没跟上原型 | 业务状态标签、面板、表格、二级导航、双语名等在原型里是组件级的东西，但组件方案和组件页里没有，或者还是旧写法（P1-1 至 P1-3） |
| 写法不规范 | 大量行内样式代替组件变体；组件样式散在 `proto.css` 后面的补丁里并被反复覆盖（P1-4、P1-5） |

## 一、问题清单

### P0：违反组件方案的硬规则

| # | 问题 | 实测 | 方案怎么规定 | 建议 |

| P0-2 | **可点元素不够大，且没有补热区** | 分段控件每段 32px；订单行步进器 32px（`.dn-oline .side .sh-stepper` 把组件的 36 改成了 32）；「清空」文字链接 17px；会员行 29px | 默认 44；小号 36，并用热区补到 44（方案写了 `.sh-hit`，但全项目没有这个类） | 实现 `.sh-hit`（伪元素扩到 44）；分段和步进器挂上；订单行步进器回到组件规定的 36；「清空」、会员行改成小号按钮或挂热区 |
| P0-3 | **只有图标的按钮缺无障碍标签** | 结单区「⋯ 更多」、挂单「⏸」、侧滑面板「✕ 关闭」 | IconButton 必须有 `aria-label`（组件方案第三节之 4） | `btn()` 支持传 `aria-label`，三处补上 |

## 二、做得好的地方

- **颜色全部走令牌。** 原型里除皮肤色板和支付品牌图标外没有色值；接入色彩体系 v2 后，204 个状态画面在 7 个皮肤下都正确换色。
- **形状全部走令牌。** 出现的圆角都能追溯到框架或按钮令牌，换「形状方案」时整页一起变。
- **按钮层级守住了。** 一屏一个实心主按钮；危险实心只在确认弹窗；soft、muted 用得对。
- **类名没有野生的。** 用到的类全部在样式表里有定义。

## 三、建议的处理顺序

| 顺序 | 内容 | 说明 |
|---|---|---|
| 1 | P0 四项 | 改动小，直接改原型和组件段 |
| 2 | P1-1、P1-3 | 先把 StatusTag、StatusIcon、DataTable、SubNav、Toolbar、BilingualName、区块标题写进组件方案和组件页，让方案追上原型 |
| 3 | P1-2、P1-4 | 定下 Panel 用哪种实现；行内样式改成变体 |
| 4 | P1-5 | 重排 `proto.css`：组件一处定义，原型段只留外壳 |
| 5 | P2 | 删除废弃类；原型补批量选择、加载态、支付失败、整单备注四个场景 |

改完后重跑本次的采集脚本，目标：11px 为 0；可点元素 < 36px 为 0（36–43px 的都挂热区）；只有图标的按钮全部有标签；字符图标为 0；行内样式只剩网格模板和状态取色变量。
