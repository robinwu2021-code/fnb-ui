餐饮 App 的任务在 `android-ui-v3` 分支的 `docs/android/剩余任务清单-2026-11-11.md`；零售接入的任务（R0 门店业态分流 → R1 规则移植 → R2 数据 → R3 收银 → R4 订单退换货 → R5 库存作业 → R6 商品与价签 → R7 零售设置与报表 → R8 电子秤与客显）在 `android-retail` 分支的 `docs/android/零售业态接入方案-2026-11-11.md`。原来排在这里的 A0–A5 不再单独做：设计系统、餐饮功能、硬件、集群已在现有 App 里推进。

## 五、已知限制（原型，不再排期）

- 硬件、平台授权和推送都是模拟：192.168.1.x 能连上，其他网段超时；OAuth 回调用按钮模拟。
- 数据在内存和 localStorage 里，刷新复原；零售改价直接改示例数据。
- 平面图存本机 `pos-react.floor`；2.5D 固定一个视角，不画椅子和人。
- 零售的分类、规格、渠道同步仍沿用餐饮菜品模块。
