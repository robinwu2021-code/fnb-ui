# 全线点餐 POS · 方案：去灰、结账全流程、状态体系、营销与快捷操作

> 状态：已实施（2026-10-23）。决定：默认皮肤**保持黑白灰**（不换经典蓝），尽量少用灰；其余按推荐方案；另加菜品管理、会员管理与标签、报表模块。结果见文末「十、实施结果」。
> 对象：`prototypes/bapp/pos-ui.html`、`pos-components.html`、`proto.css`、`tools/gen-colors.py`，以及 [UI 组件方案](全线点餐POS-UI组件方案.md) v9、[业务状态](全线点餐POS-业务状态.md)。
> 来源：本轮意见——① 取消灰色线条，也不用灰色的底，尽量少用大面积灰底；② 优化结账页整体布局和全流程交互；③ 整理桌台、订单、菜品的状态，用图标和颜色区分；④ 增加营销功能（储值、积分、活动、会员），需求取自 ai-shop，交互要完整；⑤ 拼桌、拆单、调价、挂单、会员码等常用功能能快速调出；⑥ 形成方案。
> 方法：在原型里按格点取样（每 6px 一个点，取该点最上层有底色的元素）实测灰底面积；逐个走结账流程；对照业务状态字典；营销需求见第五节注明的 ai-shop 文件。

## 一、结论

| # | 问题 | 方案一句话 |
|---|---|---|
| ① | v9 去掉了描边，但改用浅灰块分层，灰底面积仍占 30%–55%；墨黑皮肤下选中色也是灰 | **「白底 + 主题浅色 + 状态色」三种面，不再用中性灰做底**：卡内块改白底、靠间距和内容分组；需要「底」的地方用主题色的 50 档或状态浅底；画布只留 8px 缝隙。默认皮肤从墨黑改为有色相的主题色（推荐经典蓝） |
| ② | 结账页是三栏「支付方式 · 收款 · 明细」，但优惠、会员、改价不在流程里；收完款只有一个结果弹窗 | **结账改为两栏五步**：左「账单与优惠」（核对 → 会员 → 优惠），右「收款」（方式 → 金额 → 确认）；顶部一条进度（应收 → 优惠 → 已收 → 找零）；收款后进入「完成」页（小票、发票、积分、清台） |
| ③ | 桌台只有 6 个状态且「用餐中」借用订单状态；菜品的「状态」和「标记」混在一起 | **三个实体各一张状态表**：桌台 10 态、订单 9 态、菜品分「售卖状态 5 态 + 出品状态 9 态 + 标记 6 种」；全部用业务状态九组的图标和颜色，在卡片上统一用「左上图标 + 顶部状态色条 + 文字」 |
| ④ | 原型只有「会员价」「满 200 减 10」两个静态字样 | **营销四块：会员、储值、积分、活动与券**。收银台上能识别会员、开会员、充值、储值付款（顾客本人确认）、核销券、自动匹配活动、按规则叠加优惠；规则和状态取自 ai-shop（第五节）。积分在 ai-shop 是平台积分、线下不发不抵，需拍板（5.6） |
| ⑤ | 拼桌、拆单、调价、挂单藏在「更多」菜单或没有；会员只能从系统栏进 | **快捷操作条 + 扫码直达 + 行内操作**：结单区头下一排 5 个常用（可在设置里换）；扫码枪扫到会员码自动绑会员；订单行左滑 / 长按出行内操作（调价、赠送、退菜、转菜） |

## 二、去灰（①）

### 2.1 实测

默认设置（色块面感 · 墨黑皮肤 · 紧凑 · 1280×800），设备内容区里「最上层底色是中性灰」的取样点占比：

| 工作台 | 灰底占比 | 主要来源 |
|---|---|---|
| 点餐 | 55%（其中 21% 是菜品图未加载时的图位底） | 菜品卡块色 13%、合计块 7%、待下单组 5%、画布缝隙 3% |
| 订单（卡片） | 50% | 订单卡片 40%、筛选胶囊 3% |
| 班次 | 42% | 分组列表 21%、输入框 7%、统计块 7%、合计块 4% |
| 桌台 | 39% | 桌台卡 23%、分组列表 6%、统计块 6% |
| 结账 | 30% | 合计块 7%、收款头 5%、按键 5%、分组列表 5% |
| 设置 | 14% | 分组列表 8% |

另外两处「灰」不在上表里但同样显眼：
- **墨黑皮肤的主色 tint 就是灰**（gray-150），选中的菜、当前导航项、soft 按钮、选中的筛选全是灰底。
- **中性控件全是 faint 灰**：搜索框、输入框、步进器、分段轨道、筛选胶囊、muted 按钮。

### 2.2 原则：三种面，不用中性灰做底

| 面 | 颜色 | 用在 |
|---|---|---|
| **白** | `--c-surface` | 面板、卡片、卡内块（菜品卡、桌台卡、订单卡、支付方式、数字键）、分组列表、合计块之外的一切 |
| **主题浅色** | 主题色 50 档（新增角色 `--c-primary-wash`）；选中仍用 100 档 tint | 需要「一块底」又不表达状态的地方：输入框、搜索框、步进器、分段轨道、筛选胶囊、键盘数字键、合计块、收款头、待下单组 |
| **状态浅底** | 业务状态组的 tint（已有 `--c-st-{组}-tint`） | 带状态的块：用餐中 / 待结账的桌、要处理的订单卡、沽清的菜 |

| 规则 | 说明 |
|---|---|
| 不画线 | 列表行间的线也去掉，改用行高 + 4px 行距 + 分组标题；表格（设置页）改为隔行用主题浅色（只在超过 8 行的表上） |
| 白块怎么和白面板分开 | 靠三样东西：**间距**（块与块 8、组与组 16）、**内容本身**（菜品图、桌号大字、状态色条）、**悬停 / 按下的主题浅色**。白面板里的白卡不再需要边界——整齐的网格本身就是边界 |
| 画布 | 设备画布保留一档极浅色，只出现在面板之间 8px 的缝隙里（占比 ≤ 3%）。可选「画布也用主题浅色」 |
| 墨黑皮肤 | 墨黑的 50 / 100 档就是灰，与本条原则冲突。**默认皮肤改为有色相的主题色**（推荐经典蓝；虹选红因与危险色撞色不推荐做默认）；墨黑保留为可选皮肤，选它时按 v9 的块色规则 |
| 灰只留给 | 禁用态（字和底）、占位字、次要文字。不再有「中性块」 |

### 2.3 各组件改法

| 组件 | 现在 | 改为 |
|---|---|---|
| 菜品卡（有图） | 块色底 | 白底；图片圆角，图下文字直接落在白底上；未加载时图位用分类粉彩底（已有 `--kp`），不用灰 |
| 菜品卡（无图） | 块色底 | 白底 + 左侧 4px 分类色条；或整卡分类粉彩底（「色块」变体） |
| 桌台卡 | 空闲块色 | 空闲白底；用餐中、待结账等用状态浅底 + 顶部 3px 状态色条（见第四节） |
| 订单卡 | 块色 | 白底 + 左侧状态色条（所有状态都有，不只要处理的） |
| 分组列表、统计块 | 块色、行间线 | 白底、无线、行距 4；统计块数字之间靠间距 |
| 输入、搜索、步进器、分段、筛选 | faint 灰 | 主题浅色 50；选中仍是 100 tint + 主色字 |
| muted 按钮 | faint 灰 | 主题浅色 50 + 墨字（「取消」「打印报表」这类） |
| 键盘 | 数字块色、功能键深一档 | 数字键主题浅色 50；功能键主题浅色 100；确认键主色实心 |
| 结单区合计块 | faint 灰整块 | 主题浅色 50 整块（与列表的白底对比清楚，又不是灰） |
| 收款头 | 块色 | 主题浅色 50 |
| 待下单组 | 块色 | 主题浅色 50 |
| 骨架 | 灰色渐变 | 主题浅色 50 → 100 渐变 |

令牌：`gen-colors.py` 为每个主题色系新增 `--c-primary-wash`（50 档）、`--c-primary-wash-hover`（100 档的一半，或 75 档）；墨黑主题这两个角色仍是灰（因此不做默认）。删除 `--c-tile*`、`data-surface` 开关（面感只剩一种，不再需要切换）。

## 三、结账页布局与全流程（②）

### 3.1 现状问题

| 问题 | 说明 |
|---|---|
| 优惠不在流程里 | 会员、优惠券在右侧明细里是静态文字；没有识别会员、选券、积分抵现、整单折扣、抹零的操作 |
| 改单要退出结账 | 发现点错菜、要调价、要赠送，只能回点餐页 |
| 三栏分散注意力 | 左支付方式、中收款、右明细，收银员的视线要在三处跳 |
| 收款结束就断 | 只有一个「收款成功」弹窗；没有发票、积分到账、清台、下一桌 |
| 部分支付没有承接 | 组合支付只是示例；收了一部分以后离开，再回来不知道还差多少 |

### 3.2 布局：两栏 + 顶部进度

```
┌ 系统栏 ───────────────────────────────────────────────────────────┐
├ 进度条：应收 ¥268.00 → 优惠 −¥20.00 → 应付 ¥248.00 → 已收 ¥0 → 待收 ¥248.00 ┤
├ 账单与优惠（左 480）──────────────┬ 收款（右）─────────────────────────┤
│ A03 · 4 人 · #1024        [改单] │ 支付方式（横排大胶囊）                │
│ ── 账单 ─────────────────────── │ [微信][支付宝][现金][银行卡][储值][挂账]│
│ 6 道菜（展开 / 收起），行内：调价·赠送 │ ── 收款区（随方式变化）──────────── │
│ ── 会员 ─────────────────────── │ 现金：实收 · 找零 · 快捷金额 · 键盘    │
│ [扫会员码 / 输手机号] 或已识别会员卡 │ 扫码：请出示付款码 · 扫码枪状态       │
│ 熟客 · 本店余额 ¥520 · 券 2 张      │ 储值：本金 / 赠送余额 · 验证码          │
│ ── 优惠（自动匹配 + 手选）────────── │ 组合：已付列表 + 剩余                  │
│ ✓ 非高峰 8 折（活动，自动）−¥20    │                                      │
│ ○ 优惠券：本单已参加活动，不能用券  │ 键盘右下：确认收款 ¥248.00            │
│ ○ 会员价（待定）                    │                                      │
│ ○ 积分（线下不抵，见 5.6）          │                                      │
│ ○ 整单折扣 / 抹零 ›（选原因，需授权）│                                      │
│ ── 合计块（主题浅色）──────────────  │                                      │
│ 小计 · 优惠 · 服务费 · 应付          │                                      │
└────────────────────────────────┴──────────────────────────────────────┘
```

- **左栏「账单与优惠」从上到下就是结账的前三步**：核对账单 → 识别会员 → 选优惠；每一步都能就地操作，不用离开结账页。
- **右栏「收款」**：支付方式改成横排大胶囊（48 高，品牌色图标），下面是收款区；确认收款仍在键盘右下。
- **进度条**：一行五个数，任何一步改动都实时更新；优惠、已收用主题色，待收为 0 时整条变成功色。
- 导航在左 / 右时，结账页不显示导航（全宽两栏）；从结单区「结账」进入，左上「返回点餐」。

### 3.3 全流程

| 步 | 场景 | 交互 |
|---|---|---|
| 0 进入 | 结单区「结账」、桌台卡「结账」、订单页「取单 → 结账」 | 带出这一单；有待下单的菜时先提示「还有 2 道没送厨：送厨并结账 / 删除后结账」 |
| 1 核对账单 | 菜品折叠成「6 道菜 · ¥268」，展开看明细 | 行内操作（左滑或长按）：调价（需授权）、赠送（需授权）、退菜（需授权）；「改单」回点餐页并保留结账进度 |
| 2 会员 | 未识别时显示「扫会员码 / 输完整手机号 / 开会员」三个入口；扫码枪扫到会员码任何时候都直接识别 | 识别后显示会员卡（分层、标签、本店余额、可用券数），匹配会员专享活动；开会员只需完整手机号，手工开的是线索会员（权益灰掉，见 5.1） |
| 3 优惠 | 按 ai-shop 计算顺序：活动（自动匹配）→ 券（手选或扫券码）→ 积分（若开放，5.6）→ 人工折扣 / 抹零 | 每条优惠一行，带「✓ / ○」和金额；互斥项自动置灰并写原因（「本单已参加满减，不能用券」「用券后不能抹零」）；顾客明确选的券不静默丢弃；人工优惠必须选原因、超额度走授权 |
| 4 收款 | 选方式 → 输金额或等待设备 / 顾客确认 → 确认 | 单一方式：收满即可确认。组合支付：每收一笔进入「已付列表」（可撤销），待收自动减少，收满后自动进入第 5 步（储值不参与组合）。扫码、刷卡由设备回调自动确认；储值等顾客本人确认，余额不足时不可选；失败进支付失败结果（已做好） |
| 5 完成 | 「完成」页替代原来的结果弹窗 | 大号「收款成功 ¥248.00」+ 找零；本单优惠合计、储值余额、（若开放）预计积分；操作：打印小票（默认自动）· 开发票（扫码开票 / 填抬头）· 清台（结账后自动清台时不显示）· 下一桌（回桌台）。5 秒无操作自动回桌台 |
| 中途离开 | 收了一部分就离开 | 订单状态变「部分支付」，桌台卡显示「待收 ¥148」；再次进入直接落在第 4 步，已付列表保留 |
| 反结账 | 已结账订单在订单页「反结账」 | 需授权；原支付原路退回；储值付款首期不能自动退（提示已登记待办）；已核销的券不可撤销；积分按 ai-shop 规则冲正（若开放） |

## 四、状态体系（③）

### 4.1 原则

- 状态和「标记」分开：**状态**是会变的流程位置（用餐中、已沽清），每个实体同一时刻只有一个主状态；**标记**是属性（招牌、新品、辣、需称重），可以有多个，用分类色或中性字，不用状态色。
- 状态一律用业务状态九组的图标和颜色（[业务状态](全线点餐POS-业务状态.md)第二节），新增状态只归组、不新造颜色。
- 卡片上统一呈现：**顶部 3px 状态色条 + 左上状态图标 + 状态文字**；需要处理的状态（待处理、异常两组）再加状态浅底。列表里用 `st-tag.dot`。

### 4.2 桌台（10 态，现有 6 态 + 补 4 态）

| 状态 | 组 | 图标 | 卡片呈现 | 说明 |
|---|---|---|---|---|
| 空闲 | 已关闭 | `circle` | 白底，无色条 | 可开台 |
| 已预订 | 预约 | `calendar-clock` | 白底 + 预约色条 + 「19:00 张先生」 | 到店前 30 分钟起显示 |
| **待点餐**（新增） | 等待中 | `hourglass` | 等待色条 + 「已开台 6 分」 | 开台后还没下单；超过 10 分转「待处理」提醒 |
| **用餐中**（新增，原借用订单「进行中」） | 进行中 | `utensils` | 进行中色条 + 人数 · 时长 · 金额 · 上菜进度 | |
| **超时未上菜**（新增） | 待处理 | `timer` | 待处理色条 + 浅底 + 「超时 2 道」 | 有菜等待超过设定时长 |
| 待结账 | 待处理 | `receipt` | 待处理色条 + 浅底 + 金额 | 已打印预结单或顾客要求结账 |
| **部分支付**（新增） | 待处理 | `wallet` | 同上 + 「待收 ¥148」 | |
| 待清台 | 待处理 | `sparkles` | 待处理色条 + 「已结账 3 分」 | 结账后未自动清台时 |
| 并台 / 拼桌 | 变更标记 | `git-merge` / `users` | 白底 + 「并入 A03」或「A03-2」 | 拼桌见第六节 |
| 停用 | 已关闭 | `ban` | 压淡 | 维修、包场 |

### 4.3 订单（9 态，现有）

进行中、待结账、部分支付、已结账、挂起、已取消、已反结账、合自、拆自——沿用字典。补两条规则：订单卡 / 订单行的状态色条覆盖所有状态（不只要处理的）；「挂起」卡片显示挂起人和挂起时长。

### 4.4 菜品

| 维度 | 状态 / 标记 | 组 · 图标 | 呈现 |
|---|---|---|---|
| 售卖状态（菜单上） | 在售 | — | 不显示 |
| | 仅剩 N（≤ 5） | 待处理 · `triangle-alert` | 卡片右下 dot 形式 |
| | 已沽清 | 异常 · `circle-slash` | 整卡压淡 + 图上 chip，不可点 |
| | **限时供应**（新增） | 预约 · `clock` | 「11:00–14:00」，不在时段内同已下架 |
| | 已下架 | 已关闭 · `archive` | 不出现在点餐菜单，只在菜品管理里 |
| 出品状态（订单里） | 待下单 · 已下单 · 制作中 · 催菜中 · 待上菜 · 已上菜 · 已退 · 赠送 · 转自 · 已改价 · 临时菜 | 沿用字典 | 订单行 `st-tag.dot` |
| 标记（属性，可多个） | 招牌 · 新品 · 辣 · 素 · 需称重 · 套餐 | 不用状态色：分类色或墨字 + Lucide 图标（`award` `sparkle` `flame` `leaf` `scale` `layers`） | 菜名后小图标；筛选胶囊可按标记筛 |

## 五、营销：会员、储值、积分、活动与券（④）
