# 全线点餐 POS · 黑白灰色系方案

> 状态：**已定为默认**（2026-10-23）。原配色保留为「多色」选项（`data-tone="color"`）。待确认事项已按建议决定（第五节）。
> 预览：`pos-ui.html`、`pos-components.html` 默认 `data-tone="quiet"`；页首「色系」可切到 **多色** 对比。旧存档里的原默认值不再沿用，打开即为黑白灰。色值由 `tools/gen-colors.py` 生成到 `pos-colors.css` 的 `[data-tone="quiet"]` 一段，不改组件、不改结构。
> 前提：默认皮肤「墨黑」（主色 = 墨，墨只给正文和主按钮；选中 = gray-200 块 + 墨字；白底少灰，见《设计规范》3.0）。

## 一、问题：墨黑皮肤下，颜色在「装饰」而不是「提醒」

墨黑把主色收成了墨，但状态色、辅助色、分类色没跟着收。抽样四个画面（墨黑 · 中文）：

| 画面 | 彩色文字（种） | 彩色底（种） | 主要来源 |
|---|---|---|---|
| 桌台 | 13 | 7 | 9 个状态组，每组圆点、文字各一档，一种色相就是两种颜色 |
| 点餐 | 9 | 13 | 11 个分类色小方块 + 无图卡粉彩底 + 结单区菜品状态 |
| 订单卡片 | 11 | 8 | 状态标签：进行中蓝、等待青、暂存橄榄、变更品红、完成绿… |
| 结账 | 3 | 6 | 支付方式品牌色（微信、支付宝等） |

结果：一屏同时出现 8–13 种颜色，真正要人处理的「待结账」「接单超时」只是其中一种，**跳不出来**；版面本来是黑白灰，颜色反而显得零碎。

## 二、原则

1. **黑白灰承担结构和常态。** 版面、选中、主操作、正常进行中的状态，全部用灰阶和墨。
2. **颜色只给「要人处理」的事。** 全屏只留两种信号色：**琥珀 = 待处理**（待结账、待点餐、催菜、超时未上菜…），**红 = 异常**（接单超时、支付失败、打印失败…）。看到颜色就该动手。
3. **常态靠明度分层，不靠色相。** 正在发生的最黑，已经过去的变浅：

   | 层 | 灰阶 | 状态组 |
   |---|---|---|
   | 正在发生 | 墨 gray-900 | 进行中（制作中、用餐中、营业中） |
   | 等着 | gray-700 | 等待中（待取餐、配送中、支付中、待同步） |
   | 已过去 | gray-600 | 已完成（已上菜、已支付）、变更标记（补打、改价、赠送…） |
   | 结束 | gray-500 | 已关闭（已取消、已退、停用） |

4. **要提前看到的用形状，不用颜色。** 预约、暂存保留 chip（底 + 图标 + 文字），底色用中性 gray-150、墨字。
5. **一种颜色只用一档。** 圆点（图标）和文字同档，一屏不会出现「同一个琥珀的两种深浅」。
6. **图标 + 文字始终在。** 去掉颜色后，状态仍由图标和文字表达（原有规则，不变）。

## 三、色值

### 3.1 状态组

| 组 | 现行 | 黑白灰：图标 / 文字 | 黑白灰：chip 底 | 卡片状态块（常态 / 要处理） |
|---|---|---|---|---|
| 待处理 action | 琥珀 600 / 700，chip | **warning-700** #8F5000 | warning-200 #FFD1A9 | 30% / 60% 琥珀（不变） |
| 异常 failed | 红 600 / 700，chip | **danger-700** #B70F0F | danger-200 #FECDC6 | 30% / 60% 红（不变） |
| 进行中 progress | 蓝 600 / 800 | gray-900 | gray-100 | gray-100 / gray-150 |
| 等待中 waiting | 青 600 / 800 | gray-700 | gray-100 | gray-100 / gray-150 |
| 已完成 done | 绿 600 / 800 | gray-600 | gray-100 | gray-100 / gray-150 |
| 变更标记 trace | 品红 600 / 700 | gray-600 | gray-100 | gray-100 / gray-150 |
| 预约 booked | 紫罗兰，chip | gray-900 | gray-150 | gray-100 / gray-150 |
| 暂存 held | 橄榄，chip | gray-900 | gray-150 | gray-100 / gray-150 |
| 已关闭 closed | 灰 500 / 600 | gray-500 / gray-600 | gray-100 | gray-50 / gray-100 |

中性组的卡片状态块不按「浅底 30% 叠白」算（灰叠白几乎看不出），直接取 gray-100：**占用中的桌（gray-100）比空闲桌（gray-50）重一档**，当前桌 gray-200 块。

### 3.2 其他

| 位置 | 现行 | 黑白灰 |
|---|---|---|
| 分类小方块 | 11 色实心 | gray-300 中性小方块（分类靠名字区分） |
| 无图菜品大字位 | 分类色字 | 墨字，底 gray-100 |
| 进行中避让角色 `--c-progress-*` | 状态蓝 | 墨 |
| 主色、选中、主按钮 | 墨 | 不变 |
| 优惠金额（−¥）、已用优惠图标 | 成功绿 | 墨字 + 「−」号（`--c-saving`） |
| 支付方式图标 | 品牌色 | 不变（顾客和收银员靠品牌色认支付方式） |
| 收款成功、已收齐 | 成功绿 | 不变（结果页，一次性） |

### 3.3 对比度

| 组合 | 对比度 | 要求 |
|---|---|---|
| 琥珀 700 字 / 琥珀 200 底 | 4.51 | ≥ 4.5（正好过线，标签字不小于 12px） |
| 红 700 字 / 红 200 底 | 4.78 | ≥ 4.5 |
| 琥珀 700、红 700 / 白 | 6.33、6.80 | ≥ 4.5 |
| 墨 / gray-150（预约、暂存 chip） | 14.09 | ≥ 4.5 |
| gray-700 / gray-100 | 7.36 | ≥ 4.5 |
| gray-600 / gray-100 | 4.79 | ≥ 4.5 |
| gray-500 图标 / gray-100 | 3.17 | 图标 ≥ 3 |

## 四、效果（抽样）

| 画面 | 现行 | 黑白灰 |
|---|---|---|
| 桌台 | 18 张桌 7 种底色、13 种字色 | 只有待结账、待点餐、部分支付、待清台、超时（琥珀）亮起；其余灰阶，当前桌墨块 |
| 订单卡片 | 蓝、青、橄榄、品红、绿、琥珀、红 | 只剩琥珀（待结账、部分支付）和红（接单超时） |
| 点餐 | 分类 11 色 + 菜品状态色 | 菜品照片是唯一的大面积颜色；结单区只有「催菜中」这类待处理是琥珀 |

## 五、决定（2026-10-23，全部按建议执行）

| # | 问题 | 决定 | 理由 |
|---|---|---|---|
| 1 | 默认色系 | 黑白灰为默认，原配色保留为「多色」 | — |
| 2 | 已完成用灰还是绿 | **灰**（gray-600），不改 | 信号色只留琥珀、红两种，「看到颜色就该动手」；已完成靠勾选图标 + 文字表达 |
| 3 | 优惠金额 | **墨字 + 「−」号**（黑白灰下）；多色下仍是成功绿 | 结单区每单都有优惠行，绿色会常驻在清单里；新角色 `--c-saving`（黑白灰 = 墨，多色 = 成功绿），已用优惠的图标同样处理。收款完成（待收 0）、结果页的绿保留 |
| 4 | 空闲桌改白底 | **不改**，仍是浅灰 gray-50 | 白卡放在白面板上没有边界，违反「卡片要有底块」；空闲与占用靠状态图标、人数、金额区分 |
| 5 | 其他皮肤 | **所有皮肤都可用**，不改 | 色系和皮肤是两个开关，互不影响 |
