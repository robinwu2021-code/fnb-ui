# POS v3 Ordering Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver the approved v3 ordering prototype with functional settings and ordering interactions.
**Architecture:** Buildless native ES modules. Pure order/settings model; reusable component functions; independent page renderer and CSS tokens. Existing prototypes stay available.
**Tech Stack:** HTML, CSS, JavaScript, Node built-in tests.
**Spec:** docs/全线点餐POS-UI组件方案-v3.0.md

## Global Constraints
- Chinese/English, Google font fallbacks, 48px targets, no gray control outlines.
- Independent skin/style/layout/type settings, compact fixed dock, scrollable order lines.
- Only ordering page is delivered; payments remain a clearly labeled preview.

## Tasks
- [x] Verify domain/settings expectations with failing tests: variant merging, stock bounds, sent-line protection, settings normalization, six layout variants.
- [x] Implement order/settings model and import existing sample menu data.
- [x] Build shared buttons, cards, order lines, modal/settings and ordering workbench.
- [x] Implement settings persistence, responsive layouts and bilingual rendering.
- [x] Run Node tests, syntax checks and browser checks for ordering, settings, overflow and screenshots.

## Review Focus
Long English names; biggest font at narrow width; settings without resetting order; image failures; queued kitchen requests while offline.

## Delivery rulings
- Ordering page is the first deliverable per explicit user request; a full component gallery and other workspaces remain planned.
- Business data is session-local; only display settings are persisted. Checkout is explicitly a preview.
- Single-table demo stock validation is enforced; multi-device and global inventory are outside this prototype.
