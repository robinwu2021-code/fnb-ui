> 状态：方案稿 v1 · 2026-11-11 · 待确认
> 关键画面原型（2026-11-11）：`prototypes/pos-react/src/retail/`，入口 `#retail`（页首「零售收银」）；8 个画面 = 空车 · 扫了 14 件 · 未知条码 · 称重 · 选规格 · 取单 · 收款现金 · 收款完成，页首「模拟扫码」6 种码。先不接 `biz` 配置层（第 1 期），状态在 `retail/RetailPos.tsx` 自带的小 store 里。

> 第 1 期配置层（2026-11-11 完成）：`src/biz/`（`store.ts` 业态与零售当前页签 · `index.ts` BIZ 定义：页签 / 布局 / 设置菜单 / 快捷操作 / 费用 / 计价 · `dict.ts` 词条覆盖）；`i18n.tr` 先查业态词条；`Workbench` 按业态分流到 `retail/RetailWorkbench.tsx`；系统栏页签、设置菜单与「管理」入口按业态读；页首加「业态」开关，旧链接 `#retail` 自动切到零售收银。零售的订单 / 商品 / 报表 / 会员 / 班次页签暂时复用餐饮模块（页面顶部有提示），库存作业是占位。
> 第 4 期退货（2026-11-11 完成）：零售「订单」页签改为自己的 `retail/RetailOrdersWB.tsx`（时段 · 状态筛选 已结账 / 部分退货 / 已退货 · 详情含商品、整单优惠、支付、退货记录）；退货弹窗 `retail/ReturnDialog.tsx` 四步（找原单 → 选商品 → 原因与金额 → 退款），无单退货走主管授权、只退现金 / 储值，平台单不能在门店退；入口为订单详情「退货」和收银「更多 › 退货」；规则在 `domain/aftersale.ts`（可退数量、优惠分摊、退款金额、默认回库存、原单状态），退完发 `stock.changed` 事件；页首「退货画面」可直达 6 个画面。换货（§4.3）同日完成：订单详情「换货」走同一个弹窗的换货模式（找原单 → 选退回商品 → 原因 → 去收银），退回部分记到原单（记录标「换货」），发 `exchange.credit` 事件；收银订阅后开新购物车并带「换货抵扣」行，按 `domain/aftersale.exchangeSettle` 显示应补差价 / 应退差价 / 等价，补差价走正常收款，退差价一键原路退回；无单不能换货。页首有「换货 · 选退回」「换货 · 补差价」「换货 · 退差价」三个画面。
> 落地工程 `prototypes/pos-react/`（和餐饮同一个工程、同一套壳，按「业态」切换），参照《[React 迁移方案](全线点餐POS-React迁移方案.md)》

## 〇、总则

### 0.1 目标门店

| 店型 | 典型 | 关键诉求 |
|---|---|---|
| 便利店 / 小超市 | 单店 300–3000 SKU，标准条码为主 | 扫码快、一单十几件、高峰排队；现金 + 扫码付 |
| 生鲜 / 烘焙 / 散称 | 称重商品、店内码 | 秤直连或称重码；按重量计价、临期打折 |
| 服饰 / 精品 / 杂货 | 尺码 × 颜色 SKU，低频高客单 | 规格矩阵、会员、换货、导购提成 |
| 餐饮店里的零售角 | 奶茶店卖杯子、餐厅卖伴手礼 | **同一台机器两种模式**——这是和餐饮共用一套产品的直接理由 |

设备基线不变：横屏平板 1280 × 800（最小 1024 × 768），外接扫码枪、小票打印机、钱箱、客显屏；零售额外常用电子秤、标签打印机。

### 0.2 不改的东西

- 设计规范全部沿用：四种工作台布局 W1–W4、栏宽三档 + 360 + 440、面板骨架 P1–P6、色块不画线、墨只做字和主按钮、两套圆角、密度两档、皮肤 / 色系、L1–L6 布局切换、中英文。
- 令牌：只用 `--c-*` 角色和业务状态 9 组；零售新增状态走 `gen-colors.py` → `sync:tokens`，**不新增状态组和颜色**。
- 系统栏页签 ≤ 6；新增功能先问能不能进设置菜单「管理」。
- 示例数据本地模拟，不接后端；没接的地方用「未实现」画法（设备方案 §0.3）。

### 0.3 餐饮 vs 零售：差在哪

| 维度 | 餐饮 | 零售 | 设计上的结论 |
|---|---|---|---|
| 订单起点 | 开台 → 点菜 → 送厨 → 上菜 → 结账（分钟到小时） | 扫码 → 收款（几十秒） | 零售没有「桌台」「送厨」，**点餐和结账合成一个「收银」工作台** |
| 商品录入 | 点图片 / 分类找菜 | **扫条码为主**，搜索、快捷键为辅 | 输入焦点常驻扫码框，宫格退到次要位置 |
| 商品模型 | 菜品 + 规格 / 做法 / 加料 / 套餐 | 商品 + SKU（尺码颜色）、条码、单位、称重、批次 | 规格浮层改成 SKU 矩阵；新增称重浮层 |
| 订单行状态 | 待下单 / 制作中 / 已上 / 催菜 / 赠送 / 已退 | 正常 / 赠送 / 改价 / 促销 / 称重 / 退货 | 去掉制作链路，新增「退货」行 |
| 售后 | 退菜、反结账 | **退货、换货**（原单退 / 无单退） | 订单工作台加退换货流程 |
| 库存 | 今日库存、沽清 | 进销存：入库、盘点、调拨、预警、临期 | 「菜品」工作台换成「商品」，加库存作业 |
| 优惠 | 餐饮规则：活动与券互斥（B01）、用券不抹零（B08） | 零售规则：活动取最优一个、券在活动后算 | `pricing` 按业态取规则（营销方案 §九第 4 条已列这两套） |
| 费用 | 服务费、茶位费、打包费 | 无服务费；可能有购物袋、押金 | 费用行配置化 |
| 外部渠道 | 外卖平台（菜品 / 菜单 / 门店同步） | 即时零售平台（同一批平台的零售类目）、小程序商城 | 渠道同步页原样复用，列由平台派生 |
| 打印 | 结账单 + 档口厨房单 | 小票 + **价签 / 条码标签** | 去档口路由，加标签模板 |

## 一、业态切换机制

### 1.1 一个开关：`biz`

- 门店级配置：设置 › 门店 › 门店信息 › **业态**（`fnb` 餐饮 / `retail` 零售 / `both` 餐饮 + 零售角）。原型页首 DevBar 加一个「业态」Seg 便于对照。
- store 新增 `biz: 'fnb' | 'retail'`（`both` 时由系统栏左侧「模式」切换，当前模式写入 `biz`）。
- **所有差异集中在 `src/biz/` 一处**，组件里不写 `if (biz === 'retail')` 散落判断：

```
src/biz/
  index.ts        BIZ[biz] → { modules, tabs, menu, quick, fees, pricing, entities, dict }
  fnb.ts          现有配置原样搬入（MODULES、设置菜单、快捷操作、费用、餐饮计价规则）
  retail.ts       零售配置
```

| 配置项 | 餐饮 | 零售 | 消费方 |
|---|---|---|---|
| `modules` | 现有 `MODULES` | §1.2 | `layout/modules.ts` → `layoutOf()` |
| `tabs` | 桌台、点餐、结账、订单、报表、设置 | 收银、订单、商品、报表、设置 | `SysBar` |
| `menu` | 设置 11 组 | §七 | `SettingsWB` |
| `quick` | 会员、挂单、拆单、拼桌、调价 | 会员、挂单、取单、整单折扣、改价 | 结单区 / 购物车快捷操作、可拖快捷方式库 |
| `fees` | 服务费 5%、茶位费、打包费 | 购物袋（按件）、押金（可选） | `AdjRows` / `pricing` |
| `pricing` | 餐饮规则 | 零售规则 | `totals()` |
| `nouns` | 菜品 / 桌台 / 送厨 | 商品 / — / — | i18n 词表按业态覆盖（`dict.retail.ts` 只放差异 key） |

### 1.2 零售的模块布局表

| 模块 | 页签 | 布局 | 栏宽 | 来源 |
|---|---|---|---|---|
| `pos` 收银 | 收银 | **W2**（购物车 440 · 右侧操作区） | 440 | 新；右侧操作区在「扫码 / 宫格」与「收款」两态间切换，收款态直接复用结账右栏 |
| `orders` 订单 | 订单 | W1 | 导航 128 · 详情 360 | 复用 `OrdersWB`，加退换货 |
| `goods` 商品 | 商品 | W1 | 导航 128 · 详情 360 | 由 `MenuWB` 改造 |
| `stock` 库存作业 | （设置 › 管理） | W1 | 导航 128 · 详情 360 | 新：入库、盘点、调拨 |
| `members` 会员 | （设置 › 管理） | W1 | 128 · 360 | 复用 |
| `reports` 报表 | 报表 | W4 | 160 | 复用，加零售分区 |
| `shift` 班次 | （设置 › 管理） | W3 | — | 原样复用 |
| `settings` 设置 | 设置 | W4 | 160 | 复用，换菜单 |

页签 5 个，留 1 个空位给 `both` 模式下的「模式切换」或将来的「库存」上页签。

> 为什么收银用 W2：规范规定 440 只给 W2 用；零售购物车一单十几行，需要比 360 宽的账单；而且收款时左边购物车不动、右边换成收款区，正好就是现有结账工作台的结构——**零售收银 = 结账工作台 + 一个「扫码」前置态**，不新增布局和栏宽。

## 三、收银工作台 `pos`（核心）

### 3.1 结构

```
┌ 系统栏：店名 · 收银 订单 商品 报表 设置 · 打印 网络 渠道 会员 显示 · 时间 ┐
├──────────────── 440 ───────────────┬──────────────── 余下 ───────────────────┤
│ 购物车（P2）                        │ 右侧操作区：两态                          │
│ 头：单号 · 会员 · 快捷操作 5 个      │ ① 扫码态                                 │
│ 清单：CartLine × n（最新在上，高亮）│   扫码框（常驻焦点，大号）· 最近扫描提示 │
│                                    │   快捷商品：分类 Seg + ItemCard 宫格        │
│ 费用与优惠：活动 / 券 / 折扣 / 抹零  │ ② 收款态 = 结账右栏原样                    │
│ 底：件数 · 应收大字 · [收款]         │   步骤条 · 待收 · 收款方式 · 操作区        │
└────────────────────────────────────┴──────────────────────────────────────────┘
```

- 账单在左还是在右跟随 L1–L6 的「详情」位置（W2 现在固定左 440，零售收银同样允许按布局翻转）。
- 一屏实心主按钮 1 个：扫码态是底部「收款」，收款态是当前方式的确认键。
- 从收款态回扫码态：步骤条第一步「购物车」可点，或顶部「继续加商品」；已收的部分保留（组合支付规则不变）。

### 3.2 扫码态

| 区域 | 内容 | 复用 |
|---|---|---|
| 扫码框 | 大号 `Search`，占位「扫条码 / 输入编码、拼音、名称」；扫码枪输入（HID 键盘模式，以回车结束、两键间隔 < 30ms 判为扫码）直接加购，不必先点框 | `Search` |
| 最近扫描 | 扫码框下一行：上一件的名称、单价、「× 撤销」；未识别时换成琥珀 `Banner`「条码 690… 未找到 · 临时商品 / 新建商品」 | `Banner` |
| 快捷商品 | 分类 `Seg`（常用 / 散称 / 烟酒 / 饮品 / 袋子…）+ `ItemCard` 宫格；用于无码商品、散称、袋子 | `Seg` + `ItemCard` |
| 数量快键 | 先按数字再扫码 = 数量（「3 × 」提示在扫码框左侧 chip）| `Chip` |

扫码结果分流：

| 扫到 | 处理 |
|---|---|
| 标准条码（EAN-13 / UPC / 店内码），单 SKU | 加一件；同商品同价已在车里则数量 +1 并把该行移到最上、闪一下 |
| 条码对应多个 SKU（一码多品）| 弹 SKU 选择 |
| 称重码（店内码 `2X…`，含金额或重量）| 解析成重量 / 金额，直接加一行「称重」行，不弹窗 |
| 散称商品（宫格点选或 PLU）| 弹称重浮层（§3.3）|
| 会员码 / 付款码 / 券码 | 自动识别类型：会员码 → 识别会员；付款码 → 收款态且选中扫码支付；券码 → 验券（复用平台券侧滑）|
| 未知条码 | 琥珀横幅；「临时商品」（输名称 + 价格，行带「临时」标记，复用 `custom item`）或「新建商品」（店长权限，侧滑最小表单）|
| 已下架 / 禁售时段（烟酒、限购）| 红色横幅写原因；禁售可凭主管授权放行（复用授权 x2）|

### 3.3 称重浮层（新，`ov:weigh`）

- `Dialog` 560：商品名 + 单价（元 / kg 或元 / 500g）· 大号重量（秤读数，稳定后变墨字，不稳定时灰字 + `loader`）· 去皮 / 清零 · 计算金额 · [加入]。
- 秤未连接：重量区变 `Keypad` 手输，头部 `StatusTag` 灰「秤未连接」（复用设备状态 `unplugged`）。
- 按件计价的散称（按个卖的面包）走数量，不走秤。

### 3.4 SKU 选择浮层（由规格浮层 x1 改造，`ov:sku`）

- 一维规格：`OptionGroup` 一排；二维（尺码 × 颜色）：矩阵，行 = 颜色、列 = 尺码，格子里写库存；库存 0 的格子 `disabled` 并写「缺货」，低库存琥珀字。
- 餐饮的规格 / 做法 / 加料仍用同一个浮层的「选项组」形态，两种形态由商品数据决定，不由业态决定。

### 3.5 购物车（`CartLine`）

| 元素 | 规则 |
|---|---|
| 主行 | 名称 · 数量 `Stepper` · 小计；称重行数量位置写「0.532 kg」，不可加减 |
| 副行 | SKU（「白 / M」）、条码尾号、单价；促销命中写在副行（「第二件半价 −¥6.00」，`text-saving`）|
| 行操作 | 点行展开：改数量 · 改价（复用调价，含授权门槛）· 赠送 · 删除 · 备注 |
| 状态 / 标记 | 正常不画；赠送、改价、临时商品、称重、退货用 `StatusTag`（§六）|
| 顺序 | 最新加入在上（零售习惯），可在显示设置改成「按加入顺序」 |

### 3.6 收款态

直接嵌 `CheckoutWB` 的右栏（组件拆成 `PayPane` 后两边共用）：步骤条改为「购物车 → 收款方式 → 收款 → 完成」；收款方式、现金快捷金额、组合支付、储值、扫码等待、失败弹窗全部原样。完成弹窗把「下一桌」换成「下一位」，并在 1.5 秒后自动回到空购物车扫码态（可在设置关闭）；找零金额大字保留到下一单第一次扫码。

### 3.7 挂单 / 取单

- 挂单复用 `hold` 浮层（原因可选）；取单用侧滑列出挂单 `StatusTile`（暂存组）：时间 · 件数 · 金额 · 会员。
- 当前车非空时取单：先问「挂起当前单再取」。

### 3.8 客显屏

零售里客显比餐饮重要：实时显示购物车（最新一行放大）、应收、找零；空闲轮播。配置沿用设置 › 设备 › 客显屏。

## 四、订单与售后

### 4.1 订单工作台改动

- 导航：时段（不变）；渠道 Seg：门店 / 小程序商城 / 即时零售平台。
- 状态筛选新增「部分退货」「已退货」。
- 详情：商品清单 · 支付记录 · 金额 · 操作：**退货** · **换货** · 补打 · 开发票 · 撤销交易（原「反结账」，当天当班、需授权）。

### 4.2 退货流程（`ov:return`，`Steps` 四步，W2 风格的宽弹窗 760）

1. **找原单**：扫小票条码 / 输单号 / 按会员手机号查；找不到 →「无单退货」（需主管授权，退款只能现金或储值）。
2. **选商品**：原单行 `Checkbox` + 可退数量 `Stepper`（已退过的扣掉）；称重行只能整行退；赠品随主商品联动提示。
3. **原因与金额**：原因 `OptionGroup`（质量问题 / 不想要 / 错拿 / 其他）· 退款金额 = 按原单优惠分摊后的实付（明细可展开看分摊）· 是否回库存（默认是，质量问题默认否 → 记报损）。
4. **退款**：默认原路返回（复用支付状态「退款中 / 已退款」）；超时未知走「结果未知」；完成打退货小票。

### 4.3 换货

= 退货第 1–3 步 + 回到收银工作台，购物车头部带一条「换货 · 抵扣 ¥X」的负数行，补差价按正常收款，差价为负则退款。复用收银，不单独画收款界面。

## 八、计价规则（`pricing`）

`totals()` 拆成「公共流水线 + 业态规则」：

```
小计 → 行级促销（零售：第二件半价、N 件 M 元、称重商品折扣） → 费用（餐饮服务费 / 零售购物袋）
     → 整单活动 → 券 → 人工折扣 → 抹零 → 应收 → 已收 / 待收
```

| 规则 | 餐饮（现有） | 零售 |
|---|---|---|
| 活动与券 | B01 参加活动就不能用券 | 活动取最优一个，券在活动后算（营销方案 §九第 4 条 B 方案，已有实现）|
| 人工折扣 | B07 用了活动或券不能再打折 | 同 B07 |
| 抹零 | B08 用券后不能抹零 | 允许（按设置的抹零方式）|
| 平台券 | 不与其他优惠同享、不找零 | 同 |
| 退货分摊 | — | 整单优惠按行实付比例分摊，退货按分摊后金额退 |

`pricing.ts` 改为 `totals(input, rules = BIZ[biz].pricing)`，餐饮结果不变（用现有测试数据回归一遍应收数字）。

## 十二、待定

1. **`both` 模式的入口**：系统栏左侧店名下加「餐饮 / 零售」切换，还是零售角只作为点餐页的一个分类（更轻，但没有扫码态）？建议先只做 `fnb` / `retail` 两态，`both` 放二期。
