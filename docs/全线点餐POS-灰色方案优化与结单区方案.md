## 二、灰色方案的优化意见

### 2.1 实测：灰的档位太多、彼此太近

墨黑皮肤现在同时在用 5 档浅灰：

| 档 | 色值 | 用在 |
|---|---|---|
| gray-0 | #FFFFFF | 面板 |
| gray-50 | #F4F6F9 | 画布（面板之间的缝） |
| gray-75 | #F1F3F5 | 块色：卡内块 |
| gray-100 | #EDEFF2 | 输入框、搜索、步进器、分段轨道、筛选、muted 按钮、合计块、功能键 |
| gray-150 | #E5E7EA | 选中（tint） |

两两对比度：

| 对比 | 对比度 | 说明 |
|---|---|---|
| 画布 50 vs 块色 75 | 1.03:1 | 几乎一样：块色看起来像「露出的画布」，不像「面板里的块」 |
| 面板 0 vs 画布 50 | 1.08:1 | 面板和画布分得开，但很弱 |
| 面板 0 vs 块色 75 | 1.11:1 | 卡内块和白面板分得开 |
| 块色 75 vs 输入框 100 | 1.04:1 | 输入框比卡片还深一点点，「控件」比「内容」重 |
| 块色 75 vs 选中 150 | 1.11:1 | **墨黑下选中的菜和没选中的菜只差 1.11:1，主要靠主色字和份数角标区分** |
| 块色上的行线（gray-100 线 on gray-75） | 1.04:1 | 分组列表放在块色里时，行线几乎看不见 |

结论：灰本身不是问题，问题是**五档灰挤在 L 0.93–0.97 之间、职责交叉**，所以画面「发闷」又「分不清」。

### 2.2 建议（按收益排序）

| # | 建议 | 做法 | 收益 |
|---|---|---|---|
| G1 | **灰只留三档，各管一件事** | 画布 = gray-100（比块色深，把白面板「托」起来）· 块色 = gray-50（面板里的卡、按键、输入框共用这一档）· 选中 = gray-200 底 + 墨字 600 | 画布、面板、卡内块三层分明：面板 vs 画布 1.15:1、块色 vs 选中 1.21:1 |
| G2 | **输入框和卡片同一档** | 输入框、搜索、步进器、分段轨道、筛选、muted 按钮改用块色（不再比卡片深）；靠圆角、占位字和图标表明「可输入」 | 控件不再抢内容的分量 |
| G3 | **墨黑的选中再加一道形状** | 小控件（导航项、分段、筛选、选项）：gray-200 底 + 墨字 600；大块（菜品卡、桌台卡、订单卡）：gray-200 底 + 份数角标 / 墨色 2px 内圈二选一 | 选中和未选中拉开到 ≥ 1.2:1，且不只靠颜色 |
| G4 | **灰色区域里不用灰线，用白缝** | 块色里的列表（分组列表、订单行、待下单组）行间改 1px 白线（或 2px 白缝）；白面板上的列表仍用 gray-100 线 | 块色里的行线重新看得见，画面更干净 |
| G5 | **一个区域只铺一块灰** | 同一栏里不叠多块灰：结单区现在有快捷操作 ×5、备注条、待下单组、合计块共 8 块灰；按第三节改成只有中间清单一块灰 | 去掉「补丁感」 |
| G6 | **状态色不进灰** | 要处理的桌台、订单继续用状态浅底（半透明）；不把状态卡也做成灰 | 状态在灰色画面里仍然跳出来 |
| G7 | **强光门店再给一档「灰块」** | 可选：画布 gray-150、块色 gray-100 的高对比档（v9 曾有），设置里切换 | 后厨、窗边等强光环境 |

G1–G4 都只改令牌和少量组件规则，不动结构；建议和第三节一起做。

## 三、结单区 v4 方案

### 3.1 现状（实测，1280 × 800 · 紧凑）

| 段 | 高度 | 内容 |
|---|---|---|
| 头 | 164（23%） | 桌号 · 状态 · ⋯；一行信息；快捷操作 5 个（44 高，图标在上字在下）；备注条 |
| 清单 | 326（45%） | 待下单组（灰）· 已下单 |
| 底 | 230（32%） | 会员行 · 小计 / 服务费 / 优惠三行 · 应收 · 送厨 / 结账；整块 gray-100 |

问题：
1. **清单只剩 45% 的高度**，6 道菜只能完整看到 3 道——结单区最重要的内容被挤掉。
2. **底部太高**：会员、小计、服务费、优惠、应收、按钮叠了 6 行，而这些内容一单里几乎不会变多。
3. **底部是灰的**，和上面的灰色待下单组连成一片，价格区和清单的边界不清。
4. 服务费、优惠和菜品分在两处，收银员要上下对照才知道钱是怎么算出来的。

### 3.3 各段规则

| 段 | 内容 | 视觉 | 规则 |
|---|---|---|---|
| 头 | 桌号 20 号粗体 · 状态标签 · 会员胶囊（已识别时「熟客 · 王女士」，未识别不显示）· ⋯；一行信息（人数 · 时长 · 方式 · 单号 · 备注，一行省略）；快捷操作一排 | 白底；快捷操作 36 高、图标 + 两字横排、块色 | 不超过 120；备注不再单独占一行（点信息行可编辑备注）；会员行从底部移到这里 |
| 清单 | 待下单（白色小卡，可改数量）→ 已下单（直接落在块色上，行间白缝）→ 费用与优惠 | **整块块色**，左右与面板内边距对齐、四角圆 | 唯一的灰色区域；独立滚动；「费用与优惠」永远排在最后，和菜品一起滚 |
| 费用与优惠 | 服务费、活动、券、人工折扣、抹零、（会员价待定）逐行；每行 图标 · 名称 · 金额 | 13 号次要字，金额等宽；加价墨色，减价成功色；不可用的置灰并写原因 | 只列本单真正发生或可用的项；点「优惠券」「人工折扣」直接打开对应弹窗（和结账页同一套规则） |
| 底 | 应收（28 号粗体，右）· 件数与已优惠（12 号，左）· 送厨 / 结账 | **白底**，靠和上面块色的明暗差分开；不加线、不加阴影 | 固定两行，不超过 112；不再显示小计（清单里逐项可见）；批量模式时按钮换成催菜 / 拆单 / 转菜 / 退菜，高度不变 |

### 3.4 状态与边界情况

| 情况 | 结单区表现 |
|---|---|
| 没点菜 | 清单显示空状态（块色里居中一句话）；底部隐藏 |
| 只有待下单 | 「已下单」组不显示；底部「送厨 · N」为 soft、「结账」为主 |
| 全部已下单 | 「待下单」组不显示；底部只有「结账」 |
| 批量模式 | 已下单行前出勾选框；底部换批量操作 |
| 会员已识别 | 头部出会员胶囊；会员专享活动出现在「费用与优惠」里 |
| 清单很长 | 只有清单滚动；头和底固定；滚动时「费用与优惠」跟着菜品走，不吸底（应收已在底部） |
| 离线 | 横幅在系统栏下；结单区不变 |

### 3.5 一并调整的地方（同一结构复用）

| 位置 | 改法 |
|---|---|
| 结账页左栏「账单与优惠」 | 同样「灰色清单 + 白色窄底」：清单里依次是菜品（可折叠）、会员卡、费用与优惠；底部白条只放「应付」 |
| 桌台详情、订单详情 | 已点清单放进同样的块色清单；底部白条放主操作 |
| 班次「钱箱实盘」 | 面额输入放块色清单里；底部白条放差异与「确认交班」 |

## 四、需要确认

1. **G1–G4 一起做**（推荐）：画布加深到 gray-100、块色减到 gray-50、选中 gray-200 + 墨字 600、块色里的行线改白缝。或者只做结单区，不动整体灰阶。
2. **结单区按 v4 方案改**（推荐），并把同样结构用到结账左栏、桌台详情、订单详情、钱箱实盘。
3. **会员信息放头部胶囊**（推荐）；或者作为「费用与优惠」里的第一行。
4. **快捷操作改成一排 36 高横排小按钮**（推荐）；或者收进 ⋯ 菜单，头部只留桌号和信息。
