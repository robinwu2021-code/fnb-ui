交付：[视觉样张](design/pos-ui-v1.1.png)、[v1.1设计令牌](design/pos-ui-tokens-v1.1.json)。本轮是设计规范更新，尚未改造Android应用。

## 1. 视觉方向

白色成为连续画布，以字体层级、对齐和留白区分区域。避免“灰底上铺满白色圆角卡片”。结构趋于平直，操作仍具有清晰形状；高级感来自克制、比例和一致性，不依赖装饰。

## 2. Google字体与中英文

英文与数字优先 [Manrope](https://fonts.google.com/specimen/Manrope)，中文优先 [Noto Sans SC](https://fonts.google.com/noto/specimen/Noto+Sans+SC)。实施时随包提供经过授权核对的字体与许可，离线不依赖Google网络；加载失败使用系统sans-serif。样张暂用本机替代字体，不代表最终字体效果。

| 用途 | 字号/行高sp | 字重 |
| --- | --- | --- |
| 非关键编号 | 12/16 | 400 |
| 辅助信息、状态 | 16/24 | 400 |
| 正文 / 按钮 | 18/28 | 400 / 600 |
| 面板标题 | 24/32 | 600 |
| 页面标题 | 32/40 | 600 |
| 核心金额 | 40/48 | 700 |
| 结果金额 | 48/56 | 700 |

支持zh-CN/en切换并持久化；首次默认中文。切换语言保留桌台、订单、支付与筛选状态。导航、字段、错误、无障碍名称均来自资源字典，不靠页面字符串替换。商品名称有独立翻译字段，缺译时显示原名。金额币种不随语言切换；时间、数量和复数按locale格式化。

默认只显示所选语言，避免中英双行挤满界面；样张并列仅用于对照评审。按钮与状态按英文较长文案自然扩展；不缩小字号。测试“Confirm payment”“Payment status unknown”等长文案，以及1.3×/2.0×字体缩放。

## 3. 背景、留白与边界

- 全局画布和普通面板均白色；普通区域之间不铺灰色沟槽、不加线框。
- 只在输入、悬停和局部工具条用极浅底`#F5F7F6`；账单主体保持白色。不要用大面积灰底区分左右区域。
- 标准外边距24dp、栏间24dp、区域内边距24dp、区块间32dp、卡片间20dp。窄窗可降到16dp外边距；优先减少列数，不缩字或触控区。
- 按钮、卡片、输入框无灰色描边。必要的浮层可用中性柔影：偏移Y6、模糊24、透明度10%；输入可选Y2、模糊12、6%。不为每张卡都加阴影。
- 阴影只是层次提示，不能承担唯一识别信号；输入保留常驻标签和可见输入区域，操作保留动词名称。实际可用性需真机验证。
- 键盘焦点仍使用有色焦点环；输入错误保留红色提示和错误标记。选中使用主题浅底+勾，必要时主题色描边，不使用灰线。

## 4. 圆角分工

| 对象 | 新规则 |
| --- | --- |
| 工作台、内容区、账单区 | 0dp，无独立圆角外壳 |
| 普通菜品/桌台卡 | 4dp；白色无框，选中时显浅主题底 |
| 动作按钮、输入、数字按键 | 12dp；按钮比容器柔和 |
| 多行选择块 | 12dp；不做胶囊 |
| 对话框、侧滑 | 12dp + 必要柔影 |
| 状态标签 | 4dp；减少大色块，只包裹内容 |
| 单行筛选、开关 | 胶囊，但不能扩展为所有组件默认形状 |

保持主操作56dp、次操作48dp以上；字体增长时增高。状态标签最小32dp以容纳24sp行高及上下8dp内边距。

## 5. 布局影响

大字体与增加留白会减少单屏列数，这是有意取舍。网格宽须扣除外边距、栏距、导航、账单及内容内边距后再计算，不沿用v1.0列数算例。详情以380dp为基准；320dp下动作独占行，金额不截断。960dp附近优先提供顶部分类布局，避免大字挤在窄网格里。

主标题下只保留一行辅助信息；操作底栏与内容通过留白分隔。正常状态用文字+小图标，待处理和异常才使用局部状态底。主题色主要用于主操作、当前选择和少量数量标记。

## 6. 验收

中英文分别验收全部页面；检查长按钮、长菜名、金额、键盘及字体缩放。检查无灰色描边、普通区域无大圆角外框、无大面积灰底。弱边界输入需通过可发现性测试；焦点和错误提示不能被取消。新版颜色与字体必须重新执行真实界面对比度和触控检查，旧版64组检查不自动覆盖本版。
