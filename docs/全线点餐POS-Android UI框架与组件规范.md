## 1. 统一基线与优先级

默认：**松绿主题、浅灰画布、白色面板、标准密度、L1 框架、图文菜品**。深色模式、多皮肤和玻璃效果不属于本版视觉验收范围。

当旧规范冲突时，Android 新页面以本文和配套 token 为准；业务状态含义继续使用 [业务状态](全线点餐POS-业务状态.md)。旧 HTML v1/v1.5/v1.6 保留历史呈现，不因本文自动改版。

| 分歧 | 统一规定 |
| --- | --- |
| 44dp 与 48dp 点击区 | 所有独立操作至少 48×48dp，紧凑模式也不缩小 |
| 墨黑与松绿主按钮 | 主按钮松绿；正文和金额墨色；选中使用松绿浅底 |
| 禁止所有线条与表单描边 | 无装饰外框；输入边界、选中描边、焦点环、必要行分隔有明确角色 |
| 字号和字体多套可选 | 一套 Android 系统无衬线字体和八档字号，不向收银员开放字体切换 |
| 间距 8/12/16/20 混用 | 标准密度统一外边距16、栏间16、面板内边距20；紧凑12/12/16 |
| 当前桌与业务状态混色 | 当前对象用选中样式，业务状态独立显示图标+文字，状态不决定选中 |
| 结账入口与主操作过多 | 主导航四项；结账是订单任务；当前可操作任务只有一个主按钮 |

**单位**：空间、尺寸、圆角、线宽用 dp；字号和行高用 sp；字重为数值；动效用 ms。Web 评审稿可按 1px 示意 1dp，但截图必须记录实际 density，不能用屏幕像素推断 Android 布局。

## 2. 整体 UI 框架

### 2.1 固定层级

```text
应用窗口（先处理系统安全区）
  系统栏：门店/班次 | 桌台 · 点餐 · 订单 · 交班 | 网络 · 打印 · 设置
  全局异常横幅（按需出现，占据布局空间）
  工作台：资源导航 | 主内容 | 当前对象详情
    各面板：头部 / 独立滚动主体 / 固定操作底栏
  窄窗摘要与底部导航（按需出现，不覆盖主体）
  浮层：菜单 → 模态遮罩与对话框 → 非阻塞反馈
```

主导航决定工作台，资源导航决定分类/桌区/状态；两者不能混在同一个筛选条。网络和打印显示异常图标及文字；正常时允许图标入口，必须有可访问名称。结账页保留返回和订单身份，隐藏易造成误切换的主导航。

### 2.2 四种工作台模板

| 模板 | 结构 | 页面 | 规则 |
| --- | --- | --- | --- |
| W1 | 资源导航 + 内容 + 详情 | 桌台、点餐、订单 | L1 默认左导航/右详情；L3 顶部资源导航/左详情 |
| W2 | 账单核对 + 收款 | 结账 | 无资源导航；账单侧跟随 L1/L3 详情位置，收款区最大560 |
| W3 | 汇总 + 核对详情 | 交班 | 无资源导航；详情侧跟随框架 |
| W4 | 设置菜单 + 设置内容 | 设置/设备 | 不再额外加第三个详情栏 |

L3 的顶部资源导航只跨主内容，不压缩账单高度。L2/L4/L5/L6 暂不列入本版必验布局。设置按当前应用保存，不随切桌变化。

### 2.3 尺寸与断点

| 角色 | 数值 | 约束 |
| --- | --- | --- |
| 宽窗系统栏 | 最小64高 | 店名、操作员可两行；内容增长时增高，不裁字 |
| 窄窗顶栏 / 底部导航 | 最小56 / 64高 | 不包含系统状态栏/手势区高度 |
| 资源导航 | 分类96、桌区/订单128、设置160宽 | 名称最多两行，计数单独留位 |
| 详情栏 | 960–1279宽时320；≥1280时380 | 后续最大400；字号放大可改为单任务模式 |
| 普通 / 宽对话框 | 最大560 / 760宽 | 四周至少24；空间不够时使用全屏任务 |
| 宽窗侧滑 | 480宽 | 内容区不足时改为底部面板或全屏 |
| 底部面板 | 最大可用高度90% | 需容纳键盘时重算可用高度；内容滚动、操作固定 |
| 菜品 / 桌台卡宽 | 144–200 / 128–200 | 按可用空间计算列数，不依赖设备型号 |

<600dp：单列任务+底部摘要；600–959dp：主内容+可打开的详情；≥960dp：默认多栏；≥1280dp：宽详情。这是 POS 自定义阈值，不与 Android 官方尺寸类同名。可用高度<480dp时缩减固定摘要，复杂操作改全屏，优先保留金额和操作可达性。

网格先按最小卡宽求列数 `floor((内容宽+间距)/(最小卡宽+间距))`，至少一列；空间充足且卡片将超过200时，允许在最小宽约束内增加列数，否则限制卡宽并保留末端空白。空间不足一张最小宽时卡片占满可用宽度并增高；不得水平裁切。

标准密度、L1、分类栏96时：1280dp窗口去除外边距32、两条栏间距32、导航96、账单380，主内容面板740；再扣面板左右内边距40，实际网格700，可排4张163dp菜品卡，间距16。960dp时详情320，主内容面板480，实际网格440，只能排2张最大200dp卡，末端留24dp空白；可由用户切L3增加内容宽度，不能偷偷缩小卡片。桌区导航128时另算列数，不沿用点餐的列数。

### 2.4 滚动与对齐

- 面板头、金额底栏固定；主体和资源导航独立滚动；通常不让整个工作台上下滚动。
- 窄窗、低高度或大字体导致固定区域挤占主体时，改成全屏任务+可滚动内容，不坚持多栏。
- 标题、搜索、卡片网格左边缘对齐；详情标题、订单行、金额名称左边缘对齐；金额右对齐。
- 主按钮与金额摘要使用相同左右内边距；控件按文字基线或视觉中心对齐，不能靠任意 top 偏移。
- 安全区只消费一次；软键盘不得盖住当前字段、错误信息、应收或确认按钮。

## 3. 字体与排版

### 3.1 字体策略

Android 默认使用系统 `sans-serif`，中文由系统 CJK 字体回退，西文与数字遵循系统无衬线字体。这样原型无需联网加载字体。不同厂商字形可能不同，应在目标机核对中文、数字与货币符号。

如以后要求跨设备像素一致，统一打包已审核授权的中西文字体，并重新验收行高和数字宽度；不能一页 Inter、一页 Roboto、一页思源黑体。Compose 支持字体族和字体资源配置，具体接入见 [Android 字体文档](https://developer.android.com/develop/ui/compose/text/fonts)。

### 3.2 八档文字 token

| Token | 字号/行高 sp | 字重 | 使用场景 |
| --- | --- | --- | --- |
| `caption` | 12/16 | 400 | 非关键编号、计数徽标、演示注释；不能用于操作按钮、状态、价格 |
| `support` | 14/20 | 400 | 做法、人数、时间、表单说明、错误与状态文字 |
| `body` | 16/24 | 400 | 正文、输入内容、设置项、费用说明 |
| `label` | 16/24 | 600 | 按钮、分类、菜名、订单行名称 |
| `title` | 20/28 | 600 | 面板标题、桌号、键盘数字 |
| `page` | 24/32 | 600 | 工作台标题、关键统计 |
| `amount` | 32/40 | 700 | 应收、待收、实收等当前核心金额 |
| `result` | 40/48 | 700 | 收款结果页金额；不在列表中使用 |

紧凑模式不缩字号，只调整间距与行高下限。所有尺寸表中的高度均为最小值，文字按系统字体缩放增高；必须验证1.0×、1.3×和2.0×。不得通过把 sp 转 dp 固定字号、负字距、整体缩放页面解决溢出。

### 3.3 文本与金额规则

- 默认字间距0；中文不额外拉字距，不使用全大写替代标题层级。
- 金额、份数、桌号启用 `tnum`，但不把整段中文改为等宽字体；目标字体需实测支持。
- 金额统一“¥1,234.00”；负值写“−¥20.00”，费用优惠同时有“优惠”标签；所有金额保留两位小数。
- 菜名最多两行，超过显示省略号并提供详情入口；桌号、关键金额、支付结果、错误原因不得省略。
- 次要元信息用分隔点分组，如“4人 · 26分钟”；不要把所有说明塞进一行小字。
- 标题使用动作或对象名称：“确认收款”“桌台详情”；Toast 写结果，错误写原因与下一步，不只写“操作失败”。

## 4. 边距与密度

以4dp为基础刻度：**0、4、8、12、16、20、24、32**。线宽和图标线宽是例外，不因4dp网格增粗。

| 角色 | 标准（默认） | 紧凑 | Token |
| --- | --- | --- | --- |
| 工作台外边距 | 16 | 12 | `density.*.pagePadding` |
| 栏间距 | 16 | 12 | `panelGap` |
| 面板内边距 | 20 | 16 | `panelPadding` |
| 网格卡片间距 | 16 | 12 | `cardGap` |
| 业务区块间距 | 24 | 20 | `sectionGap` |
| 同组控件间距 | 8 | 8 | `controlGap` |
| 表单字段间距 | 16 | 12 | `fieldGap` |
| 常规列表行最小高 | 64 | 56 | `rowMinHeight` |

组件专用值优先于容器密度：菜品卡内边距12、输入框左右16、按钮左右20、对话框内边距24；同一组件不因出现在不同页面而改值。标签与字段间8，字段与辅助/错误文字间4，图标与按钮文字间8，状态图标与文字间4。

容器用 `gap` 或相邻元素间距表达一次留白，不叠加两个 margin。首尾元素不再给容器额外内缩；嵌套面板默认不再套有背景的面板，优先用区块标题+留白。

## 5. 色系与颜色职责

### 5.1 基础与主题色

| Token | 色值 | 职责 |
| --- | --- | --- |
| `color.canvas` | `#EDEFF2` | 工作台背景、栏间留白 |
| `surface` | `#FFFFFF` | 面板、弹窗、菜单 |
| `surfaceSubtle` | `#F4F6F9` | 账单清单底、内容占位 |
| `control` | `#E5E7EA` | 次按钮、输入框底、未选筛选 |
| `controlPressed` | `#DCDEE1` | 中性控件按下 |
| `text` | `#181A1C` | 正文、标题、金额 |
| `textSecondary` / `icon` | `#5C5E61` | 辅助说明、占位提示、常规图标 |
| `textDisabled` | `#76797D` | 真正禁用控件的非必要标签，不用于必读原因 |
| `primary` | `#306F5F` | 主操作、已点数量、开启控件 |
| `primaryHover` / `primaryPressed` | `#215749` / `#174237` | 鼠标悬停/触控按下，白字不变 |
| `onPrimary` | `#FFFFFF` | 实心主色上的文字与图标 |
| `selected` / `selectedText` | `#DFF2EC` / `#306F5F` | 选中底和文字 |
| `selectedPressed` | `#D1E9E1` | 已选控件按下，仍用 selectedText |
| `inverse` / `onInverse` | `#313335` / `#FFFFFF` | Snackbar；操作菜单仍白底 |
| `scrim` | `#0C0E12`，45% | 模态遮罩，不遮暗对话框本身 |

基础色不随菜品分类变化。菜品图片保留原图；支付品牌色只用于官方标识，支付方式名称仍用可读文字色。不要通过整体透明度降低沽清卡片，否则价格和状态也会失去可读性。

### 5.2 业务状态色

复用现有九组语义；颜色只着在状态标签/图标和必要提示上，避免整页九种大色块。chip 带自身浅底；inline 默认仅图标+文字。状态在主题选中底或灰控件底上时改用带自身底的标签，防止对比度下降。

| 组 | 字色 | 浅底 | 图标色 | 形式/示例 |
| --- | --- | --- | --- | --- |
| 待处理 action | `#8F5000` | `#FFD1A9` | `#AD6200` | chip；待结账、缺纸、支付未知 |
| 进行中 progress | `#004A93` | `#C2DDFF` | `#0076DE` | inline；制作中 |
| 等待中 waiting | `#00575B` | `#B4E5E8` | `#00888E` | inline；支付中、待同步 |
| 已完成 done | `#005C31` | `#B1EBC4` | `#008F50` | inline；已收款、已上菜 |
| 预约 booked | `#8436AC` | `#EBCDFF` | `#9E49CA` | chip；已预订 |
| 暂存 held | `#415400` | `#D1E3AE` | `#688400` | chip；待下单、挂起 |
| 变更 trace | `#A81E70` | `#FFC9E1` | `#C63288` | inline；补打、改价 |
| 关闭 closed | `#67696B` | `#EDEFF2` | `#848689` | inline；空闲、已取消 |
| 异常 failed | `#B70F0F` | `#FECDC6` | `#D82821` | chip；支付失败、沽清 |

“dot/inline”并非只放一个圆点，仍必须有语义图标和文字。当前选中不是业务状态：待结账桌被选中时，整卡使用主题浅底+选中描边，内部保留“待结账”琥珀标签。用餐中桌不自动使用与当前选中相同的整卡背景。

### 5.3 对比度与搭配限制

正文、辅助文字及必读状态统一目标≥4.5:1；必要图标、输入边界、选中标记≥3:1；装饰分隔线不承担识别控件的责任。此为项目验收目标，参考 [WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 和 [非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)，不等同于仅靠数值就完成全应用无障碍认证。

本版特意修正两个旧配色问题：`#848689` 在控件底 `#E5E7EA` 上只有约2.95:1，不再作为输入边界；松绿文字在按下灰底 `#DCDEE1` 上只有约4.37:1，因此选中控件使用自己的 `selectedPressed`，不能套中性按下背景。

静态颜色值是完全不透明的 sRGB；禁止在组件内临时混色或改变 alpha，再声称沿用已验证对比度。增加皮肤需重验实际前景/背景组合。

## 6. 线条、圆角与层级

### 6.1 四类线条

| 角色 | 宽度 | 颜色/规则 |
| --- | --- | --- |
| 装饰分隔线 | 1dp | `lineDecorative #DCDEE1`；仅密集订单/表格行、滚动与固定底栏分界需要时使用 |
| 表单识别边界 | 1dp | `lineControl #76797D`；输入、搜索、未选勾选/单选；错误时替换为2dp异常字色 |
| 选中/当前对象描边 | 2dp | `primary #306F5F`；配选中底和勾；导航选中不额外画框 |
| 键盘焦点环 | 2dp，间隙2dp | `focus #1C51D9`，白色间隙；在选中描边之外，不能代替选中态 |

面板和普通卡片不画常驻装饰外框，不同时堆“外边框+内分隔+阴影”。描边绘制不改变布局尺寸；焦点环不得被父层裁掉。1dp不等于一个物理像素，应由 Android 按 density 渲染。

### 6.2 固定圆角

| 角色 | 圆角 |
| --- | --- |
| 静态状态标签、勾选框 | 4dp |
| 动作按钮、输入、数字键、菜单项、导航项、分段容器 | 8dp |
| 菜品/桌台卡、多行规格/支付选择块 | 12dp |
| 工作台面板 | 16dp |
| 对话框、侧滑外角、底部面板顶角 | 20dp |
| 单行筛选、计数徽标、开关 | 胶囊，半高；JSON 用 `"50%"` 标识，不转换成999dp |

多行规格块不做胶囊。图片与卡片相接时遵循卡片裁切；不要在同一张卡上同时出现三套不相干圆角。

### 6.3 阴影、遮罩与动效

面板、卡片、固定底栏的 elevation=0；弹出菜单4dp、模态容器8dp。阴影仅表达浮层，不用于增强按钮。白色容器保持白色，不接受 Material 默认色调叠加导致偏紫/偏绿。层级顺序由 `layer` 决定，elevation 不是 z-index。

按下反馈120ms、状态切换180ms、面板进入/退出240ms；减少动效设置下为0ms或即时状态变化。动效不控制业务完成时机，付款成功依赖状态结果；不能用彩带或颜色代替“已收款”。

## 7. 通用组件规范

所有控件实现适用的默认、按下、焦点、禁用、加载、错误、选中状态；不适用的状态不强加。按钮的瞬时按下不写入业务选中状态；键盘焦点可与选中/错误同时存在。

### 7.1 组件尺寸与结构

| 组件 | 最小尺寸/内边距 dp | 文字/图标 | 状态及使用要求 |
| --- | --- | --- | --- |

### 7.2 交互状态统一表

| 状态 | 呈现 | 行为 |
| --- | --- | --- |
| 默认 | 组件基础角色色 | 可执行时可点击 |
| 按下 | 主按钮primaryPressed；灰控件controlPressed；选中块selectedPressed | 保持大小，不缩放/跳动；松手后恢复 |
| 悬停 | 主按钮primaryHover；其他控件采用轻微底色变化 | 仅鼠标/触控板适用，不能作为触屏唯一提示 |
| 焦点 | 蓝色焦点环+白间隙 | 按焦点顺序导航，完整显示当前元素 |
| 选中 | 主题浅底+文字；选择块再加勾/描边 | 读出“已选中”；单选互斥、多选独立 |
| 禁用 | 灰底+disabled字，无按下反馈 | 不接受事件；必读原因用textSecondary，不能一起变淡 |
| 加载 | 原位置进度标记+当前动作文字 | 控件宽度不变、阻止重复；异常可恢复 |
| 错误 | 字段红边+错误图标+具体原因 | 保留用户输入；焦点环仍可见，不用红色一项表达错误 |

“暂时不可用”且用户需要知道原因时保留禁用入口，如“离线，扫码支付不可用”；完全不在本轮范围的能力隐藏，不能显示可点击的假入口。付款结果未知是持久的业务状态，应呈现查询入口，而不是长期旋转的普通按钮加载态。

| `OrderDock` | 订单头、待下单/已下单组、金额摘要、操作 | 320/380宽；分组标题保留；金额栏不跟列表一起滚走 |
| `AmountSummary` | 小计、费用/优惠、待收 | 费用行最小32；金额amount；明细折叠有明确展开入口 |

账单行避免把菜名、单价、数量、状态、操作全部强行塞在一行。标准宽380时优先“菜名 + 行金额”，下一行规格/数量；320宽或大字体时步进器独占一行。所有金额列右对齐；价格和数量不靠空格对齐。

点餐底栏：待下单>0时主按钮“送厨·N项”，结账为次操作；无待下单且可收款时主按钮“去结账”。结账底栏主按钮“确认收款 ¥X.XX”；金额不足或网络条件不满足时显示明确原因。底栏通常最多两项可见操作，其余放“更多”。

## 9. 浮层与反馈

| 类型 | 用途 | 关闭/焦点规则 |
| --- | --- | --- |
| 短任务对话框 | 开台人数、规格、备注、确认清台 | 标题+内容+操作；内容可滚；打开后焦点进入，关闭回到触发控件 |
| 侧滑/底部面板 | 账单、设备、较多筛选 | 宽窗480；窄窗≤90%可用高；重要任务不足空间转全屏 |
| 全屏任务 | 窄屏结账、复杂表单、大字体容纳失败 | 明确返回和对象身份；返回不丢已保存业务 |
| 菜单 | 当前对象的次要操作 | 点击外部/返回关闭；一次只开一个菜单 |
| Snackbar | 已保存、已复制等可暂时消失的信息 | 不遮挡金额/主操作；带动作时允许无障碍延长显示 |
| 页面内错误/结果页 | 支付失败、未知、完成等重要结果 | 持续显示至处理；不能只用Toast承载 |

浮层打开后背景不可操作，背景主按钮不计作当前活动任务的主操作；新模态不得直接堆在旧模态上。错误优先就地呈现，只有跨页面影响才进入全局横幅。返回键先关闭输入法，再关闭浮层，最后离开页面。

## 10. 图标、可访问性与输入

统一采用 Lucide 线性语义，常规图标24dp、按钮内20dp、状态内16dp、空状态40dp，基准24视口线宽1.75。Android 后续使用离线矢量资源，映射已有业务状态图标名；本轮不要求联网下载新图标。品牌标识单独管理，不混用 Emoji、字符箭头和不同粗细的图标库。

点击区至少48×48dp，视觉小图标居中，且相邻点击区不重叠；该下限参考 [Compose 默认无障碍行为](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)。文字标签、角色、选中/禁用/错误状态均提供语义；装饰图标不重复朗读。TalkBack顺序为系统导航→工具条→内容→当前详情→金额→主操作。

手势必须有替代操作：滑删有删除入口、长按详情有详情入口。外接键盘能到达所有主路径，焦点离开菜单后返回原位置。扫码枪输入与搜索、现金输入分别处理，不把扫码数据写进任意焦点字段。触控模式不能依赖hover或tooltip才能理解。

## 11. Token 与 Compose 接入约定

JSON 为单个浅色主题的数值基线：`color/status` → PosColors，`typography/font` → PosType，`density/layout/component` → PosMetrics/PosDims，`radius/stroke/elevation/motion` → 统一样式定义。组件代码引用语义名，不写散落色值和尺寸。

| 现有位置 | 后续规范化内容 |
| --- | --- |
| `theme/PosTheme.kt` | 标准密度默认值、八档字体与行高、控件最小48、Material Typography与POS类型的显式映射 |
| `theme/PosColors.kt` | 松绿实色及选中浅底、分离装饰线和控件边界、九类状态角色、禁止透明色临时合成 |
| `ui/shell/Frame.kt` | 96/128/160资源栏、320/380详情、16/20间距、按可用窗口重排 |
| `ui/components/Controls.kt` | 按钮变体、状态矩阵、焦点环、字段错误、最小点击区与语义 |
| `ui/order/*`、`tables/*`、`checkout/*` | 移除局部字号/颜色/形状分叉，使用业务组件和统一底栏 |

令牌分三层：基础值 → 语义角色 → 组件规格。当前JSON是已解析快照，部分组件尺寸重复基础值；更新时必须同步校验，不允许复制后各改一份。不得把 JSON 中的 sp 数值当 dp，也不能把 `radius.capsule="50%"` 当数值长度。

Material 内置组件不保证自动符合此规范；需显式校准颜色、Typography、shape、最小点击区、边界和默认内边距。不得全局关闭最小触控保护来塞进旧版44dp布局。

## 12. 组件样张与验收

后续组件展示页至少按以下分组呈现，先验组件再验页面：

1. 基础：全部字号、八档间距、基础/状态色、圆角、四类线、层级。
2. 通用：按钮四种层级、图标按钮、输入、筛选、分段、选择块、步进器、选择控件、状态标签。
3. 状态：默认/按下/焦点/禁用/加载/错误/选中；包含“错误+焦点”“选中+焦点”叠加。
4. 业务：菜品、沽清菜品、桌台各状态与选中、订单行、金额底栏、支付选择、现金键盘。
5. 模式：对话框、面板、菜单、空/加载/错误、Snackbar；同样内容在320/380详情宽和窄窗呈现。

| 检查 | 通过条件 |
| --- | --- |
| 数值一致 | 文档与JSON一致，组件无另造间距/圆角/字号 |
| 文字 | 关键文本不截断；1.0×/1.3×/2.0×可读；中文、英文、长菜名和大金额通过 |
| 对比 | 指定文字组合≥4.5、必要边界/图标≥3；同时验证真实渲染态，不仅默认值 |
| 触控 | 所有独立操作≥48；步进器和相邻图标无重叠命中区 |
| 状态 | 不靠颜色；支付未知、离线、缺纸、沽清有明确文字与操作 |
| 布局 | 360、800、959/960、1100、1279/1280、1600dp；横竖屏、低高度、键盘展开通过 |
| 层级 | 一个活动主任务；焦点环不被裁切；模态背景不可操作 |
| 业务 | 切桌不串单、主操作随状态切换；加载失败不显示空账单 |

本版通过数值审查后可作为实施依据；最终验收仍需 Android 真机/模拟器实测字体、点击区、insets和返回行为。本次不会把静态样张或对比度计算表述为运行时验证。

本轮已核算64个指定色彩组合并检查最小尺寸，结果见数值校验记录。独立实施审阅发现的网格内边距遗漏已修正；文档中的网格宽度明确指扣除面板内边距后的空间。
