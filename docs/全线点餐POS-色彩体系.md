# 全线点餐 POS · 色彩体系

> 状态：已接入原型 · 2026-10-23（`pos-ui.html`、`pos-components.html` 都加载 `pos-colors.css` 并开启 `data-colors="v2"`）
> 取值：`prototypes/bapp/pos-colors.css`，由 `prototypes/bapp/tools/gen-colors.py` 生成（同时生成 `pos-colors.json` 和预览页 `pos-colors.html`），不要手改。
> 评审：[色彩体系评审](全线点餐POS-色彩体系评审.md)。P0、P1 全部改入；撞色按方案 A（状态浅底加深一档 + 避让规则），输入框与开关按拍板 2 方案 A。
> 范围：基本色（黑白灰）、可调整的主题色、状态色、**辅助色（业务状态）**、分类色，以及每种颜色用在界面的哪个位置。已接入原型。
> 业务状态：[业务状态（辅助色与图标）](全线点餐POS-业务状态.md)，14 个实体、81 个状态，同样由生成脚本输出。

## 一、总则

1. **基本色是黑白灰，承担版面的全部结构。** 画布、面板、卡片、文字、分隔、中性控件都用灰阶，不随主题变。
2. **主题色可以调整，只出现在固定的几类位置**（第六节）：主操作、选中态、数量与已点标记、和钱有关的标记、开关和勾选开启、焦点环、文字操作。一屏主题色面积不超过 5%。
3. **每个主题色是一个完整色系：** 50–950 共 11 档色阶，加上从色阶派生的角色（实心、悬停、按下、实心上的字、浅底、浅底悬停、描边、文字、焦点）。换主题只换色系。
4. **状态色和分类色不随主题变。** 状态浅底比主题浅底深一档（200 对 100），同屏出现时靠明度就能分开。
5. **撞色时让位置，不改状态色。** 主题色和某个状态色色相太近时，用避让角色把撞上的位置换成别的颜色（第五节）。
6. **组件只用角色令牌**（`--c-*`），不直接写色阶或色值。
7. **业务状态用辅助色加图标。** 订单、菜品、桌台、外卖、支付、工单等的状态按意思分 9 组，每组一种颜色（状态色或 4 个新增辅助色之一）和一种形式；每个状态一个 Lucide 图标（第七节之二）。
8. **颜色不单独承载信息。** 状态一律「圆点或图标 + 文字」；选中同时换底色和文字色；描边（300 档）只做装饰，不能单独表示选中。

## 四、主题色：每个色系一套

### 1. 色阶的生成

- 色相取品牌原色（OKLCH）；每档明度固定：50 → 950 依次为 0.975、0.945、0.89、0.82、0.735、0.65、0.57、0.495、0.415、0.345、0.275。
- 彩度以品牌原色为峰值、两端收窄（50 档 14%，500–600 档 100%，950 档 54%），超出 sRGB 时自动降彩度。
- 7 个色系同一档明度一致，换主题时浅底、描边、文字的轻重不变。

### 2. 角色取档规则

| 角色 | 令牌 | 规则 | 用途 |

### 4. 新增一个主题色

在 `tools/gen-colors.py` 的 `THEMES` 里加一行（键、中文名、英文名、品牌原色），运行 `python3 -I prototypes/bapp/tools/gen-colors.py`。脚本按上面的明度表和取档规则算出色阶和角色，自检对比度和撞色，再写出 CSS、JSON 和预览页。新色系的色相如果离某个状态色不到 15°，要在 `AVOID` 里加避让规则，否则自检会报错。

## 五、撞色与避让（评审 P0-1，方案 A）

两步：
1. **状态浅底统一用 200 档**，比主题浅底（100 档）深一档。同屏的主题浅底和状态浅底现在差 ΔE 6.2–11.5（改之前最小 0.2）。
2. **色相太近的色系加避让规则。** 用四组避让角色表示「容易撞上的位置」，默认取主题色或状态色，撞色的色系把它们换掉：

| 避让角色 | 管哪些位置 | 默认 |
|---|---|---|
| `--c-mark-bg` / `--c-mark-text` | 赠送、会员价、优惠券、预订等和钱有关的主题标记 | 主题浅底 + 主题文字 |
| `--c-progress-dot` / `--c-progress-text` | 制作中、已接单等进行中状态 | 成功圆点 + 成功文字 |
| `--c-due-bg` / `--c-due-text` / `--c-due-mark` | 桌台「待结账」；`--c-due-mark` 是桌号前的标记 | 警告浅底 + 警告文字，不加标记 |
| `--c-hint-bg` / `--c-hint-fg` | 提示类说明 | 信息浅底 + 信息文字 |

| 色系 | 撞上的颜色 | 色相差 | 避让 |
|---|---|---|---|
| 虹选红 | 危险 | 0° | 赠送、会员价、优惠券、预订这类主题标记改用中性标签，红色只留给已退、失败 |
| 微信绿 | 成功（「已完成」组） | 5° | 「已完成」组（已上菜、已结账、已送达…）改用灰色，绿色只留给主题 |
| 琥珀 | 警告（「待处理」组） | 8° | 桌台「待结账」在桌号前加 ¥ 标记，不只靠底色 |
| 经典蓝 | 信息（「进行中」组） | 10° | 提示类说明改中性底，「进行中」组（制作中、已接单…）改用灰色，蓝色只留给主题 |
| 青碧 | 辅助色青（「等待中」组） | 6° | 「等待中」组（待取餐、配送中、支付中…）改用灰色 |

其余组合靠浅底深浅（状态 200、主题 100）、图标和文字区分。生成脚本会拦下色相差 < 15° 又没有避让规则的新色系（状态色和辅助色都查）。
