## 一、自动发现设备

### 1.1 设备种类与接入方式

| 类型 | 角色 | 接入方式（真实实现） | 原型模拟 |
|---|---|---|---|
| 打印机 | 小票 / 厨房 / 标签 | 三路，见 §1.2：**蓝牙扫描取 IP → 再按 IP 连**；**直接填 IP**；**扫打印机机身 / 配置页二维码**（码里带 IP + 协议 + 端口） | 固定 3 台（前台、热菜档口、标签），一台 `no_paper` |
| 副 POS | 同店第二台收银 / 点菜平板 | mDNS `_fnbpos._tcp` 广播；同一局域网互相可见；也可扫主机屏上的二维码配对 | 固定 2 台：`POS-02 · 前台右` `PAD-01 · 服务员` |
| 厨房屏 KDS | 档口出餐屏 | mDNS `_fnbkds._tcp`；或扫屏幕上的二维码配对 | 固定 2 台，一台 `offline` |
| 客显屏 | 收银台顾客侧 | 同一台机的第二屏（系统枚举）或网口 | 1 台 |
| 钱箱 | 接在打印机上 | 随打印机带出，不单独发现 | 挂在前台打印机下 |
| 电子秤 / 扫码枪 | 串口 / USB / 蓝牙 | 枚举串口 + 协议握手 | 各 1 台，电子秤 `unplugged` |
| 取餐叫号屏 | 外带 / 外卖取餐 | mDNS | 1 台，标「未实现」 |

### 1.2 打印机的三路接入

打印机不走「扫网段」：网段扫描慢、跨 VLAN 失效、很多打印机不回 ping。按现场常见做法三选一，侧滑里是三个页签（`Seg`）：

| 路 | 流程 | 界面 | 失败分支 |
|---|---|---|---|
| **A 蓝牙扫描取 IP** | ① BLE 扫描周边打印机 → ② 列出设备名 + MAC → ③ 选中后通过 BLE 读出它当前的 IP / 端口 / 协议 → ④ 用这个 IP 建网口连接（不走蓝牙打印） | 列表每行：名称 · MAC · 信号格；选中后下方出「读到 IP 192.168.1.52 · ESC/POS · 9100」+ `[连接]`；连接成功后进 §1.4 命名用途 | 读不到 IP（打印机没入网）：出 `Note`「该打印机未连 Wi-Fi，先用打印机工具配网，或改用网线」+「改为填 IP」链接；连接超时：toast「192.168.1.52 无响应」，保留在列表里可重试 |
| **B 直接填 IP** | 填 IP、端口（默认 9100）、协议（`Seg`：ESC/POS · TSPL 标签 · CPCL）→ `[测试连接]` → 成功后命名用途 | 三个输入 + 测试按钮；测试中按钮转圈；成功出绿点「已连接 · 打印机型号 XP-80」 | 超时：输入框下红字「无响应，检查打印机是否同一网络」 |
| **C 扫码** | 扫打印机机身标签或配置页上的二维码（约定格式 `fnbpos://printer?ip=…&port=…&proto=…&name=…`）→ 自动填 B 的三个字段并自动测试 | 相机取景框（原型放占位图 + `[模拟扫到]`）；扫到后跳 B 页签，字段已填，自动跑测试 | 码不是本格式：toast「不是打印机配置码」 |

原型里 A 的 BLE、C 的相机都是模拟（§0.3 第二行），B 的连接测试也用 2 秒假延时；但三条路的界面和分支文案全部画出来。

### 1.3 设备状态（`device` 实体，复用 + 新增）

| 状态 | 组 | 用途 |
|---|---|---|
| `online` 在线 | done | 已添加且连通 |
| `offline` 离线 | action | 已添加，连不上 |
| `no_paper` 缺纸 | action | 打印机专用 |
| `unplugged` 未连接 | closed | 已添加但从未连通（如电子秤） |
| `to_sync` 待同步 / `sync_failed` | waiting / failed | 副 POS 数据同步 |
| **`found` 新发现**（新增） | booked | 蓝牙 / mDNS 扫到、尚未添加 |
| **`pairing` 配对中**（新增） | waiting | 点了「连接」到握手完成之间 |

### 1.5 侧滑：添加设备（`sheet:device-add`）

第一步选类型（`RadioCards`：打印机 / 副 POS / 厨房屏 / 客显 / 电子秤 / 扫码枪 / 其他），之后按类型分流：

- **打印机** → §1.2 的三页签 **蓝牙扫描 · 填 IP · 扫码**，连接成功后进「命名与用途」：名称、用途（结账单 / 厨房单 / 饮品单 / 标签，多选）、是否带钱箱、份数默认值，`[完成]`。
- **副 POS / 厨房屏** → 两页签 **附近设备**（mDNS 列表，选中即配对）· **扫码配对**（扫对方屏幕上的码）。
- **客显** → 列出系统检测到的显示输出（HDMI-2 / USB-C），选一个 `[预览]`。
- **电子秤 / 扫码枪** → 串口 / USB 列表 + 协议下拉；蓝牙标「未实现」。

每一路成功后都回到设备列表并选中新设备，toast「已添加 ‹名称›」。

### 1.6 副 POS 的特别处理

- 详情多两项：**角色**（主 / 副，副机只读）和 **同步**（`to_sync / synced`，上次同步时间，「立即同步」）。
- 主机离线时副机顶部横幅「主机离线 · 本机可继续点餐，结账需等主机恢复」（复用 `Banner`）。

### 1.7 数据与状态

```ts
// src/data/devices.ts
export type DeviceKind = 'printer' | 'pos' | 'kds' | 'cds' | 'drawer' | 'scale' | 'scanner' | 'pickup';
export type DeviceSt = 'online' | 'offline' | 'no_paper' | 'unplugged' | 'to_sync' | 'sync_failed' | 'found' | 'pairing';
export type Proto = 'escpos' | 'tspl' | 'cpcl';
export type AddedVia = 'ble' | 'ip' | 'qr' | 'mdns' | 'usb';
export interface Device { id: string; name: string; kind: DeviceKind; ip?: string; port?: number; proto?: Proto; conn: string; via?: AddedVia; st: DeviceSt; use?: string[]; fw?: string; role?: 'main' | 'sub'; lastSync?: string; todo?: boolean }
```

store 加 `devices: Device[]`、`dsel`、`dkind`、`dadd: { step, kind, tab: 'ble' | 'ip' | 'qr', scanning, found, draft }`；动作 `dev:add` `dev:scan:ble` `dev:read-ip:<mac>` `dev:test` `dev:qr` `dev:save` `dev:remove:<id>` `dev:test:<id>` `dev:rename`。设置菜单 `MENU.device` 第一项插 `['devices', '设备列表', 'Devices']`。


**原型已实现（2026-11-11）**

- 页面：设置 › 设备 › 设备列表（`src/modules/settings/DevicesPage.tsx`）；「打印机」页是同一组件只看打印机，右上按钮变「添加打印机」。系统栏打印侧滑底部加了「全部设备 ›」。
- 侧滑：`src/overlays/DeviceAdd.tsx`，三步 类型 → 连接 → 命名与用途。打印机三个页签都能走通，并画出失败分支：没配网读不到 IP、跨网段连接超时、IP 格式错误、扫到非配置码。副 POS / 厨房屏有附近设备和扫码配对两个页签；客显选视频输出、秤和扫码枪选端口，已占用的端口置灰，蓝牙标「未实现」；叫号屏整类标「未实现」，可先登记。
- 详情里「修改连接」复用同一侧滑，直接从第 ② 步开始，保存后更新原设备。
- 列表页直接操作：附近设备「添加」（连接中 → 在线）、缺纸「已换纸」、离线「重连」、副机「立即同步」、两步确认「移除设备」，名称可就地改。

- 新状态 `device.found`、`device.pairing`、`feature.todo` 暂时在 `src/lib/states.ts` 里本地合并；并入 `bapp/tools/gen-colors.py` 后跑 `npm run sync:tokens`，再删掉那段。

### 2.2 一个平台要同步什么

| 对象 | 方向 | 内容 | 平台差异（要在映射页里体现） |
|---|---|---|---|
| 门店 | POS → 平台 | 营业状态（接单 / 暂停）、营业时间、备餐时长 | Uber Eats 有「暂停到某时刻」；Talabat 暂停需填原因 |

| 订单 | 平台 → POS | 新单、取消、退款 | 复用 `delivery` 实体 |
| 出餐 / 骑手 | 双向 | 出餐就绪、骑手到店 | Talabat 骑手到店有通知，其他两家原型不显示 |

### 2.4 侧滑：添加平台（`sheet:plat-add`）

## 三、主界面可拖动布局 · UI 原型方案

### 3.1 两类可拖对象

| 类 | 对象 | 拖动结果 |
|---|---|---|
| **栏** | 导航栏、内容区、详情栏（结单区） | 交换左 / 中 / 右；导航拖到顶边变横排（即 L1–L6） |
| **快捷方式** | 点餐页的操作按钮：会员、挂单、拆单、拼桌、调价、备注、换桌、赠送、预结单、沽清、开钱箱、叫号 … | 从「快捷方式库」拖到界面上的**停靠槽**；槽内排序；拖回库 = 移除 |

不做自由像素级摆放；栏宽固定三档不拖改；不做跨工作台拖。

### 3.2 点餐页快捷方式的停靠槽

现状：快捷操作固定 5 个，放在结单区头部下面一排（`QUICK`），其余藏在「更多」菜单。方案改成**四个停靠槽**，每个槽有容量，快捷方式可以拖到任何一个槽：

```
┌ 系统栏 ─────────────────────────────────────── [槽 S：2 个] 时间 ┐
├ 分类 ┬ 工具条 [搜索] [筛选…]            [槽 T：3 个] ┬ 结单区 ─────┤
│      │                                            │ 头 · A03 · 4人│
│      │  菜品宫格                                   │ [槽 Q：5 个]  │
│      │                                            │ 清单…        │
│      │                                            │              │
│      │ [槽 F：悬浮，右下，最多 3 个圆钮]             │ 底 · 送厨 结账│
└──────┴────────────────────────────────────────────┴──────────────┘
```

| 槽 | 位置 | 容量 | 形态 | 适合放 |
|---|---|---|---|---|
| **Q 结单区头** | 结单区头下一排（现有位置） | 5 | 图标 + 两字，`h-ctl-sm` | 最常用：会员、挂单、拆单、拼桌、调价 |
| **T 工具条尾** | 菜品宫格工具条右端 | 3 | 图标按钮 36×36，热区 44 | 和找菜有关：沽清、临时菜、叫号 |
| **S 系统栏** | 系统栏右侧入口区左侧 | 2 | 图标入口，同现有「打印 / 网络」入口 | 全局：开钱箱、预结单 |
| **F 悬浮** | 内容区右下角，纵向一列圆钮 | 3 | 48 圆钮，墨底白图标 | 单手够得着的：备注、赠送 |

- 槽空着时在编辑态显示虚线占位「拖到这里」，非编辑态不占空间（F 槽空时不显示）。
- 容量满了再拖入：被挤出的那个回到库里，toast「‹拼桌› 已移回库」。
- 「更多」菜单（`MoreMenu`）自动 = 库里没放到任何槽的快捷方式，不再手工维护。

### 3.3 进入 / 退出编辑态（长按）

- **进入**：长按 600 ms 任意**面板头**、任意**快捷方式**、或系统栏空白处。长按期间按下处出一个由小到大的圆形进度环（`--c-sel-bg`），松手前移动 > 8 px 取消（不和滚动、拖菜品冲突）。
- **进入后**：
  - 工作台整体进编辑态：业务按钮不响应点击（`pointer-events: none`），只响应拖动；
  - 每个栏四角出 6 px 虚线框，左上角拖柄 `grip-vertical`；
  - 四个停靠槽显示虚线占位和容量「3 / 5」；槽内每个快捷方式左上出小拖柄，右上出 `×`（点一下移回库）；
  - 底部升起 **快捷方式库**（高 120，`Sheet` 的底部变体）：横向滚动，全部未放置的快捷方式按图标 + 两字排开，上方一行搜索；
  - 系统栏变成编辑条：左「编辑布局 · 点餐」· 中「长按拖动 · 拖到槽里放置 · 拖回下方移除」· 右 `[恢复默认] [取消] [完成]`。
- **退出**：`完成` 写 localStorage，`取消` 回滚；切页签先问「放弃未保存的布局？」。编辑态只针对当前工作台。

### 3.4 拖动过程的反馈

| 动作 | 跟手 | 目标反馈 | 放下 |
|---|---|---|---|
| 拖栏 | 栏整体 `opacity .6` + 轻微缩小 `scale(.98)` | 可落位置出 4 px 墨色插入线；拖到工作台顶边 24 px 内出横向插入条（= 导航到顶） | 200 ms 归位过渡 |
| 拖快捷方式（库 → 槽） | 拖影是该槽形态的预览（拖向 F 槽时变圆钮，拖向 S 槽时变图标） | 进入槽区域槽高亮 `bg-sel-bg`；槽满时高亮变红边 + 显示「将替换最后一个」 | 落入即按槽形态渲染 |
| 槽内排序 | 同上 | 槽内其他项让位（sortable 动画） | — |
| 拖回库 | 拖影缩小 | 库区高亮 | 回库并按字母排序 |
| 点按模式 | 编辑态里**单击**对象 | 四角出 ◀ ▶ ▲ ▼，点一下移一位；槽内项再出「移到 Q / T / S / F」四个小按钮 | 给无触摸精度 / 键盘场景 |

### 3.5 原型要画的画面（交付清单）

1. 点餐页 · 默认（四槽默认内容：Q 五个、T 沽清、S 开钱箱、F 空）。
2. 点餐页 · 长按中（进度环，600 ms 的三帧）。
3. 点餐页 · 编辑态（虚线框、槽占位与容量、底部库、编辑条）。
4. 拖「备注」从库到 F 槽 · 拖动中（圆钮拖影 + 槽高亮）。
5. 拖「拼桌」到已满的 Q 槽（红边 + 替换提示）。
6. 拖导航栏到顶边（横向插入条）→ 放下后变横排资源栏。
7. 点按模式（选中「挂单」出四向箭头 + 移到槽按钮）。
8. 完成后的三种个性化布局样例：收银员（Q 满、S 开钱箱 + 预结单）、服务员平板（F 三个圆钮、Q 只放会员 + 备注）、店长（T 沽清 + 临时菜、导航在顶）。
9. 桌台页编辑态（只有栏可拖，没有槽，证明同一套编辑态可复用）。

### 3.6 技术方案（原型已实现 · 2026-11-11）

- **不用 dnd-kit**，自写 Pointer Events 拖动引擎（`src/layout/edit/drag.ts`）：设备舞台是 `transform: scale()` 的，自己按 `#device` 的实际宽度换算坐标更直接；触摸 / 鼠标 / 笔一套代码。拖动中的位置放在独立的小 zustand store（`useDrag`），pointermove 不触发整个 POS store 重渲染。
- 命中检测用 `elementFromPoint` 找最近的 `[data-slot]`，槽内落点按各项中心点计数；拖栏时按指针在网格里的相对位置判定左 / 上 / 右。
- 编辑态下工作台加 `.wb-edit`：所有后代 `pointer-events: none`，只有 `[data-editable]`（槽、可拖项、拖柄）接收指针，业务按钮天然失效。
- 长按：在 `[data-lp]` 区域（面板头、导航栏、系统栏、快捷方式）按住 600 ms，移动超过 8 px 取消；进入后吞掉松手那一下的 click。另有两个显式入口：结单区「更多」菜单底部「编辑布局」，以及显示设置第一行。
- 数据：Q 槽沿用 `store.quick`（设置页「快捷操作」开关仍可用），T / S / F 在 `store.slots`，一起存 localStorage；进入编辑态时存快照，「取消」还原，「恢复默认」回默认但仍在编辑态。
- 栏位 `nav / detail` 仍是全局的（和 L1–L6 同一字段），不按工作台分开存；结账（W2）的详情栏位置固定，只显示「位置固定」。
- 文件：`src/data/slots.ts`（槽定义、纯函数）· `src/layout/edit/drag.ts` · `Slot.tsx`（四种形态）· `EditChrome.tsx`（栏位框、插入条、库、拖影、点按菜单、长按环、编辑条）。

## 四、桌台布局：按店内布局摆放，2D 平面 / 2.5D 空间

### 4.1 三种视图

桌台工作台内容区头部加 `Seg`：**宫格 · 平面 · 2.5D**，记在 `tview`（持久化）。导航和详情不变，只换内容区。

| 视图 | 用途 | 画法 |
|---|---|---|
| 宫格（现有） | 快速找桌号、按状态筛 | `TableTile` 自适应列 |
| 平面 2D | 服务员按位置找桌、看一眼全场状态 | 按 `x y w h shape rot` 绝对定位的 `StatusTile`，内容精简为 桌号 + 状态点 + 金额 |
| 2.5D 空间 | 认位置、看区域之间的关系（入口、过道、包间在哪） | **只画空间，不画具体桌子**：地面分区、墙、门、吧台、厨房等固定物有厚度；桌台只是地面上的**状态色块**（和平面同一形状），不画椅子、不画桌腿 |

状态色三种视图一致：桌面 = 状态组块色（`--bk`），异常组加 4 px 状态色边，当前桌描边 2 px 墨。

### 4.2 桌台数据扩展

```ts
export interface Table {
  id: string; st: TableSt; seats: number; ppl: number; min: number; amt: number;
  area: string;                                   // 大厅 / 包间 / 露台
  x: number; y: number; w: number; h: number;     // 栅格坐标与占格数（1 格 = 20px）
  shape: 'rect' | 'round' | 'square' | 'booth';
  rot: 0 | 90 | 180 | 270;
}
export interface Fixture { id: string; kind: 'wall' | 'door' | 'bar' | 'kitchen' | 'cashier' | 'pillar' | 'plant' | 'zone'; x: number; y: number; w: number; h: number; label?: string }
export interface Floor { area: string; cols: number; rows: number; fixtures: Fixture[] }
```

示例：大厅 32 × 20 格，12 桌（A01–A12）+ 吧台 + 收银 + 门 + 厨房口 + 两个 `zone`（靠窗区、中央区）；包间区 6 间 V01–V06。

### 4.3 平面 2D

- 画布：内容区 `.bd` 里一个 `position: relative` 容器，宽 = `cols × 20`，高 = `rows × 20`，按内容区宽度等比 `scale`，超高内部滚动。
- 栅格底纹只在编辑态显示（`repeating-linear-gradient`，`--c-wash-strong`）。
- 固定物：墙 = `--c-inverse` 4 px 线；门 = 墙上缺口 + 弧线；吧台 / 厨房 / 收银 = `bg-wash` 块 + 居中灰字；柱子 = 深灰小方块；`zone` = 更浅的底色块 + 左上角小字区名。
- 桌台：`StatusTile` 变体 `floor`，圆桌 `rounded-full`，卡座一边带靠背粗线；`rot` 用 `rotate()`；座位 ≤ 4 只画桌号 + 状态点，≥ 6 加人数和金额。
- 点击 = `table:<id>`；双击 = 开台 / 加菜。导航状态筛选在平面下变为高亮：被筛掉的 `opacity .25`，位置不动。
- 多桌区：桌区切换切平面；「全部」时平面上方一排桌区页签。

### 4.4 2.5D 空间视图

目的是**让人认出「这是我们店」**：入口在哪、过道怎么走、包间在哪边、吧台靠哪面墙。桌子只是地面上有颜色的块。

- 实现：CSS 3D，不用 WebGL。画布容器 `transform: rotateX(60deg) rotateZ(-45deg)`（固定一个视角，不旋转），缩放两档（整区 / 放大）。
- 地面：整块 `bg-wash` 地板，`zone` 区域用更浅一档的色块 + 区名，区与区之间不画线，靠色差分。
- 有厚度的只有固定物：墙（高 3 格、半透明 `--c-inverse` 40%，不挡后面的桌）、吧台 / 厨房 / 收银（高 1.5 格，顶面 `bg-wash-strong` + 两个侧面深一档）、门（地面缺口 + 开门弧线）、柱子（高 3 格）。做法：每个固定物三块 div（顶、左侧、前侧）加 `translateZ`，不做六面。
- 桌台：**贴地的扁平色块**（高 0.2 格，只为让它从地板上浮出来一点），形状和平面一致，颜色 = 状态组块色；块上只有桌号一个数字，用反向 `transform` 补偿成正对视线、字号 ≥ 13；人数 / 金额 / 状态字都不画，点击后在详情栏看。
- 不画椅子、不画桌腿、不画人。空桌和有人的桌靠颜色区分，和宫格一致。
- 交互：点击桌台同 2D；hover / 长按出一个小 `tooltip`（桌号 · 状态 · 人数）。编辑只在 2D 做，2.5D 只看。
- 动画：切到 2.5D 时从平面 `rotateX(0)` 过渡到 `60deg`，400 ms，让人看懂两者是同一张图。

### 4.5 编辑平面（设置 › 桌台 › 区域与桌台 › 编辑平面；或桌台平面视图头部「编辑」）

W3 布局（内容 · 详情 360）：

- 左 = 2D 画布 + 栅格；顶部工具条：**选择 · 添加桌 · 固定物 · 墙 · 分区**，撤销 / 重做，`[恢复默认] [取消] [保存]`。
- 右 = 选中对象属性：桌号、座位数、形状（`RadioCards` 四种）、尺寸（`Stepper` 格数）、朝向（四向按钮）、桌区；固定物：类型、标签、尺寸；分区：区名、底色深浅。
- 拖动：dnd-kit，吸附 20 px 栅格，碰撞时红边不让放；`rect` 桌边 8 px 拖柄缩放。
- 批量：框选后对齐（左 / 上 / 等距）；「按宫格自动排布」把没坐标的桌按 6 列铺开（导入旧数据兜底）。
- 添加桌：底部「桌台库」拖入（两人方桌 / 四人方桌 / 六人长桌 / 八人圆桌 / 卡座）；桌号按区前缀递增。
- 右上角「预览 2.5D」按钮，编辑中随时切过去看空间效果，再切回继续编辑。

### 4.6 数据与状态

store：`tview: 'grid' | 'floor' | 'iso'`、`floors: Floor[]`、`fsel`、`fedit`、`fzoom: 1 | 2`；`tables` 增加坐标字段；动作 `tview:<v>` `floor:edit` `floor:save` `floor:cancel` `floor:add:<kind>` `floor:move`。持久化 localStorage `pos-react.floor`。


**原型已实现 · 2D 部分（2026-11-11）**

- 数据：`src/data/floors.ts`，大厅、包间两张 40 × 26 格的平面；桌台摆放（坐标、占格、形状、朝向、座位）与固定物分开存。实体固定物（厨房、吧台、收银台、柱子、绿植）参与碰撞，分区、包间、门只是地面标记。保存后存本机 `pos-react.floor`；编辑器新加的桌台会补进桌台列表。
- 查看（`src/modules/tables/FloorCanvas.tsx`）：桌台工作台内容区头部「宫格 / 平面」切换（记住选择），平面下可切桌区；格子大小按内容区宽度自适应。单击选桌、双击按状态开台 / 加菜 / 结账；左侧按状态筛选时其余桌变淡、位置不动。
- 编辑（`FloorEditor.tsx` + `floor-ops.ts`）：入口在平面视图头部和 设置 › 桌台 › 区域与桌台。拖动吸附到格；压到桌台或实体固定物时红框、松手回弹；右下角拖柄改大小；方向键微调、Delete 移出、Ctrl+Z / Ctrl+Shift+Z 撤销重做。工具条可加五种桌、六种固定物，自动排布、恢复默认；属性面板改桌号（仅新桌）、座位、形状、尺寸、旋转、移出平面；没选中时列出「未摆放」的桌，点一下放回空位。改动只进草稿，保存才生效，取消丢弃。
- 已知问题（工程原有，未改）：UnoCSS 把 `rounded-rt` 同时解析成主题圆角和「右上角 0.25rem」，全工程用它的块右上角都被压成 4px。平面里的桌台用 `!rounded-full` / `!rounded-[var(--rk)]` 绕开；全局修复要改 `uno.config.ts` 的圆角命名。

**原型已实现 · 2.5D 部分（2026-11-11）**

- `src/modules/tables/IsoCanvas.tsx`：桌台工作台视图切换多了「2.5D」，和平面共用同一份坐标。CSS 3D 等轴变换（向后倒 58°、转 −40°，无透视），不用 WebGL。
- 只画空间：远侧外墙半透明全高，近侧外墙只画矮边、门处留缺口；厨房、吧台、收银、柱子、绿植有厚度；包间是四面矮墙加房号、朝走廊留门。桌台是贴地薄色块（状态色同宫格），上面只有正对视线的桌号；不画椅子、桌腿、人。
- 交互：单击选桌、双击按状态开台 / 加菜 / 结账、悬停出「桌号 · 状态 · 人数」提示；状态筛选时其余桌每个面单独变淡（整块设 opacity 会把 3D 压平）。缩放两档（整区 / 放大可滚动），切进来时从平面翻转过去。
- 编辑器工具条加「预览 2.5D」，随时看草稿的空间效果；编辑仍只在平面上做。
