# 餐饮 POS 组件设计规范 v3.5

日期：2026-11-03。适用：产品、设计、Web 与 Android 开发、测试。

组件是餐饮 POS 开发规范的一部分。点餐、桌台、结账、系统管理及组件展示页使用同一套颜色角色、字体层级、控件形态和状态契约。本文独立描述基础组件与组合规则；业务流程继续参照 v3.1–v3.4 开发文档。

本版从当前 v3 原型与仓库中保存的 B 端方案提取，形成开发基线，不在本次修改页面。文中的“当前”指已存在的原型实现；“开发要求”指正式组件应达到的标准，不能据此认定原型已经全部实现。

## 2 设计语言

- 紧凑、扁平、结构清晰。用字号、字重、对齐和局部浅底组织信息，控制灰色面积。
- 白色表面承载内容，浅色画布只暴露在区域间隙；不能把所有区域合为没有边界的一片白。
- 菜单分类与菜单、桌台区域与桌台内容属于一个大面板，以柔和阴影或轻渐变分开逻辑，内部不留大缝。
- 普通按钮无灰色轮廓；选中使用主题浅底与主题文字，无底部阴影、底线或立体效果。
- 每个操作区只保留一个最强主操作。账单区结账实心，送厨为次操作；编辑弹层以保存为主操作。
- 颜色不能独自表达状态；必须同时有文字、图标或明确选中语义。

| 正文 | `--ink` | `#181A1C` | 名称、标题、金额 |
| 辅助文字 | `--sub` | `#5C5E61` | 时间、规格、次级说明 |
| 主色 | `--primary` | `#306F5F` | 主操作、选中图标与文字 |

组件引用角色，不直接绑定“绿色按钮”“灰色卡片”。正式实现将当前硬编码的业务状态色集中为语义 token，不在每个组件重复写值。B 端旧 `sh-bg/sh-surface/sh-ink/sh-sub/sh-primary/sh-primary-tint` 分别映射到画布/内容面/正文/辅助文字/主色/主题浅底；旧 `sh-faint` 必须按用途拆到 tile 或 control，不能机械全局替换。

### 3.3 桌台状态色

当前卡片和平面视图共用以下状态配方，状态不随主题皮肤变化。

| 状态 | 背景 | 状态文字 | 表达 |
| --- | --- | --- | --- |
| idle 空闲 | `#FFFFFF` | `#52635C` | 白色块、淡阴影、空闲文字 |
| dining 用餐中 | `#E5F3EB` | `#216548` | 整卡浅绿 |
| reserved 已预订 | `#FFF2D9` | `#8A5A14` | 整卡浅琥珀 |
| paid 已结账 | `#E8EFFB` | `#3A5E98` | 整卡浅蓝 |
| cleaning 待清台 | `#F9E8E3` | `#995546` | 整卡浅暖色 |

禁止顶部状态色条。选中保留状态背景，增加状态色 2px 外环及明确选中语义；这是业务卡片选中反馈，不是普通按钮的灰色描边。金额用正文色，优惠显示负数并标注来源，支付品牌色只用于对应品牌图标。

成功/警告/危险等通用语义角色与桌台业务状态分开命名。当前原型尚未集中定义完整语义色板；正式实现可从 B 端 `vars.ts` 的 success/warning/danger 三件套（标记/浅底/文字）收敛，不能直接把八套主题色当作状态色。

## 4 字体与排版

### 4.1 字体方案

当前默认为 Manrope + Noto Sans SC，保留现有偏好；组件展示推荐的 Inter 是可选方案，尚未自动替换默认。中文、英文、数字各自核对，不能把更换英文字体当成中文已经变化。

| 选项 | 拉丁文字/数字 | 中文 | 用途 |
| --- | --- | --- | --- |
| manrope | Manrope | Noto Sans SC | 当前默认，柔和几何 |
| inter | Inter | Noto Sans SC | 中性工作台，优先评审备选 |
| roboto | Roboto | Noto Sans SC | 终端风格 |
| noto | Noto Sans | Noto Sans SC | 多语言一致性 |
| plex | IBM Plex Sans | Noto Sans SC | 数字辨识 |
| outfit | 标题 Outfit，正文 Inter | Noto Sans SC | 标题强调，正文保持中性 |

正式资源按 Google Fonts 对应字体包交付，核对各字体许可并保留许可文件。Android 使用随包字体及系统回退，不依赖收银现场下载；Web 回退为 Noto Sans SC、PingFang SC、系统无衬线。

### 4.2 角色字号

以下为当前标准字号/紧凑配方的 CSS px；Android 使用 sp 并做真机校准。

| 角色 | 字号 | 字重 | 行高与对齐 |
| --- | --- | --- | --- |
| 页面标题 | 20 | 600 | 1.3，左对齐 |
| 面板标题 | 18 | 600 | 与右侧操作基线对齐 |
| 表单分区标题 | 13 | 600 | 分区编号为弱强调 |
| 正文、菜名 | 14 | 400 / 菜名600 | 1.45–1.5，允许换行 |
| 普通按钮 | 14；页头13 | 500 | 文字、图标垂直居中 |
| 输入值 | 13–14 | 400 | 标签12，与同列控件对齐 |
| 辅助说明 | 12 | 400 | 1.5，不用极浅灰 |
| 桌号 | 21–22 | 600 | 第一视觉层级 |
| 桌台金额 | 13–14 | 600 | 右侧对齐 |
| 应收金额 | 26 | 600–700 | 不挤占菜品清单 |

当前部分桌台元信息、分区编号、标签使用 10–11px。开发要求：关键状态、错误和操作文字不得沿用这类小字；以至少12sp起做真机评审，空间不足优先重排。统一采用400/500/600，700只用于少量核心金额，禁止整屏粗体。

大字/特大档当前正文为18/20、标题30/34，局部仍有固定字号。正式组件须按语义字号统一缩放，并验证中文长名、英文长词及系统字体缩放。金额使用等宽数字特性 `tabular-nums`，统一两位小数；金额、数量不换行，名称最多两行，完整名称可在详情读取。输入备注保留原文。

## 5 间距、圆角、线条与阴影

| 项目 | 基线 |
| --- | --- |
| 基础间距 | 4 / 6 / 8 / 12 / 16 / 20 / 24 |
| 紧凑：区块间距/内边距 | 8 / 12 |
| 标准：区块间距/内边距 | 20 / 20 |
| 舒展：区块间距/内边距 | 24 / 24 |
| 组件内文字间距 | 4–6；并列按钮8 |
| 默认面板/卡片/按钮圆角 | 8 / 4 / 12 |
| 面板形状档位 | 0/0、4/2、8/4、16/12（面板/卡片） |
| 按钮圆角档位 | 0 / 4 / 8 / 12 / 胶囊 |
| 普通桌台阴影 | `0 2px 10px #18221E0C, 0 1px 3px #18221E06` |
| 分类与内容分隔 | 轻渐变与方向性模糊阴影，区域间不再追加大间距 |

常规按钮、输入和卡片不使用灰色边框。表格可用极淡行分隔或留白建立行关系；不要每个单元格画框。焦点2px轮廓、错误提示和桌台选中环属于必要状态，不能因“无描边”而删除。普通按钮无阴影；模糊阴影用于桌台、浮层或逻辑分隔，不表示按钮选中。

视觉尺寸和触控命中分开管理。当前工具栏/图标/表格行内控件有32–40px视觉高度，主要操作48px；正式 Android 触控命中至少48dp，邻接热区不能重叠。圆角设置不能改变字重、业务状态色和操作层级。

## 6 基础组件契约

### 6.1 Button

| 变体 | 背景/文字 | 使用 |
| --- | --- | --- |
| primary | 主色/主色前景 | 结账、确认收款、保存商品 |
| secondary | 控件底/正文 | 取消、返回、一般辅助操作 |
| soft | 主题浅底/主色 | 轻强调、部分送厨入口 |
| text | 透明/主色 | 低优先级快捷动作 |
| danger | 轻底或透明/危险文字 | 删除、退菜等入口；确认弹层再强化 |

当前 `button()` 暴露 primary、text、danger 和 active 等类；soft 是本规范要求的语义变体，当前有些场景通过局部样式实现，正式组件应集中封装。active 属于状态，不能与 primary 并列当成业务变体。

建议统一尺寸配方：small视觉36、medium40、大型主操作48；旧 B 端44/36/52仅保留作历史参照，触控命中仍按48dp要求独立扩展。图标与文字间距6–8、左右内边距12；同组等高。结账面积大于送厨，取消不抢主操作。

必须覆盖默认、悬停、按下、焦点、禁用、加载中。当前原型具备默认/选中/禁用/部分焦点反馈，加载中防重复提交需正式组件补齐。禁用保留原因；危险确认写明对象和结果。按钮用2–4字动词或清晰动作短语，不写“确定”替代具体动作。

### 6.2 IconButton

统一线性 SVG，默认图标20–21，笔画约1.6–1.7，颜色继承角色；不要混用表情、字符图案和多套线宽。图标按钮当前36–40px视觉方块，系统管理38px宽。必须提供本地化 `aria-label`/contentDescription、悬停提示、焦点和选中状态。

系统管理使用齿轮；图文排列在搜索行最右侧单一位置切换；关闭使用关闭图标。结账、送厨、保存等重要动作保留文字。显示设置及组件展示使用同一图标入口配方。

### 6.3 输入与选择

| 组件 | 结构与状态 | 规则 |
| --- | --- | --- |
| TextField/SearchField | 标签、值、可选清空、辅助/错误说明 | 标签常驻；浅底无灰框；错误就地显示，保留输入 |
| FilterChip | 文案、可选计数、选中态 | 筛选列表；选中浅底+主色字，`aria-pressed` |
| SegmentedControl | 互斥模式、组名、当前项 | 当前 v3 使用平面浅底选中，不沿用旧 B 端浮起白色滑块 |
| OptionPicker | 规格/支付等选项、价格、不可用原因 | 默认轻底，选中主题浅底；沽清选项保留并禁选 |
| Checkbox/Radio | 明确标签、组选规则、选中 | 多选用复选、单选用单选；不以不同底色代替语义 |
| QuantityStepper | 减少、数量、增加、边界反馈 | 校验库存及订单状态；送厨后禁止直接修改数量 |

搜索框与快捷筛选及布局图标在同一行，搜索宽度可收缩，不能独占工具栏。现 v3 搜索匹配中英文名及编号；旧 B 端文档提及的拼音首字母搜索尚未实现。当前草稿数量减到0直接移除；不宣称已实现旧 B 端的逐行删除确认。

### 6.4 信息与浮层

- Tag/Badge：标签不可伪装成按钮；数量角标与状态标签分开。状态文字不可省略。
- Dialog/Sheet：固定标题与关闭、内容内部滚动、固定底部操作；关闭恢复触发点焦点；错误留在表单内。
- Toast：简短说明操作结果；不能替代字段错误，也不能把本地演示保存写成服务端成功。
- DataTable：标题与字段标签清晰，金额右对齐，行操作固定位置；窄屏表格内部滚动，不撑破面板。
- Empty/Loading/Error：空数据给下一步，加载不抖动主要布局，失败保留输入并可重试；正式组件补齐这些状态。

## 8 实现分层与复用映射

| 层级 | 现有文件 | 正式实现职责 |
| --- | --- | --- |
| 基础令牌 | `tokens/theme.css`、`model.mjs`设置默认值 | 色彩、字号、间距、形状、模式；以语义名称输出 |
| 基础组件 | `components/controls.mjs/.css` | 按钮、图标、搜索、筛选、工具栏；不引用订单存储 |
| 页面公共区 | `components/chrome.mjs` | 页头、页脚、全局入口 |
| 业务组件 | `components/ui.mjs`、`management.mjs`、`sku-editor.mjs`、`product-media.mjs` | 接收业务数据和回调，不复制颜色/字号 |
| 页面装配 | `workbenches/order.mjs`、`tables.mjs`、`admin.mjs` | 路由、业务校验、数据保存、工作台状态 |
| 组件验收 | `components/gallery.mjs`、`components.html` | 直接调用共享组件，展示各状态及长文本 |

Android 对应按 `PosTheme → PosButton/PosTextField/PosChip → PosDishCard/PosTableCard/PosProductEditor → Screen` 分层。此命名是开发建议，不代表当前已有完整 Compose 组件实现。Web 历史 CSS 覆盖应收敛到组件配方；不要把覆盖链逐层翻译进 Android。

B 端 `PosBtn` 的 pay/main 映射主操作、send/soft映射次操作、sec映射中性、ghost映射文本、danger映射危险；旧 `.sh-btn` 类名仅作迁移对照，不强制新页面继续沿用。

## 9 展示与开发验收

[独立组件展示页](http://127.0.0.1:8765/v3/components.html) 为可运行参照，需启动本机原型服务。展示页与业务页使用共享组件；发现视觉差异时修复公共配方，不在展示页另外美化一份。

逐项验收：

- 按钮：主次层级、平面选中、危险/禁用/焦点/加载；图标具备名称和触控热区。
- 字体：中英文、长菜名、数字小数、六种字体回退与字号放大；金额列不跳动。
- 色彩：八套皮肤、三类主要表面、五种桌台状态；文字与实际底色对比度通过。
- 布局：分类不越界，搜索/筛选/排列同行；内容独立滚动，页头页脚及主要操作可达。
- 表单：错误不清空输入、SKU独立值保留、上传失败反馈、取消不修改商品。
- 复用：点餐、桌台、管理、组件页无复制的按钮或状态配色；新增组件先进入展示页。

当前尚待收敛：部分固定小字号、分散的业务状态色、不同控件焦点色、金额等宽数字和完整加载状态。以上为正式开发整改项，不属于本次文档整理已完成的代码变更。深色模式仅在历史 B 端有令牌，当前 v3 未提供可验收的完整深色组件方案。
